# 实验报告：BOX IMU 四元数半球约定

> 日期 2026-07-29 · 数据 `nvidia@192.168.111.122:/home/nvidia/lerobot/outputs/datasets/**/box_sensors.jsonl`（全量）
> 关联文档 [`../../ts_sync.md`](../../ts_sync.md) §9.1.1 · 代码 `gmsl2/thor_lerobot_v3.py::_imu_quat_xyzw`

## 0. 结论（TL;DR）

**不强制半球，按 SDK 原样透传符号。** 这与 `ts_sync.md` §9.1.1 原先写下的计划（「若存在翻转就强制
`w >= 0`」）相反——实测把那个前提证伪了。

- **反极翻转 0 次**：213 条 IMU 流 / 323,213 个样本里，没有一对相邻样本满足 `dot(q[i], q[i+1]) < 0`。
  SDK 的四元数流**本身就是连续的**，没有 `q → -q` 抖动需要修。
- **强制半球反而有害**：31 条流（14.6%）的姿态自然穿过 `w = 0`（即转过 180°）。对这些流强制
  `w >= 0`，会在过零处把整条向量取反，相邻样本 L2 步长从 ≤0.08 跳到 **2.001**——正是本来想避免的那种
  不连续，只是由我们自己注入。
- **强制半球能改善的流：0 条。**

顺带佐证删 `rpy` 的判断：同一批数据里 `yaw_deg` 的 ±180° wrap **确实发生**（1 条流 2 次）。
四元数没有对应问题。

## 1. 背景

`ts_sync.md` §9.1.1 决定把 `observation.state` 的 IMU 姿态从「`rpy` + `quat_wxyz`」（13 维）收敛成
「`quat_xyzw`」（10 维）。留下一个 open item：四元数有双覆盖（`q` 与 `-q` 表示同一旋转），若 SDK 不保证
固定半球，训练信号里会出现整体符号翻转，危害与 `yaw` wrap 同级。原计划是先统计翻转次数，若存在就在
打包 state 时强制 `w >= 0`。

关键在于**这是个二选一，不是「加了没坏处」**：强制半球本身也会在 `w = 0` 处引入不连续。哪一种不连续
更常见，只能实测。

## 2. 方法

`quat_hemisphere_stats.py` 扫描所有 `box_sensors.jsonl`，对**每条 IMU 流单独**统计：

- `flip`：相邻样本 `dot(q[i], q[i+1]) < 0` 的次数（真·反极翻转）；
- `w<0` / `min|w|` / `|w|<.05`：`w` 的符号分布与是否贴近过零；
- `dRaw` / `dHemi`：相邻样本 L2 步长的最大值，**原样** vs **强制 `w >= 0` 之后**——直接量化「强制半球
  会不会把事情弄糟」；
- `yawWrap`：`|yaw[i+1] − yaw[i]| > 180°` 的次数，作为 rpy 侧的对照。

> **坑（第一版结论是错的）**：多 box episode 会把 `box1672693301/box_imu` 和 `box1819152274/box_imu`
> 交错写进同一个 jsonl。按 `sid.endswith("box_imu")` 收集会把两台设备的姿态串成一条序列，凭空造出
> 「每隔一个样本就翻转」的假象（第一版跑出 3 条流共 3,895 次翻转，全是这个 artifact）。必须按**完整
> `sid`** 分组——`imu_sids()` 先枚举，`episode_stats(path, sid)` 再精确匹配。分组修正后翻转数归零。

复现：

```bash
scp quat_hemisphere_stats.py nvidia@192.168.111.122:/tmp/
ssh nvidia@192.168.111.122 'python3 /tmp/quat_hemisphere_stats.py /home/nvidia/lerobot/outputs/datasets'
```

## 3. 结果

全量输出见 [`quat_stats_full.txt`](quat_stats_full.txt)。汇总：

| 口径 | 值 |
|------|-----|
| IMU 流数 / 样本数 | 213 / 323,213 |
| 反极翻转 `dot < 0` | **0** |
| 相邻样本最大 L2 步长（原样） | 0.342 |
| `w < 0` 的样本占比 | 21.9% |
| `w` 在流内变号（穿过 `w=0`）的流数 | **31 / 213** |
| 强制 `w>=0` 后的最大 L2 步长 | **2.001** |
| `dHemi > dRaw`（强制半球变糟）的流数 | **31** |
| `dHemi < dRaw`（强制半球变好）的流数 | **0** |
| `yaw_deg` ±180° wrap 次数 | 2（集中在 1 条流） |
| 四元数模长范围 | 0.999029 – 1.000999（已归一，无需再 normalize） |

`dHemi` 最差的几条：

| 流 | n | `w<0` | `min\|w\|` | dRaw | dHemi |
|---|---|---|---|---|---|
| `dadada_20260616_084743/ep0` | 2008 | 11.5% | 0.001 | 0.013 | **2.001** |
| `dadada_20260616_084743/ep1` | 1300 | 10.2% | 0.000 | 0.012 | **2.001** |
| `thor_gmsl2_11ch_v1_20260615_071908/ep3` | 1992 | 67.9% | 0.000 | 0.014 | **2.001** |
| `thor_gmsl2_11ch_v1_20260615_075958/ep0` | 1459 | 91.0% | 0.000 | 0.015 | **2.000** |

典型形态是：手持 BOX 的姿态慢慢转过 180°，`w` 平滑地从正走到负，四元数四个分量全程连续（dRaw ~0.01）；
一旦强制半球，过零那一瞬间四个分量同时反号（dHemi 2.0）。

## 4. 落地

`gmsl2/thor_lerobot_v3.py::_imu_quat_xyzw()` 只做 `wxyz → xyzw` 重排，**不动符号**，并把上述结论写在
docstring 里。回归测试 `tests/scripts/test_thor_ts_sync_alignment.py::
test_imu_attitude_is_quaternion_only_in_xyzw_order` 用一个 `w < 0` 的样本钉住「符号透传」这条约定。

## 5. 有效范围

结论依赖的是**当前 SDK/固件的姿态解算本身连续**这一实测事实，不是数学必然。换固件、换 IMU、或改用
另一路姿态融合后，应重跑本脚本复核；若届时真的出现反极翻转，再权衡「强制半球」与「训练时用
`min(‖q−q̂‖, ‖q+q̂‖)` 这类对符号不敏感的损失」——后者不引入新的不连续，通常是更好的解法。
