## 复用了什么

输入锁定为现用最新版 P0 标定/BOX 2.0 接触 TCP 解算的两条轨迹，读取
`timed_plan.json` 的全部关节及宽度节点：Episode 0 共 571 帧，Episode 1 共 420 帧。
输入 SHA256：`7fa69ec0c215de460095a0707d01fc93c850de5474b45d70296db21b6aa4a335`。

没有启用那个已因首帧错误而封禁的旧两条数据启动脚本。

从 panda-py 中分离 Path/Trajectory 规划源码，沿用旧六条入口的
`speed_factor=0.01`、每段最多 200 帧、相邻段共享边界帧。
为了不绕过采集节点，主检查设置 `max_deviation=0`；另保留旧 `.02` 参数的诊断基准。
这里的速度系数不是采集原速：两条原始录像分别只有 9.5 秒、6.983 秒。

独立模块只含数学规划器，不链接 libfranka 或夹爪 SDK，没有 Robot/Panda/Box、
故障恢复或运动执行接口。原生算法没有更换，规划位置与旧扩展的回归对比通过。

## 修正的复用细节

1. 旧速度/加速度查询使用积分小段末端值，不完全对应所查询时刻。
   新审计接口根据同一原生路径、时刻计算瞬时导数；没有修改旧扩展。
2. 旧圆弧段累计长度漏计前一圆弧的后半段。新接口补齐源帧的弧长索引。
   回归确认这没有改变规划位置或总时长。
3. 夹爪宽度按原生路径进度插值，不再按整段经过时间的百分比播放。
   同时检查实际宽度变化速度；没有直接把宽度值当作 SDK 步数。
4. 末端差异检查包含用户提供的 `49.699345 - sqrt(...)` 开口相关后退公式。
5. 独立重新检查关节虚拟墙、全连杆碰撞模型、夹爪和已测桌面。

现有设置是加速度不超过 0.4 rad/s²、jerk 不超过 5 rad/s³、夹爪速度不超过
10 mm/s。上表是离线规划值，不是真机传感器实测，也不能拿来判断以前是否发生过碰撞。
零圆滑原生规划虽然经过所有节点，但局部转折/数值积分行为不满足现有运动包络。
圆滑参数 `.02` 的基准时长为 106.245 / 95.310 秒；这会改变转角路径，且
原生二阶规划仍不保证加速度连续或有限 jerk，所以也不能据此放行。

几何抽样中，加入 5 mm 桌面测量敏感性后的最小距离下界约 57.033 mm。
该最小值来自底座外缘，不是夹爪离桌面的高度。沿用已审核的局部铰链接触豁免；
报告列出豁免细节。没有覆盖线缆、额外障碍物、负载、第二台机械臂、制动距离，
也没有证明两次采样之间连续无碰撞。

与现用连续插值在对应源进度下比较，主检查最大接触中心差异约
0.321 / 0.526 mm，姿态差异约 0.109 / 0.117 度。这不是独立标定精度；
保留原节点也不等于两种连续插值完全一致。

另外，真机运动时出现过的夹爪 200 ms 新鲜数据超时还没有复现并确定根因。
此前只读测试通过不能证明这一故障已经修复。本版本不删除、延长或绕过该检查。
