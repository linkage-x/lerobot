## 数据与控制方式

- 输入来自已核对的新标定 `replay_p0_once_20260908/timed_plan.json`，取原始 IK 节点，不使用其中 181/131 秒的五次多项式时钟；Episode 0/1 分别为 571/420 帧。
- 输入 SHA256：`7fa69ec0c215de460095a0707d01fc93c850de5474b45d70296db21b6aa4a335`。使用同一 P0/BOX 2.0 URDF 与坐标链；没有回退到 9 月 3 日错误的旧 IK。
- 使用旧六条数据入口的原生 C++ `controllers::JointTrajectory`：速度因子 0.01，到首帧 0.03，每段最多 200 帧，圆角偏差参数 0.02 rad，刚度 `[300,300,300,300,120,80,30]`，阻尼 `[25,25,25,25,10,8,5]`。
- 控制器、规划器与原有源码逐文件比对相同。增加 Python 绑定是为了直接执行已经检查的原生轨迹对象；启动接口禁止自动故障复位，避免检查一条路径、执行时另行规划另一条。不是新的控制算法，也不是逐帧 Python OTG。
- 不再使用自定义 5 秒起步测试、0.0015 rad 到位阈值或 2 秒到位超时。保留原生速度结束条件与原生相对位置判定，以及旧入口的绝对关节/TCP 终点误差限制。控制器超时或异常会停止，不自动重试或继续。
- 原生规划有圆角平滑，不能称为逐点、逐时刻严格精确重播。名义运动时间约 106.25/95.31 秒，不包含到首帧、检查、停顿、实际位置引起的重新规划时间，也不是采集的 9.5/6.98 秒原速。

## 不连接夹爪

入口没有 BOX SDK 导入、网络连接、模式切换或夹爪开合命令。实际夹爪必须空夹，能保持所填开口不变。断网不是机械锁定。
保持固定开口时只验证机械臂运动，不重现采集的抓握过程，也不重现随夹爪开口变化的接触 TCP 轨迹。
