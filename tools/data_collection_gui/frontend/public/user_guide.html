Thor 手持采集 + FR3 回放 · 使用指南

适用版本：2026-11-10（分支 hph/dual_fr3_bimanual_replay_pr，提交 362289af 之后）。读者：第一次上手这套系统的学生和工程师。

这份页面是单个 HTML 文件，可以直接用浏览器打开，不依赖网络；部署后也可以在 GUI 所在地址下以 /user_guide.html 访问。

1当前能做什么

一句话：用右手的手持夹爪录一段示教，生成末端轨迹，再让右边那台 FR3 照着回放一遍。其余功能要么还没打通，要么没验证过，不要当成可用。

功能状态说明
右手手持采集可用手持夹爪 rig v9b 右手（ArUco 100/101/110/111，BOX 3906437858），Thor 8 路 GMSL2 相机同步录制。
轨迹生成 + QC可用Dataset Processing 页，检测目标选 Gripper Rig v9b · 右手。
右臂单臂回放可用FR3 right（192.168.1.210），带 Corenetic 夹爪（BOX 3100715645）。先在 MuJoCo 里预演并通过，再上真机。
左臂采集/回放不可用左臂（192.168.11.102）已装上和右臂相同的末端（夹爪 + 相机），但 FR3 球窝核对、手持同球、双臂同球这三步 pivot 都还没做；它的基座到相机世界的注册边 11-03 已退役。GUI 里能选到左臂，但 MuJoCo / 真机回放会被拒绝。启用方法见 第 10 节。
双臂协同回放不可用需要两台臂都有注册边，以及两臂之间的相对位置。依赖左臂标定。
带头部相机录制暂不使用当前不带 head 录制，界面里只显示 left / right 两只手。
导出 LeRobot 数据集能跑，未验证导出的标签一律保留在录制时的相机世界系，日志会列出这份数据目前能部署到哪台臂。部署时由推理端按臂名查注册边，这条链路还没在真机上跑过。见 第 8 节。
策略训练 / 推理未验证本版本没有在这套数据上跑通过训练和部署，不要拿结果下结论。推理目前只有命令行，GUI 入口还在做。

2安全与协作规矩（先读）

机械臂会真的动。任何会让 FR3 运动的按钮（Move to start、Move to trajectory start、Execute、负载辨识采集、pivot 执行），按之前必须有人站在急停旁边全程盯着，工作空间里没有人手、线缆和杂物。碰撞检查只建模了机械臂、夹爪和桌面平面，桌上的东西、线缆和另一台臂都没有建模，要靠人看。

不要自己部署。run/deploy.sh 会把你本机的整棵代码树镜像到 Thor，覆盖别人的改动，还可能把只存在于 Thor 上的标定结果（比如刚应用的注册边）抹掉。部署由维护者统一做，且先用 -n 干跑看清会删什么。

不要手改 Thor 上的代码和配置（/home/nvidia/lerobot）。需要改配置，找维护者在仓库里改、提交、再部署。

看到顶部红条「world_graph.json 不是受信版本」，停下来找维护者。它说明标定图被改过（常见原因是有人用旧代码部署覆盖了）。这时所有到机器人基座的变换都被禁用，回放会被拒绝。不要点确认。

不要推动右臂的小车，也不要碰相机支架。右臂的注册边只在 11-10 那次标定时的摆放下成立。如果确实挪过（比如为了录双手示教把车推开），推回后按车上垫块顶紧桌沿、刹车、对准地面记号，然后按下面「推过车之后」做。

车位自动检查，以及它看不到的情况。右车上贴了 40、42、44 三个 tag。每录完一段，系统会在后台拿这一段和标定时的参考比对车的位置。发现车被推过，就停用右臂的注册边，顶部出现红条「小车被推动过」，导出到基座、MuJoCo 和真机回放都会被拒绝。

它只看已经录下的视频：推了车之后没有新录像，系统仍以为车在原位。tag 被挡住、看不全时，结果只是「看不清」，注册边照样可用。所以：

  • 推过车之后（哪怕只碰了一下），回放前先录一段 10 秒左右的视频：人别站在车前，车上 40/42/44 和桌面 tag 都要露出来。大约一分钟后看日志里的 cart check fr3_base_right：ok 才能回放。
  • 结果是 moved（红条）：车没推回原位。重新推到位再录一段；推不回去就要重新做同球标定，找维护者。
  • 结果是 partial 或 unseen：tag 没看全，检查不算数。把挡住 tag 的线缆、杂物挪开，重录。42 号最容易被线缆挡住。
  • 黄条（tag 彼此对不上、相机或基座边重新标定过）：找维护者，这时推车不会被发现。

其他约定：录制前夹爪 BOX 先上电预热 30 分钟；一次只有一个人操作 GUI 的录制器（Connect/Disconnect 是全局的）；做了任何标定，在群里说一声并写进日志。

3系统一览

数据怎么走

手持夹爪（右手）rig v9b，4 块 ArUco 贴片 + BOX（扳机、6D 力、触觉）
→
Thor 录制8 路 GMSL2 相机 + BOX 数据，写成一个 session 数据集
→
轨迹生成相机看 marker → 每帧末端位姿（相机世界系），写 sidecar
→
换到臂的基座经注册边 world → fr3_base_right，生成该臂用的副本
→
IK QC + MuJoCo离线可达性 + 真模型预演
→
真机回放FR3 right 跟踪末端轨迹，夹爪按扳机开合

两个「选择」发生在不同阶段：

  • 哪只手在轨迹生成时就定了：选「右手」目标，只认 100/101/110/111 号 marker，输出 state_action.right.csv。画面里出现别的 marker（左手 rig、车上和桌上的 tag）不影响。
  • 哪台臂在回放时才选：sidecar 一直保存在相机世界系，回放页选了哪台臂，就换到哪台臂的基座里规划和执行。所以同一段数据以后也能给左臂用（等左臂标好）。

右臂回放的精度预期

world → fr3_base_right 这条边是 11-10 用 4 个球位做的同球检验拟合的：随机误差 p95 约 1.5 mm，另有最多约 3 mm 的竖直方向系统偏差（球垫是软的，FR3 和手按压的深度不同）。合起来在标定覆盖的区域内典型约 3 mm、最大约 5 mm，FR3 自身跟踪误差和相机标签误差另算。

标定覆盖的区域（右臂基座系，mm）：x 507…611，y −315…236，z 250…615。示教动作尽量落在这个范围附近，离得越远，旋转误差放大得越多。

4每天开工检查

  1. Thor 和相机。Thor 开机或重启后，相机流可能起不来。在 Thor 上执行： 
    cd ~/lerobot && ./tools/thor/gmsl2/recover_argus.sh --sdk ~/Desktop/SG16A_AGTH_G3Y_A1
    它会停掉正在运行的录制器，但不动 GUI 的 gateway：跑完回到 GUI 重新点 Connect 即可，不用重新部署。还不行：Thor 和转接板（12 V/3 A）全部断电至少 3 秒再上电。Thor 关机可能卡约 9 分钟后由看门狗重启，别急着拔电。
  2. 打开 GUI。用维护者给的地址。前端跑在维护者的开发机上，形如 http://<开发机 IP>:<端口>/，端口以维护者通知为准（不一定是 5173）。在开发机本机上打开时，IP 写 localhost。顶部应显示 Gateway online，并且没有红色警告条。
  3. Calibration → 概览。看相机自检有没有报漂移、有没有要重做的项。有就停下找维护者，不要带着漂移的相机录数据。
  4. Device Manager。相机都在线；手持 BOX（3906437858）和右臂夹爪 BOX（3100715645）在线。
  5. BOX 预热与零点。两只 BOX 上电后预热 30 分钟，然后在 Calibration → BOX 传感器 做 6D 零点 / origin（每天第一次做 origin，之后动态校准大约 30 分钟一次）。页面按 BOX 分组，两种 BOX 做法不同：
    • 手持 BOX（如「手持右 BOX 3906437858」）：放到工装上固定，不要手持，再点该组的「原始零点 / 动态校准」。
    • 臂上 BOX（「右臂夹爪 BOX 3100715645」，橙色边）：工装就是机械臂本身。用该组里的「夹爪 6D 零点」，机械臂会自动转到指尖朝上再校零，机械臂会动，要有人守急停。不要用「高级：手动校零」——臂不在指尖朝上时会做出错的零点，而且不报错。
    每组的「必须标定仍在有效期」变红就要重做；臂上 BOX 的有效期按 Thor 上的零点记录算，换一台电脑看也一样。
  6. 右臂状态。FR3 Desk 里 FCI 已激活、没有报错；右臂小车在原位（垫块顶住桌沿、已刹车），车上 40/42/44 号 tag 没被线缆挡住。今天车被动过的话，先录一段 10 秒的车位检查视频，日志里 cart check fr3_base_right: ok 之后再回放（见第 3 节）。

5手持采集（Live Record）

  1. （可选）绑定任务。在 Task Library 激活一个任务，录到的数据会归到该任务的数据集；不绑定就是普通 session。Live Record 页顶部会显示 Recording for task: …，可以 Unbind。
  2. 连接录制器。Connect（快捷键 C，顶栏也有）。连接后录制器、标定和设备预览共用这一个会话。勾了激光跟踪仪的话，要等它 Home 成功才能开录。
  3. 开始一段。手持夹爪放到起始位置、静止 1–2 秒，点 StartEpisode（E）。
  4. 做示教动作。注意：
    • 右手 rig 的 4 块贴片尽量让至少 2 台已标定相机同时看到；手、袖子、物体别长时间挡住贴片。
    • 动作别太快（1 m/s 量级会丢检测）；在右臂可达、并且尽量靠近上面那块标定覆盖区的范围里做。
    • 结束时同样静止 1–2 秒。
  5. 保存或丢弃。Save（S）保存，Discard（D）丢弃，Exit（Esc）退出会话。保存后页面出现 Raw dataset saved，可以直接 Open in Replay、Queue Traj Gen 或 Go to Processing。
  6. 收工。顶栏 Disconnect。正在写盘时不能断开。

保存时提示 0 samples（BOX 没数据）：这一段的力和扳机数据是空的，丢掉重录，并告诉维护者（多半是 BOX 网络或绑定地址问题）。

6轨迹生成与 QC（Dataset Processing）

  1. 选检测目标。页面上方 Detection Target 选 Gripper Rig v9b · 右手（ids 100/101/110/111）。选错目标会认错 marker 或解不出位姿。
  2. 生成。在数据集列表里找到刚录的 session，点 Generate EE Trajectory。状态会经过 queued → running → pose ready，可以点 View Log 看进度。在 Thor 上本地跑，一段几分钟。
  3. QC。生成后点 Run QC。主要看三块：
    • Online Sync Manifest：相机帧和 BOX 数据的时间对齐是否通过。
    • Marker detection evidence：每台相机的检测率，看是否大段丢检。
    • FR3 offline IK evaluation：这只手的轨迹在对应臂的基座里逐帧求 IK，是否都够得着（fr3_ik_reachability）。
    全部通过后状态变成 QC pass，按钮变成 Open Replay。

生成失败显示 Regenerate Trajectory；QC 失败显示 Re-run QC。重跑前先看日志里的原因，不要反复点。IK 不可达通常说明动作超出了右臂工作空间，这段数据只能丢掉或者重录。

7右臂回放（Episode Replay）

顺序固定：先选臂 → MuJoCo 预演并通过 → 预检 → 回到起点 → 执行。每一步都有门禁，前一步没过，后面的按钮是灰的。

  1. 选数据和 episode。左侧 Replay Datasets 选 session，Episode 区用 Previous / Next / Go 切换。确认显示 Trajectory: Ready；如果是 Missing，点 Generate EE Trajectory。
  2. 看一遍数据。Replay Inspector 里有录制视频、End-effector pose 3D 视图（副标题显示 hands right）和下方 hand pose trajectories 曲线。检查轨迹完整、没有突然跳变；有大段丢检的 episode 不要回放。
  3. 先选臂。在 Real Robot Replay 面板的 Arm 里选 right。MuJoCo 会在所选臂的基座里规划，所以要先选臂、再跑 MuJoCo。
  4. MuJoCo 预演。在 MuJoCo EE trajectory replay 面板选 Right hand，点 Run MuJoCo · right，等渲染完成后看视频：有没有碰撞、贴桌面、关节翻转、姿态怪异。确认没问题再点 Pass MuJoCo check，按钮变成 MuJoCo passed。
  5. 预检。上方 Replay Controls 点 Preflight right。它按这台臂自己的配置检查连接和设置（包括 Desk 里的末端负载）。看 Safety 行和诊断信息，有报错先解决。
  6. （可选）回 home。Move to start (home)，确认弹窗里点 Yes, move，机械臂走到预设的起始关节角。
  7. （可选）其他设置。
    • Command lead：默认 3 帧（20 fps 下 150 ms），用来抵消机械臂约 155 ms 的跟踪滞后。没有特别理由不要改。
    • Record the laser tracker…：要用激光跟踪仪记录真值时才勾。勾了以后，执行前要把 SMR 从鸟巢里拿出来装到臂上，否则 Execute 会拒绝。
  8. 到轨迹起点。点 1 · Move to trajectory start，确认弹窗后机械臂移动到轨迹第一帧，Phase 变成 at start 并保持。
  9. 执行。再看一眼工作空间，急停在手边，点 2 · Execute trajectory。夹爪按录制时的扳机开合（扳机 ≥ 90% 视为夹紧）。随时可以点 Abort 或按急停。
  10. （可选）误差分析。如果录了激光，在回放页做一键分析，看激光测得的末端与期望轨迹的偏差。

MuJoCo 没通过但「可审阅」时，会弹出 override 提示（Yes, proceed）。只有你看过渲染、明白失败原因（比如只是某个指标擦边），并且和维护者确认过，才可以继续。

换 episode、换手或换臂之后，MuJoCo 的结果会失效，需要重新跑和通过。面板提示「MuJoCo right was planned in the left arm's base」时，说明预演用的臂和现在选的臂不一致：选好 right 臂再跑一次 MuJoCo。

8导出与训推（当前未验证）

本版本没有验证「右臂数据 → 导出 → 训练 → 在右臂上推理」这条链路。

坐标系约定（11-10 起）

  • 导出不换坐标系。Dataset Export 页把 QC 通过的数据导出成 LeRobot v3，位姿留在录制时的相机世界系（world_…），不再写进任何一台臂的基座系。这样同一份数据左臂、右臂、双臂都能用；以后某台臂重新标定，已经训练好的策略也不用重新导出。
  • 导出日志会告诉你能部署到哪台臂。看日志里的这几行：
    • Deployable on the right arm (fr3_base_right) via …：可以部署到右臂。
    • Not deployable on the left arm (fr3_base) until it is registered: …：左臂要先按 第 10 节 完成标定。
    这几行只是提示，不会改变导出的数据。
  • 换到臂的基座系是部署时做的。推理端必须指定 --arm right 或 --arm left，没有默认臂。启动时它会从 tools/fr3/fr3_arms.json 取这台臂的 IP、夹爪 BOX、URDF 和 IK 目标点，再从 world_graph.json 取「相机世界 → 这台臂的基座」那条边，在日志 world_graph_edge=… 里打印这条边的方法、拟合时间和误差。边已退役，或者网页顶上有 world_graph 守卫红条，推理直接拒绝启动，不会悄悄换成别的对齐方式。
  • 推理开始前臂要在示教起点附近。world_graph 模式下，臂会去示教时手在房间里的实际位置，而不是从臂当前所在的位置开始做。如果臂离示教起点太远，第一帧指令会被拦下，之后每一步限幅约 5 mm，臂会慢慢挪过去。回放页的 1 · Move to trajectory start 是给回放用的，推理不能用它。推理用的起点按钮还在做：系统会选一条真实示教的起点（medoid），把臂移过去，再自动判断有没有到位，没到位就不让执行。按钮做好之前，推理只能跑 --preview（只看不动），不上真机执行。系统会强制执行这一条：命令里没写 --preview 时，推理脚本会显示 [REFUSED] real execution of a policy is locked 并退出，机械臂不会动。看到这一行，就补上 --preview；不要自己想办法绕过去。
  • 「用起始姿态估计变换」（--dataset-alignment start_pose）只有显式指定才会用。用了以后，起始姿态差 1°，整条轨迹都会跟着转 1°。只有维护者在场时才用。
  • 用旧边导出的 fr3_base 数据集。11-10 以前导出的、写在左臂基座系里的数据集，如果当时用的边已经退役，推理会拒绝，并列出是哪条边。重新导出一次就能用（新导出留在相机世界系）。
  • 标签链有防混用检查：外参、相机状态、注册边、TCP 定义、BOX 配帧不一致的数据不能混在一个导出里。看到相关报错不要强行加 --allow-mixed-labels。

现在能做到哪一步

  • 训练：GUI 只能准备训练视图，训练本身还要另外手动跑。
  • 推理：只有命令行 tools/fr3/fr3_act_infer_real_runtime.py。tools/fr3/run_pick_place_infer*.sh 是旧设备（pika 夹爪、海康相机）用的，不要用。
  • GUI 里的分级放行流程还在做：离线对比 → MuJoCo → 真机只看不动 → 真机限幅执行。做好之前，推理只能到「真机只看不动」（--preview）这一级，必须有维护者在场，且有人守着急停。结果里要注明「未验证链路」。

10启用左臂：完整标定步骤

目标：让左臂（192.168.11.102，基座系 fr3_base）像右臂一样能单独采集和回放，进一步支持双臂协同。整个流程和 11-10 右臂那次相同，核心是一条新的 world → fr3_base 注册边，用「同一个球，FR3 和手持各绕它转一次」的方法测出来，不依赖激光，也不依赖 TCP 定义。

标记说明：操作员 在 GUI 里完成；维护者 需要改仓库配置、提交并部署（先 -n 干跑）。

前提（缺一个都不要开始）

  • 左臂摆放已最终确定。小车推到最终位置、垫块顶紧桌沿、刹车、画好地面记号。标定之后再挪就要重做。
  • 相机外参稳定。概览页自检没有漂移；如果近期要重标相机，先标相机再做这一套（换外参后注册边需要复检）。
  • 左臂末端和右臂一致。现在左臂已装好和右臂同样的夹爪 + 相机。标定时的末端必须和以后回放时完全一致：同样的指尖、同样的插件 nov4、相机在、不带 SMR；中途改了末端，从阶段 3 重来。
  • 右臂小车不动。整个过程中右臂保持 11-10 的摆放，否则会同时破坏右臂的边。
  • 刚性球座。11-10 用的是软球垫，导致约 3 mm 的竖直偏差。这次换成刚性支架（或至少是硬垫）。

阶段 1 · 硬件和网络 操作员维护者

  1. 检查左臂夹爪和 BOX 的线缆余量（腕部转一整圈不拉扯）；BOX 上电后在 Device Manager 里记下它的 id。
  2. FR3 只能从 Thor 的网口访问（工作站不可达）。在 Desk 里确认 FCI 已激活、关节没有超出 FR3 限位（运输姿态可能超限，要先用 Desk 拉出来）。
  3. 维护者 改配置并部署（现在注册表里左臂还是「无夹爪 BOX」，回放配置用的是 mock 夹爪）：
    • tools/fr3/fr3_arms.json：arms.left.corenetic_device_id 填夹爪 BOX 的 id，删除 no_gripper_why。
    • 左臂回放配置 third_party/opencv_kalibr/fr3_data_collection_replay/replay_cube_pose_in_robot_base.thor.yaml：gripper_backend: corenetic，corenetic_device_id 同上（两边必须一致，fr3_arms.validate 会检查）。

验收：Episode Replay 页 Preflight left 通过；Device Manager 里该夹爪 BOX 在线；在 Calibration → FR3 机械臂 的 ⓪ 遥控里能让左臂夹爪开合。

阶段 2 · 夹爪 BOX 预热和零点 操作员

  1. BOX 上电预热 30 分钟。
  2. Calibration → BOX 传感器 里「左臂夹爪 BOX …」那一组（阶段 1 在 fr3_arms.json 填了 corenetic_device_id 之后才会这样显示）：用组里的「夹爪 6D 零点」，模式选 origin（BOX 要重新上电，页面会提示），之后每 30 分钟一次动态校零。机械臂会动，有人守急停。不要用工装、也不要用「高级：手动校零」。

阶段 3 · 末端负载（Desk 负载）核对 操作员维护者

位置：Calibration → FR3 机械臂 → 末端负载辨识。机械臂会自动走一组静止姿态，用关节力矩算出法兰下挂了多重、质心在哪。

现状（11-10）：左臂末端和右臂是同一套配置，右臂 11-09 的辨识结果（Thor 上 outputs/fr3_payload/desk/20261109_152610/fr3_corenetic_desk_load_no_smr.json）已导入左臂 Desk，拖动时重力补偿正常；fr3_arms.json 也给左臂声明了这组值（注明「未在本臂辨识」），预检会拿左臂 Desk 的读数去比。所以这一阶段只剩一次核对采集（下面第 1–3 步，再看 Fz）；核对不过，或末端换过，再在左臂上完整辨识一次并替换。

  1. 勾完面板上的安全清单：臂在 start 姿态、周围清空（另一条臂已转开）、线缆有余量、有人守急停、已记下 Desk 当前负载、录制器已 Disconnect、BOX 已预热、夹爪空载且开度固定。
  2. ① 机械臂选 left，选末端配置和姿态集（要顺便拟合 6D 就选含「6D」的姿态集）。
  3. ② 碰撞检查：填实测的桌沿 x、桌面 z（相对左臂基座）和余量，运行检查，必须通过。
  4. ③ 开始采集，人全程看着。
  5. ④ 勾选同一末端配置的采集，生成 Desk 配置，导入 Desk。
  6. 导入后再采一次核对。
  7. 维护者 如果在左臂上重新辨识了，把结果写进 fr3_arms.json 的 arms.left.payload（并改掉 source 里的「未在本臂辨识」），以后预检会对照 Desk 核对。

验收：导入 Desk 后复采，日志里 Desk 的 O_F_ext 平均 Fz 在 ±0.2 N 以内。

参考：右臂 11-09 已做过（夹爪 + 相机、不带 SMR：1.1025 kg，质心 (5.8, −8.1, 42.0) mm），已导入 Desk 并写进 fr3_arms.json，预检会核对 Desk 与声明值（质量差 ≤ 0.05 kg、质心差 ≤ 10 mm）。末端加装或拆下 SMR、相机后要重做。

阶段 4 · 核对左臂的球窝位置 操作员

回放驱动的目标点是 corenetic_socket_ee，即插件 nov4 的球窝中心。两台臂共用同一个夹爪模型，这个点是 11-09 在右臂上实测后写进模型的（在 corenetic_gripper_ee 里约 (−0.96, 2.06, 33.50) mm，离法兰面 205.5 mm）。左臂上要确认它仍然成立。这一步和阶段 5 的第一个球可以合并做。

  1. Calibration → FR3 机械臂 → FR3 球窝 pivot，模式选 自动规划，机械臂选 left。
  2. ⓪ 让夹爪夹好插件（夹持方式和以后回放一致）。
  3. 摆球：球心离左臂底座水平 0.45–0.65 m，比桌面高 6 cm 以上。夹爪从侧面伸过去，和「底座→球」方向夹 60–90°，不要正对着往外伸（j6 会贴墙）。
  4. 1 取球心：用 Desk 引导键把夹爪大致水平地伸到球上方，球窝朝下坐到球上，松手后点 取当前位置为球心（只读关节角，不动）。之后不要再碰机械臂。
  5. 2 试探：「试探先验球心」三个格子留空（模型里的球窝就是实测球心；不要填 Desk EE，11-09 和 11-10 两次因此停机）。规划试探 → 看演算结果 → 执行（约 1–1.5 分钟，起点附近 20° 内 6 个驻点）。
  6. 3 规划 + 演算：试探拟合完成后自动「绕上次拟合的球心转」，规划 + 演算，演算全过（限位、速度、j6、桌面、支架）后 执行：14 个驻点，力环约 3 N 压在球上。

验收：拟合 rms 约 1 mm 以内；结果表里「corenetic_socket_ee 对不对」一栏，球窝中心应接近 0（1 mm 量级）。如果偏差明显（几毫米），说明左臂这套夹爪/插件和模型不一致，停下找维护者：模型是两臂共用的，不能直接改。

执行中如果因为外力超限（约 7 N）停机：先看是不是真的接触问题。软垫、先验填错、夹持变了（BOX 重启后重新夹）都会导致停机；换了夹持就重新试探。

阶段 5 · 同球检验，拟合 world → fr3_base 操作员

每个球位做两件事：FR3 绕球转（给出球心在 fr3_base 里的位置），然后球不动，手持夹爪绕同一个球转（给出球心在相机世界系里的位置）。多个球位配对后拟合出刚体变换，就是注册边。

球位怎么选

  • 至少 5 个（4 个是能做留一检验的下限；11-10 右臂只有 4 个，而且在一个方向上只撑开 68 mm，单个球就能把旋转带偏 0.7°）。
  • 两两相隔约 30 cm，不共线，也不要都在一个平面上：高低要拉开（例如桌面上 6 cm 和抬高 30 cm 以上的都要有）。
  • 覆盖以后左臂回放的主要工作区域。
  • 每个球位至少 2 台已标定相机能看到手持夹爪的贴片。
  • 每个球位都满足阶段 4 的摆球要求（水平 0.45–0.65 m、夹爪从侧面伸入）。

每个球位的操作

  1. FR3 pivot（左臂，自动规划）：取球心 → 试探 → 规划 + 演算 → 执行。条件允许时，从相差 60–90° 的两个朝向各做一次，在 ② 结果里勾选后 合并拟合所选（共用一个球心，球心不确定度大约减半）。备注写清楚球位（如「球 A」）。
  2. 把 FR3 移开，球不要动。
  3. 手持 pivot：手持夹爪夹插件坐到同一个球上，在 Live Record 正常录一段约 30 秒：先坐稳再开始，俯仰、滚转、绕竖直轴摆都转开，转完再停，全程球窝不离球。手持一侧用右手 rig（11-10 证明它很稳，pivot rms 0.3–0.7 mm）或左手 rig 都可以，因为两边各自拟合杠杆臂，手持的 TCP 常量误差不会进到球心里。
  4. 在 Dataset Processing 用对应的检测目标生成轨迹（检验时没生成也会自动生成）。

检验和存候选

  1. FR3 球窝 pivot → ③ 手持同球：添加位置，每行配对「FR3 pivot（或合并拟合）↔ 手持 episode」。下拉框会标出没有 world 戳的 episode，不要选这种。
  2. 点 检验，看 ④ 检验结果（见下方验收标准）。这一步只计算，不改任何东西。
  3. 通过后点 存为候选边，候选写到 outputs/calibration/fr3_base_registration/ball_<check>.json。

配对小技巧：球与球之间的距离不依赖注册边。如果不确定哪段手持对应哪个球，比较 FR3 侧和手持侧算出的球间距离（11-10 三对距离相差 0.3–1.3 mm），对得上就是配对正确。

阶段 6 · 应用注册边并固化 操作员维护者

  1. Calibration → FR3 机械臂 → FR3 基座注册边，点刷新，找到刚存的候选：看它的留一误差，以及相对现役边的挪动量（左臂现在没有现役边，这一项为空）。
  2. 确认后应用。如果此时到两台臂基座的路径都存在（例如已有两臂边），系统会做闭环检查：新边和其他路径在各自 sigma 内不一致就拒绝，这通常意味着某台车挪过。
  3. 应用后，守卫会记录新的受信版本。
  4. 维护者 立即把 Thor 上的 tools/thor/gmsl2/world/world_graph.json 拷回仓库并提交；否则下一次部署（哪怕是最新代码）会把它冲掉并触发红条。
  5. 维护者 在 tools/thor/gmsl2/world/README.md 里补一节「Result：left arm」：球位、配对、残差、留一、覆盖区域和已知偏差，格式参照 11-10 右臂那节。

阶段 7 · 端到端验证 操作员

  1. 用右手数据在左臂上回放（不需要左手 rig）：选一段 QC 通过的右手 episode，Arm 选 left，MuJoCo 选 Right hand 并在左臂基座里预演 → 通过 → Preflight left → 起点 → 执行。这一步验证左臂的边、负载和夹爪。注意右手录制的动作原本是给右臂的，左臂不一定都够得着，IK/MuJoCo 不过就换一段。
  2. 左手采集：手持左手 rig（106–109，BOX 3969377039），Dataset Processing 目标选 Gripper Rig v9b · 左手，生成和 QC 后，用 Left hand + left 臂回放。
  3. （推荐）勾上激光跟踪仪做一次回放误差分析，作为独立于同球检验的端到端核对。

端到端建议 MuJoCo 通过；真机回放完整执行；激光误差与右臂同量级—

双臂协同回放还需要什么

两台臂各自有了到相机世界的边以后，双臂回放还要知道两个基座的相对位置，用于两臂之间的碰撞检查。目前 fr3_arms.json 里的摆放是卷尺量的（两基座相距 0.66 m，sigma 20 mm），太粗，建议补一条两臂同球边：

  1. 选 ≥ 4 个两台臂都够得着的球位，相隔约 30 cm、不共线。
  2. 每个球位球不动，左臂和右臂各做一次 pivot（采集时选对臂）。
  3. FR3 球窝 pivot → 两臂同球 · fr3_base → fr3_base_right，每行配对左臂 pivot 和右臂 pivot，解算两臂边。两边都是关节运动学，不经过相机。
  4. 留一 ≤ 3 mm 才存为候选；在注册边面板里应用，闭环检查会核对它和两条世界边是否一致。
  5. 维护者 据此更新 fr3_arms.json 的 placement 和 sigma，提交并部署。

之后在回放页用 Both hands 和 Preflight all arms 做双臂回放。左臂边上线后，现有的相机世界系数据集不用重新导出，推理时用 --arm left 就会走左臂这条新边（见 第 8 节）。

什么时候要重做：任一台车挪过 → 重做那台臂的同球检验（和两臂边）；相机重新标定或支架改动 → 用原来的配对在 GUI 里重跑同球检验，确认边仍在门限内；换指尖、换插件、末端加装东西 → 重做负载（阶段 3）和球窝核对（阶段 4）。

术语

相机世界系（world）由固定相机定义的坐标系，id world_20260928_063531。轨迹生成的结果（sidecar）一直保存在这个系里。
基座系每台 FR3 自己的 libfranka O 系：左臂 fr3_base，右臂 fr3_base_right。
注册边world → 某个基座的刚体变换，存在 world_graph.json。回放时用它把轨迹换到臂的基座里。
pivot让工具绕一个固定点转动，从多组姿态拟合出这个点（同时得到杠杆臂）。
球窝 / corenetic_socket_ee夹爪插件 nov4 上的球窝中心，也是回放驱动的目标点和手持 rig 的 TCP。
同球检验同一个球，FR3 一侧算出它在基座系的位置，手持一侧算出它在世界系的位置，多个球位配对后检验或拟合注册边。
留一（LOO）每次去掉一个球，用其余的球拟合，再预测被去掉的那个；比拟合残差更能反映真实误差。
sidecar轨迹生成写在数据集旁边的位姿文件；每只手一份 state_action.<hand>.csv。给某台臂用的副本在 derived/<sidecar>/<基座>/。
world 戳录制时写进数据集的世界系和外参版本。没有戳的旧数据不能换到别的基座。
守卫（guard）Thor 记住它信任的那份坐标图；发现被改动就禁用到基座的边并亮红条。
