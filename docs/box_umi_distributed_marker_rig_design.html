BOX UMI 分布式夹爪 Marker Rig 设计说明

目标：评估并定义用左侧 / 右侧 / 上侧分布式 marker 替代高位 cube 的条件、收益、风险和验收协议。

关联主文档：BOX 高精度 UMI Trajectory GT Roadmap · 版本：2026-08-10

结论

Phase 3
可以拆开。 marker 不必安装成物理 cube；必要条件是所有可见 marker corner 属于同一个刚体，且这些 corner 在统一 rig 坐标系下有已标定 3D 坐标。 多相机定位求的是 T_world_marker_rig(t)，不是“立方体”本身。

照片里的高位 cube 有明确工程缺点：抬高安装包络，增加遮挡和碰撞概率，并拉长 marker_rig→TCP lever arm。若能把 tag 固定到夹爪的非运动刚体上，形成低矮、刚性的左/右/上三面 marker carrier，理论上更符合当前 roadmap 的 Phase 3 方向。

第一性原理

视觉测量链路只需要一个刚体观测模型：

u_ij = project(T_cam_i_world · T_world_marker_rig(t) · P_j^M)

其中 P_j^M 是第 j 个 marker corner 在 marker rig 坐标系下的 3D 坐标。只要 P_j^M 已知或可标定，corner 可以来自一个 cube 的多个面，也可以来自分布在夹爪左侧、右侧、上侧的多个 tag。

概念必须满足什么不必须是什么
marker rig同一刚体、角点坐标稳定、layout 可追溯不必须是 70 mm 或 72 mm 立方体
多相机定位所有可见 corner 进入同一个重投影优化不必须每台相机先独立 PnP 再 pose 平均
TCP 输出T_marker_rig→TCP 标定并带不确定度不应只写一个无 repeatability 的 fixed transform

推荐形态

优先
  • 做一个低矮刚性 carrier，固定到夹爪 palm、手腕连接座或固定外壳。
  • 左侧 / 右侧 / 上侧各布置 1 个或多个 tag，让不同桌面相机在不同姿态下总能看到足够角点。
  • tag 尽量大、平整、不可弯，贴在刚性基材上，不要只贴在软壳或薄纸边缘。
  • 左右手使用独立 layout 文件和独立标定 ID，避免镜像假设。
  • 保留 CAD 初值，但最终以多视角观测 refinement 和 repeatability benchmark 冻结。

硬约束

不可妥协
  • 不要贴在会随 opening 运动的手指上，除非显式建立 P_j^M(d) 或多刚体模型。
  • 不要让 marker carrier 参与夹持、接触或受力路径；受力会把几何误差变成系统误差。
  • 不要用胶带翘边、纸张弯曲或 3D 打印薄壁件作为最终精度基准。
  • 不要继续使用“每相机 best single marker PnP + pose 平均”作为最终 solver；分布式 rig 的收益需要 corner 级联合 BA 才能兑现。
  • 必须记录 layout hash、marker 尺寸实测值、标定时间、装配版本和 marker_rig_to_tcp_calibration_id。

利弊

方向收益代价 / 风险
机械包络降低高度，减少碰撞和遮挡；更适合夹爪真实操作空间需要重新设计 carrier，装配重复性必须量化
可观测性左/右/上分布扩大角点空间基线，姿态约束可能强于单面或小 cube侧面 tag 可能被夹爪本体或物体遮挡，掠射角会抬高 corner noise
精度传播降低 marker_rig→TCP lever arm 后，姿态误差传播到 TCP 位置的误差下降如果 carrier 柔顺或相对 TCP 漂移，算法无法靠更多相机修掉
软件模型统一成通用 marker layout，cube 只是特例；后续可支持 head cube、不同夹爪和版本化硬件需要替换硬编码 cube corner 生成、6 面假设、单 marker PnP 融合路径
维护局部坏一个 tag 仍可降级工作，QC 可按 corner/camera 可见性打分layout、ID、尺寸、装配版本管理更重要，配置分裂风险上升

验证协议

A/B

先做原型 A/B，不要直接替换生产配置。判据优先用无参考指标，其次用 FR3/FK 或治具辅助。

采集组目的主要指标
静止 300-1000 帧测 jitter、corner noise、机械微动TCP jitter、pose covariance、reprojection residual、相机间一致性
慢速 6DoF 摆动覆盖姿态和视角变化visible camera count、visible corner count、姿态连续性、catastrophic jump
典型操作遮挡验证真实任务中 tag 是否被物体/手遮挡有效轨迹覆盖率、低质量帧比例、最差姿态区间
拆装重装 5 次测装配 repeatabilityT_marker_rig→TCP translation / rotation p50、p95、max
轻载荷 / 接触方向测 carrier 与夹爪柔顺性接触前后 pose residual、回零 residual、方向相关偏置
验收口径： 如果分布式 rig 的相机间一致性、jitter、有效覆盖率没有优于高位 cube，或者拆装 / 载荷 p95 已接近 3 mm，则不能把它作为 GT 主路径冻结。 如果它只改善碰撞风险但精度持平，可以作为机械改良继续推进，但仍需标注新的 tcp_extrinsic_sigma。

代码影响

  • 新增通用 marker_layout.json：marker ID、marker size、每个 marker 的 T_marker_rig_marker_k、corner 顺序、layout hash、左右手实例 ID。
  • 把 cube_tracking.py 中“理想 cube 面角点解析生成”改成“读取 layout 后生成统一 P_j^M”。
  • 保留旧 cube 配置作为 layout 的一个兼容实例，避免一次性打断现有评估。
  • Phase 4 solver 应使用所有相机所有可见 corner 的鲁棒重投影 BA；单相机 PnP 只作为初始化和诊断。
  • sidecar 增加 marker_layout_id、marker_layout_hash、marker_rig_to_tcp_calibration_id、visible corner/camera count、covariance 和 quality flag。
  • QC 增加 layout 版本检查：数据集、tracking 配置、标定报告必须指向同一个 layout hash。

建议决策

  1. 短期：保留现有 cube 作为 baseline，同时做一个低矮分布式 carrier 原型。
  2. 中期：实现通用 marker layout 读取，让 cube 和分布式 rig 都走同一套观测模型。
  3. 冻结前：必须完成静止、慢速、遮挡、拆装、载荷五组 A/B，并把结果写入 Phase 3 benchmark。
  4. 命名：生产抽象改称 gripper_marker_rig；避免继续把所有 marker 目标都叫 cube。
