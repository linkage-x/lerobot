原文搬运

2.1 理论误差预算与可达精度判断

用于判断当前多相机 rig 是否具备毫米级测量能力，并定位真正的精度瓶颈。

误差模型
核心判断：若工作距离约 0.7–1.2 m、有效 baseline 约 0.4–0.8 m、角点定位误差约 0.1–0.3 px，纯随机三角测量误差理论上可落在亚毫米量级。最终 2–3 mm TCP 精度更可能受外参、标定板尺度/平整度、机械漂移与 marker→TCP 等系统误差限制。
现场实测（outputs/calibration/thor_gmsl2_extrinisics_robot_base_0720，7 相机联合解）： per-camera sample residual translation mean 2.3 – 7.7 mm（最差 cam_07，max 53 mm）、rotation mean 0.34° – 1.27°（max 6.97°）； pair residual translation mean 5.4 – 21.9 mm。较早的 Hikon 8 相机报告同量级（sample 4.33 mm / pair 11.9 mm，辅助 marker spread mean 4.9 mm、max 50.7 mm）。

对照上表：0.5°–1.3° 的外参旋转误差在 1 m 处就是 9–22 mm 等效位置误差，比 3 mm 指标高一个数量级。现阶段瓶颈明确在 rig 外参，不在角点噪声，也不在相机数量。 一个直接原因是标定目标：当前 stage-3 用的是 single_tag36h11_id6_160mm——单个 160 mm AprilTag，四个角点、共面、深度与倾角方向天然弱约束。
Level 1 实测（2026-08-04，outputs/metrology/level1_0720，7 相机，σpixel=0.2 px 假设）： 上面那句「瓶颈在外参」不再是推断，已量化证实。全工作区 worst-axis σ 为 p50 0.14 mm / p95 0.26 mm / max 0.34 mm；亚毫米区（σmax<1 mm）在 z≈0 处达 7.0 m²，含一个 2.24 m 的完整内接方形（中心 x≈0.30, y≈−0.05），高度上从 z≈−0.4 覆盖到 +0.8。

敏感性检验都推不翻结论：角点噪声放大到 0.5 px（区间上限的 1.7 倍）→ max 0.86 mm；裁掉图像边缘 150 px（回避未验证的厂商边缘畸变）→ max 0.56 mm；只保留 3 路相机（模拟重度遮挡）→ max 0.46 mm。

因此 Phase 2.2 的分支判据已经落地在「另一侧」：理论 <1 mm 而实测 3–5 mm ⇒ 优先排查 calibration bias、marker geometry、机械漂移，而不是改相机几何。 不要挪相机 任何放得进房间的桌子都完整落在亚毫米区内，增加相机数量同样不会改善——余量已经在两个数量级上。
0804 重标结果（calib_20260804_150355）：瓶颈已被移除。换 ChArUco + 脱离机器人后， 独立 3D 一致性（BA 未用过的 608 帧，三角化 vs 已知板几何刚体拟合）：p50 0.078 mm / p95 0.254 mm； 重建尺度偏差 +0.008%（1 m 处 0.08 mm，说明板标签的 30 mm 是准的）。 对照 0720 的 per-camera sample 平移残差 2.3–7.7 mm，好一个多数量级。 补覆盖并改用 fisheye 内参后进一步降到 p50 0.077 / p95 0.244 mm，BA 重投影 0.2437 px，cam_07 的残差从 0.85 px 降到 ≤0.265 px。

交叉验证：Level 1 理论预测 σmax p95 = 0.26 mm，此处实测 3D 一致性 p95 = 0.254 mm。 两条完全独立的路径给出同一数量级——Level 1 的模型可信，且「几何不是瓶颈」的结论得到实测确认。

生产 A/B 的决策结论：0805 已把这套标定接入生产；同一批像素上的端到端结果没有可测量提升，而把 marker_size_cm 从 5.8 改为 5.6 将相机间一致性从 26.6 mm 降到 4.1 mm。完整过程归档在 8 路相机标定实验报告；本页只保留“停止继续投入相机重标、转向 Phase 3 实物几何”的结论。
口径修正：本页下方「关键公式与数量级推导」的算例（Z=1 m, f=1000 px, B=0.5 m, σ_d=0.2 px → σ_Z≈0.4 mm）把 0.2 px 直接当成了视差噪声。 σpixel 是每角点测量噪声，而视差是两次独立角点测量之差，故 σ_d = √2·σpixel，同条件下的正确值是 ≈0.57 mm。不影响任何结论，但两个数都已在 metrology/tests/test_uncertainty.py 里钉死，避免再次混用。

关键公式与数量级推导

双目近似模型：

Z = fB / d

深度随机误差近似：

σ_Z ≈ Z²/(fB) · σ_d

例如 Z=1 m, f=1000 px, B=0.5 m, σ_d=0.2 px：

σ_Z ≈ 0.4 mm

多相机 joint pose estimation 中，多个不同方向观测共同进入 (JᵀWJ)⁻¹；随机误差可进一步下降，但 scale bias、外参 bias、机械漂移等系统误差不会按 1/√N 自动消失。

为什么“相机方向”比“相机数量”更重要
  • 多台相机如果几乎都垂直向下，XY 很强，但 Z 与部分旋转方向仍可能弱。
  • 应优先形成不同 azimuth / elevation 的交叉视角，而不是单纯增加同方向相机数量。
  • 建议计算 workspace Fisher information / pose covariance map，直接查看不同位置的 σx / σy / σz。

2.2 Workspace Uncertainty Map：σx / σy / σz

回答“桌面哪里测得准、哪里测不准，以及当前多相机 layout 是否天然支持 ≤3 mm”。

建议展开
它算的不是实际 GT 误差，而是几何可观测性： 在已知相机内外参和假定 pixel/corner noise（例如 0.2 px）时，预测工作空间中某个 3D 点或刚体 pose 的理论协方差。
核心含义与计算

对空间点 P=[x,y,z]ᵀ，每台相机给出投影 u_i = π_i(P)。线性化后：

δu ≈ J · δP

若像素观测协方差为 Σ_u，则三维点协方差近似：

Σ_P ≈ (Jᵀ Σ_u⁻¹ J)⁻¹

最终读取：

σx = √Σ_P(0,0), σy = √Σ_P(1,1), σz = √Σ_P(2,2)

对 UMI 更推荐进一步对 marker 刚体的 6DoF pose 求 Jacobian，得到：

σx, σy, σz, σroll, σpitch, σyaw

为什么它能直接指导相机布局
  • 如果多台相机几乎都从上往下看，通常 XY 很强，但 Z 与部分旋转方向可能偏弱。
  • 真正重要的是不同 azimuth / elevation 的交叉视角与有效 baseline，而不是“相机数量多”本身。
  • 如果右后角 σz = 5 mm，而中心 σz = 0.6 mm，优先调整能改善右后角交叉角度的一两台相机。
  • 可在虚拟相机布局上先重算 uncertainty map，再决定是否实际挪相机。
建议输出的 4 类可视化
  • σx map：水平 X 测量精度。
  • σy map：水平 Y 测量精度。
  • σz map：深度方向精度，桌面上方相机系统通常最值得关注。
  • worst-axis map：σmax = √λmax(Σ)，直接显示最差方向的不确定度。

进阶版可画 3D uncertainty ellipsoid，直观看出“哪个方向被约束得最差”。

从 point map 升级到 UMI pose map
  • 单点 map 只反映位置几何，不反映 marker cube 尺寸和朝向。
  • 实际 UMI 应把所有可见 marker corners 对刚体 SE(3) pose 的 Jacobian 联合起来。
  • 完整版应依赖 (x,y,z,R)：同一位置下 marker 转 90° 后，可见面和姿态可观测性会改变。
  • 第一版可以固定几个代表性姿态；第二版再加入 FoV、tag incidence angle、marker 可见面等 visibility model。
建议验收：先看理论 map 是否在主要操作区满足 σmax < 1 mm 左右；若理论上已经是 4–6 mm，则应先改相机几何。若理论上 <1 mm、实测却 3–5 mm，则优先排查 calibration bias、marker geometry、机械漂移等系统误差。

2.3 Uncertainty Map 实现路线

从“相机布局几何”逐步升级到“真实 UMI TCP 可达精度预测”。

建议实现
推荐不要一步到位：先做最简单的 3D point geometry map 验证相机布局，再升级到 marker 6DoF pose covariance，最后把 marker→TCP lever arm 传播进去得到真正与训练标签相关的 TCP uncertainty map。
代码现状：Level 1 / 2 / 3 均已完成。Level 1（2026-08-04）位于 metrology/uncertainty.py + metrology/cli/level1_uncertainty_map.py； Level 2 / 3（2026-08-18）位于 metrology/tcp_uncertainty.py + metrology/cli/level3_tcp_uncertainty_map.py， 可见性模型由 metrology/cli/fit_marker_visibility.py 从真实采集拟合而非假设。 如预判，cv2.projectPoints() 返回的 jacobian 只对 rvec/tvec/内参，不对 3D 点，因此走中心差分——这样真实的 rational 畸变模型也留在导数里，而不是退化成理想 pinhole。

验证做了两层：解析协方差对拍闭式双目公式 σ_Z = Z²/(fB)·σ_d（精确相等）；再在真实 rig 上对拍蒙特卡洛三角化——近场 3 点吻合 1–5%，远场（距相机 2.6–2.8 m、仅 4 路可见）吻合 2%。后者是端到端的，T_base_cam 方向反了或 Jacobian 退化成 pinhole 都会被它抓住。

两个实现要点值得记下：①可见性判据必须除了「投影落在图像矩形内」之外再加视线方向约束——rational 畸变模型会把远离光轴的点折回传感器，只判矩形会把不可见点误判为可见。②地图的定义域由相机覆盖自动导出（coverage_extent()：扫出 ≥2 路可见的体积），不依赖机器人也不依赖桌面尺寸——世界系若绑机器人，机器人一挪结论就得重算。

Level 3 结果（2026-08-18）：理论噪声不是瓶颈，和 Level 1 的结论一样，但这次是在 TCP 上、用真实 rig 说的。 操作区 1.0 × 1.0 × 0.6 m、步长 0.1 m（847 点）、每点 32 个均匀采样姿态、σpixel = 0.2 px： 847/847 点全部可解；σTCP 按姿态取 p50 后，全区 p50 0.09 mm / p95 0.23 mm； 按姿态取 p95 后（即"姿态转到最差方向"），全区 p50 0.23 mm / p95 0.49 mm。
对照实测：同一 rig 的 |p_rig| 端到端误差 0.90–1.03 mm、逐相机位置分歧 p50 4.1 mm。 理论比实测低一到两个数量级 —— 正落在本节验收语「若理论上 <1 mm、实测却 3–5 mm，则优先排查 calibration bias、marker geometry、机械漂移等系统误差」的那一支。 结论：不要加相机、不要指望降 σpixel；剩余误差全部是系统项（相机外参、layout、装配）。
visibility model 是量出来的不是猜的：入射角 0–40° 检出率 92–98%，65–70° 降到 77%， 75–80° 跌破 50%（拟合 cutoff 80°），85–90° 归零。0–40° 段的 92–98% 同时说明rig 自遮挡很轻，不必单独建模。
σpixel 已不再是假设（2026-08-18 实测，见 2.4 节）。生产检测器在 <70° 实测 0.156–0.214 px， 所以上面按 0.2 px 算的图直接成立（σ 与 σpixel 严格线性，0.5 px 的敏感性运行已确认恰好 ×2.5）。 按实测中位 0.167 px 折算：σTCP（姿态 p95）全区 p50 0.19 mm / p95 0.41 mm； 若把 rig 检测链路的 SUBPIX（<60° 实测 0.04 px）也算上，则降到 0.05 / 0.10 mm 量级。 无论取哪一档，都比实测的系统项低一到两个数量级，结论不变 （该系统项 2026-08-18 已从 0.9–1.0 mm 降到 0.54 mm，并判定为装配/打印项，见 rig 记录 5.3 节）。
仍未建模的两项：① 本图用单一 σpixel，而实测显示 70–80° 掠射时 σ 抬高 2–4 倍 （80° 的可见性截断只挡掉了一部分），所以掠射姿态下本图偏乐观；把角点按 σ(入射角) 加权是下一步。 ② TCP 姿态不确定度已一并输出，但它在夹爪轴系里的语义仍待 rig 装到夹爪后确认。
Level 1：Point Geometry Map 怎么算
  1. 将 workspace 离散成 3D grid，例如每 20 mm 一个采样点。
  2. 对每个点判断哪些 camera 可见：在相机前方、投影落入图像 FoV。
  3. 对每个可见 camera 求投影 Jacobian J_i = ∂(u,v)/∂(x,y,z)。
  4. 将所有 camera Jacobian 堆叠成 J。
  5. 根据像素噪声权重 W 计算信息矩阵：

H = Jᵀ W J

三维位置协方差：

Σ_P ≈ H⁻¹

读取：

σx = √Σ(0,0), σy = √Σ(1,1), σz = √Σ(2,2)

worst-axis：

σmax = √λmax(Σ_P)

正式版本：建议用 OpenCV projectPoints() + 数值差分求 Jacobian，从而自然包含真实 distortion model，而不是只用理想 pinhole 解析式。

这次采集的两个缺口。① cam_08 在全部 6 个姿态里都只看到 1 个 marker（8 观测 vs 6 位姿自由度， 修正因子 2.0，不可用），所以 7 台里只测到 6 台；补一个让 cam_08 看到 ≥2 个 marker 的姿态即可。 ② 静止测得的是下界：生产中 rig 在动，运动模糊会抬高角点噪声，仍需按「曝光 × 速度」估模糊惩罚或在典型速度下复测。

采集协议（必须做对，否则测的是别的东西）：

  • 目标刚性固定在工作区内，用生产曝光/增益/帧率、生产照明，连续采 300–1000 帧。相机先热机 ≥15 min。
  • 关键：静止目标不等于静止。楼板振动、空调风、有人走动都会让整块板一起动，直接算 corner 方差会把这部分算成探测器噪声。 正确做法是先对每帧拟合该 tag 的刚体位姿/单应，再统计去掉刚体运动之后的重投影残差——那才是探测器噪声。两者之差本身就是有用信息（机械稳定性）。
  • 测生产路径实际用的角点。已核实生产 tracking（cube_tracking.py）用的是 cv2.aruco.ArucoDetector 默认参数，即 CORNER_REFINE_NONE；pupil_apriltags 只出现在标定脚本里。上表两列就是这条路径的 A/B。
  • 按 image radius / marker 投影尺寸 / 入射角分桶，并逐相机给值（--sigma-pixel-camera cam_07=0.35），而不是全 rig 一个数。
  • 静止测得的是下界。生产中 cube 在动，运动模糊会抬高角点噪声；需另行按「曝光时间 × 运动速度」估模糊惩罚，或直接在典型运动速度下复测。

产出：实测 0.167 px 与假设的 0.2 px 相差 1.2 倍，远在 2 倍以内，故本页所有结论不变（σ 与 σpixel 严格线性，已在测试中钉死）。工具：metrology/cli/measure_corner_noise.py --rig-layout-json …（新增 rig 目标通路与逐 marker σ 输出）。

Level 2：升级到 Marker 6DoF Pose Map

最终 tracking 的不是一个孤立点，而是刚性 marker cube。对 marker pose 的局部扰动：

ξ = [δx, δy, δz, δθx, δθy, δθz]ᵀ

把每个 camera、每个可见 marker corner 的 reprojection Jacobian：

J_ij = ∂u_ij / ∂ξ

全部堆起来：

Σ_pose ≈ (Jᵀ W J)⁻¹

因此可以同时得到：

σx, σy, σz, σroll, σpitch, σyaw

完整版应依赖 (x,y,z,R)，因为同一位置下 marker 转 90° 后，可见 marker 面和姿态可观测性会改变。

Level 3：传播到 TCP，而不是停留在 Marker

最终训练需要的是 TCP trajectory，因此 Marker covariance 还要通过 T_marker→TCP 传播。

关键原因是 lever arm：marker orientation uncertainty 会转化成 TCP position uncertainty。

例如 marker→TCP 距离约 120 mm，orientation uncertainty 0.5° 时，仅 lever-arm 项就约产生 1 mm 位置误差量级。

最终得到：

Σ_TCP = J_M→TCP · Σ_marker · J_M→TCPᵀ

建议最终 QC 直接使用：

σ_TCP,x / σ_TCP,y / σ_TCP,z / σ_TCP,max

推荐画哪些图
  • σx heatmap：World X 方向理论精度。
  • σy heatmap：World Y 方向理论精度。
  • σz heatmap：深度方向理论精度，通常最重要。
  • σmax heatmap：协方差最大特征值对应的最差方向。
  • 3D uncertainty ellipsoid：对代表性位置画协方差椭球，直接看最弱约束方向。
  • 多高度切片：例如 z=0.15 / 0.30 / 0.45 / 0.60 m，避免只看单一桌面高度。
实现顺序： 先完成 Level 1，并用它决定是否需要调整 camera placement 已完成，结论=不需要调整； rig 冻结后做 Level 2； marker→TCP 标定完成后做 Level 3。 最终真正与 UMI GT 质量对应的是 Level 3，而不是 Level 1。 Level 1 的 σ 已经小到可以忽略，意味着 Level 2/3 的数值将几乎完全由 marker 几何与 marker→TCP lever arm 决定——这两项的标定质量就是最终 GT 质量。

Phase 2.4 · Canonical World Persistence（理论依据与工程实现）

原文搬运

主 roadmap 保留的是本节的原则、阈值、冻结基准与剩余缺口；此处是完整的 gauge 理论、稳定相机识别算法、已实现的模块清单、阈值实测过程与冻结论证。

理论依据：gauge、canonical frame 与 stable-camera consensus

1）BA gauge 与长期 world frame 是两件不同的事。 BA 为消除 SE(3)+scale 的 gauge freedom，可以临时固定一台相机/一帧 board；这只是优化内部约束。对外落盘的 W 应是一个冻结的 canonical frame，并由历史高质量标定保存 T_WC_i^ref。它可以取桌面友好的方向，也可以沿用现有 world，只要定义冻结且可版本化。

2）“至少 4 台不动”不是唯一性的数学要求，而是可靠性的工程要求。 若某台相机确定没动，它单独就可把新 session 注册回旧 W；但单相机没有自证能力。对候选稳定集合 S，可比较历史与当前 pairwise 外参：

ΔT_ij = inv(T_CiCj^ref) · T_CiCj^cur

若多对相机同时满足 translation / rotation threshold，它们形成稳定 cluster。4 台相机提供 6 个 pairwise constraints，可用 robust voting / maximum-consensus / clique 的方式识别“未移动子集”，并排除被碰动的 camera。

3）新 session 的临时 rig frame 不应成为新 world。 假设当前重标得到临时 gauge S，对稳定相机集合求一个共享刚体对齐：

T_WS* = argmin_T Σ_{i∈S} ρ( || Log( inv(T_WC_i^ref) · T · T_SC_i^cur ) ||²_{Σ_i^-1} )

然后所有当前相机统一写成 T_WC_j^cur = T_WS* · T_SC_j^cur。被移动的相机只更新自己的 T_WC_j；只要稳定 cluster 存在，canonical W 本身不跳。

4）stable-camera consensus 有一个不可观测模式：所有“稳定相机”共同做相同刚体运动。 若它们装在同一个框架且框架整体移动，所有 pairwise T_CiCj 都不变，内部 consensus 无法发现。这不妨碍定义唯一 camera-rig world，但会破坏它相对桌面/地面的绝对稳定性。若这种 common-mode motion 有现实可能，可保留一个与相机架机械独立的固定 ArUco / datum / laser-tracker reference 作为低频 global-drift watchdog，不再承担主标定。

5）移动平台 marker 与 world anchor 的角色必须分开。 左右 FR3 平台上的 ArUco marker 随机器人一起移动，因此它们用于估计 T_WP_L/R，不能反过来定义 W。这使系统形成清晰的三层关系：canonical camera world → mobile platform → FR3 base。

6）全相机移动时不是“旧数据失效”，而是 world graph 断边。 对旧轨迹做任意共同左乘 X∈SE(3)，episode 内 relative motion 与双手相对位姿不变：inv(XT(0))·XT(t)=inv(T(0))·T(t)，且 inv(XT_L)·XT_R=inv(T_L)·T_R。因此 delta/RPE/bimanual/contact-local 等 training-facing 信息不依赖跨 session absolute world continuity。真正不可观的是 T_Wnew←Wold；没有跨移动仍固定的 reference 时，任何算法都不能凭 camera graph 自己恢复它。

7）World 应被建模成可版本化的 pose graph，而不是一个永远只有一个名字的全局变量。 每个 canonical world node 有唯一 world_frame_id；若 continuity 可由 stable-camera consensus 保持，则继续同一 ID；若全部相机移动且无外部 anchor，则创建新 ID。以后若通过固定环境 marker / laser tracker / 其他跨 session datum 恢复 T_Wnew←Wold，只需给两个 world node 增加一条带 covariance 的 registration edge，历史 trajectory 本身无需重建。

8）因此“唯一世界系”与“永不漂移的物理绝对系”不是同一要求。 日常 session 需要的是 canonical world 的连续性；全相机移动时允许 continuity 显式断开。固定 environmental anchor 的职责只是避免/修复这类断边，不能成为历史数据可用性的前置条件。

工程实现：如何识别稳定相机并维持 world
  • 首次高质量标定冻结 world_reference.json：canonical frame 定义、每台 T_WC_i^ref、covariance/quality、标定版本与内容哈希。该文件必须纳入版本管理（现落在 tools/thor/gmsl2/world/，不放 outputs/）：它不可重建——重跑 freeze 会给同一个物理坐标系产生第二个 world_frame_id，把已录数据里盖的 ID 全变成孤儿；而 outputs/ 是 7 GB 可再生产物、会被清理。工作站与 rig 之间只能拷贝这个目录，不能各自 freeze。
  • 每个 session 用共同观测重新估计当前 camera graph；比较所有可用 pairwise T_CiCj 与 reference，robustly 找最大稳定 cluster。默认期望 ≥4 台；少于 3 台时不建议自动宣布 world persistence 通过。
  • 用稳定 cluster 联合求一个共享 T_WS，而不是任选一台相机硬当 world；输出 alignment residual、stable-camera count、每台 residual 与 world covariance。
  • 被判定移动的 camera 可以重新求 T_WC 后继续加入 tracking，不应通过重新定义 world 来“迁就”它。
  • 如果稳定相机分属不同机械支架，共同刚体移动的风险很低；若多数稳定相机共用同一大框架，建议在墙/地面/独立结构上保留少量固定 marker，只做 common-mode drift health check。
  • 新增 world continuity state machine：CONTINUOUS（stable cluster 可把当前 session 注册回原 W）、RECONNECTED（原先断开的两个 world 通过独立 anchor 后验接回）、BROKEN（无稳定 camera/独立 anchor，创建新 world island）。
  • 所有 episode / calibration / derived trajectory 必须写 world_frame_id、calibration_id、world_continuity_state、stable-camera IDs、registration residual/covariance；若存在跨 world edge，再写 parent_world_frame_id 与 T_parent_current。
  • 禁止 silent relabel：不能在全相机移动后继续复用旧 world_frame_id，也不能为了让旧/new absolute pose 看起来连续而把未知 SE(3) 当成单位阵。relative / bimanual 数据可跨 island 训练；absolute-world 数据跨 island 使用前必须有显式 registration edge。
