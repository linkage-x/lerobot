## 速度：rollout 时间花在哪（11-13 测，170025 的 rollout_010–018 和 R4 训练视图）

**控制环和推理不是瓶颈：**
- 控制周期中位 33.0 ms，p95 34 ms，9 次里只出现过一次 145 ms，没有停顿。
- 推理 p50 约 62 ms，异步进行（大约每 2 步一次），控制环从没等过推理。

**策略段：**
- 每次 13.4–19.6 s（403–588 步）。
- 自由空间（z > 0.12 m）中位约 46 mm/s，占 9.5–13.8 s；低处中位约 20 mm/s，占 3.4–9 s。
- **速度 p95 是 57 mm/s，和训练数据的 p95（57.5 mm/s）一样。** 示教数据从起点到合爪的中位时长是 13.3 s。策略就是在照着示教的速度走，没有比示教更慢，所以想加速只能改数据的时间尺度，或者改执行时的时间尺度。

**整次 trial：**
- 一次顺利的 trial 约 55–65 s：摆 peg 约 10 s，策略约 14 s，其余 30–40 s 是脚本插入（servo 2 cm/s、各段 settle/dwell、搜索）、松手和撤回。
- 也就是说，就整个循环而言，最大的一块其实是脚本。

**能加速的办法（按代价从低到高）：**
1. **执行侧时间缩放（不用重训）：** 只在自由空间把预测出的 chunk 按 1.5–2 倍播放（把相邻的 delta 相加），低处保持 1 倍。
   - 可以开关，单变量 A/B。
   - 2 倍时 p95 约 115 mm/s，低于每步 5 mm 的限幅（150 mm/s）。
   - 风险：ee 相机的运动模糊；观测和动作的节奏跟示教不同，会带来分布偏移，所以只用在自由空间。
2. **训练数据快进：** 因为动作是 `delta_ee_from_prev_cmd`，可以每 k 步合成一步（delta 相加，夹爪取最后一步，图像每 k 帧取一帧），作为一个新视图做，不用重录。
   - 建议按阶段加速：只把合爪点上方 60 mm 以外的部分加速 2 倍，低处不动，避免影响现在的精度线（近处 +x、死区）。
   - 更稳的做法是加速度条件化：原速版和快进版一起训，用一个 token 或 prompt 区分。同一个 ckpt 能跑两种速度，A/B 只差一个变量。
   - 文献里 DemoSpeedup、SAIL 是这一类方法。
3. **异步 / RTC：** 现在已经是异步，单靠它省不了时间。但加速以后必须保留：一个 chunk 在推理延迟期间会走过更远的距离，要靠 RTC 的 inference_delay 接上。R4 那条线已有 `--phase-align-unguided`（只在自由空间用 guidance），正好和"只在自由空间加速"配合。
4. **脚本段：** servo 在自由空间搬运可以提到 5 cm/s，最后 2 cm 保持 2 cm/s，再裁掉多余的 dwell。这对采数据吞吐（mass collection）帮助最大，但会改变和以往基线的可比性，所以只在两个 A/B 块之间改。

**更正（同日稍后，用 force trace 的时间戳逐段拆开 170025 的 trial 9–17）：** 一次第一落点就进的 trial（58–75 s）实际是这样分的：

| 段 | 时间 | 说明 |
|---|---|---|
| 摆 peg（scene reset） | 7–8 s | |
| 摆完到策略第一步 | **24.4 s，每次几乎一样** | 包括 `return_to_start`（关节空间回 home，`SCENE_RESET_HOMING_SPEED_SCALE=0.25`）和 rollout 启动。JEPA sidecar 的 `activated_after_s` 是 19–22 s，而且整轮在缓慢变长。具体怎么分还要加时间戳才能确认 |
| 策略 | 13.4–17.6 s | |
| 抓完 → 抬起 → 对准 → 下插到底 | **约 4.8 s** | |
| 下插完到撤回 | 5.5–19 s | 主要是有人值守时等人评分 |

- **插入本身很快。** 第一落点就进的话只要约 5 s。搜索只在第一落点没进时才花时间：每多一个落点约 2.4 s，搜满 17 个点的 miss 要 +25–30 s。
- **按 11-11 的发现，插入基本是一次性的。** 第 1–3 个落点没进的，之后只有 2/19 进了。

**按收益排序：**
1. **home 加速：** 成功路径上手里是空的，回 home 可以用 0.5 而不是 0.25。0.25 是为"手里还拿着 peg 的失败复位"定的。预计省约 6–10 s。
2. **评分不阻塞：** 这里有个约束：10-23 的规则（落点 ≤ 8 判 seated 就可信，53/53）在 R3 用策略抓取时失效了（18 进 / 6 出），所以评分不能完全交给自动判定。
3. **搜索封顶 3–4 个落点：** 每次 miss 省 25 s 以上，也少压几次孔沿，少把 peg 压歪。
4. **自由空间加速：** 开关已做好，约省 5 s。
5. **让第一落点更准（提高成功率，而不只是提速）：**
   - 按抓取后看到的 peg 在手里的偏移修正下插点（in-hand x 偏移看得见，r=0.92）；
   - 用接触时的力矩方向挑下一个落点，代替固定的搜索顺序。peg 落在孔沿上时，力矩应该指向孔心。这一点可以先拿已有的 force trace 离线验证。

**自由空间加速开关（11-13 做好，未部署，没提交）：**
- runtime 参数 `--free-space-speedup F --free-space-above-z Z`，启动脚本环境变量 `FR3_FREE_SPACE_SPEEDUP` / `FR3_FREE_SPACE_ABOVE_Z`，Rollout 页上有 "Free-space speedup" 和 "Above z" 两栏。
- **工作方式：**
  - 在 Z 以上，每个控制步从 RTC 队列取 F 个动作（小数按累计分配，1.5 就是 1、2 交替），把它们合成一个 delta 发出去：位置相加，旋转按顺序相乘，夹爪取最后一个。
  - RTC 的 guidance delay 按动作数换算（`time_per_step / rate`）。
  - 遇到合爪动作就停止合并；队列空了也停。
  - 低于 Z 时退回 1 倍；离开后要升到 Z + 滞回距离以上才重新开启。
- **启动时会拒绝的情况：** 没开 RTC、绝对动作的 checkpoint、F 不在 [1, 3] 内、没给 Z。
- **记录：** grasp loop 的 `run_start` 行会写 `runtime.freeSpaceSpeedup` / `freeSpaceAboveZ`；trace 里的 `chunk_pos` 加速时每步跳 F。
- **测试：** 合成动作和逐步重建落点一致（包括三轴旋转的情况）；runtime、GUI 和 grasp loop 的测试共 586 个全过；前端 236 个测试全过并已 build。
- **建议的第一次上机：** F=1.5、Z=0.12，用 R4、新 seed、10 次，看策略段时长和插进率。

结论：不改 R3 → R4 → R5 的顺序。这份建议用的是旧数字，并且把插入当成了策略的一个阶段，实际插入由脚本完成。它的假设 H1（失败是被步数上限截断）不成立，查过日志：093213 和 151543 共 30 次 trial，没有一次被截断。合爪步数在 276–451，上限是 600；4 次 collision 是碰撞反射结束的，也不是截断。

## 附：孔位置不固定时，还能不能用脚本专家（10-23 记）

**结论：不一定要人工接管。** 脚本专家需要的只是目标位置，而且离线重标时事后知道就够了。只要每个 trial 的目标位置有办法拿到，脚本专家加离线重标就仍然可用。

**参照：peg 的位置本来就不固定。** 每个 trial 的 peg 位置都是随机的，漏斗照样能纠偏，因为 peg 是机器人自己摆的，pegXyz 已知。这就是专家使用策略看不到的特权信息：策略只看图像，专家和重标用真值位置。孔不固定时，问题同样只是怎么拿到孔的真值。

**拿孔真值的办法（代价从低到高）：**
1. **事后反推：** 插进去的 trial，最终 seated 的位姿就给出了孔的位置，可以用来重标这个 trial 之前的所有帧。插不进的 trial 不能这样用：要么 mask 掉，要么用搜索落点粗估一个位置。
2. **每个 trial 测一次孔：** 在固定件上贴 marker 或 AprilTag 用相机测，用深度相机检测孔，或者先用末端接触探一下。测量结果只给专家和重标用，策略不需要。
3. **脚本搜索当专家：** 现在的插入就是"大致位置 + 搜索"，孔漂几毫米能自己找到。

**必须人工接管的情况：**
- 孔的位置连事后都拿不到（没有 marker、测不了，也插不进）；
- 或者纠偏动作本身写不成脚本，例如需要复杂的接触手法，或者 peg 在指间歪了要调整。

**和现状的关系：**
- 现在策略只负责抓取，插入由脚本完成，所以孔位置会不会变，暂时不影响这条 DAgger 路线。
- terminal servo 的孔位置（查过代码）：一个固定的绝对位姿 `--grasp-loop-insert-pose`（GUI `graspLoopInsertPose`），没插进就按环形搜索落点。另有一个开关 `--grasp-loop-insert-follow-seat`，下一次瞄准上一次插进去的位置，这已经是办法 1 的简单形式，用来跟踪固定件的漂移。系统里没有任何孔的检测。
- 以后要让策略连插入也学：先用办法 1（几乎不增加成本，seated 位姿已经记在记录行里）；办法 2 更通用，到时再做。
