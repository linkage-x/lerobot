换 Carrier 值多少毫米

把打印出来的 Hybrid Carrier V1 换掉现役分布式 marker rig，轨迹误差能走到哪里。 答案取决于一件事：p95 里只有 54% 的方差是 carrier 能碰的，剩下 46% 是相机外参， 换什么靶标都不动。所以这是一张尾巴账——中位数几乎不变，能改的是分位数尾部。 至于"那不如退回全 ArUco"：同一套回路里它差 3 倍，而且差距全在涂装棱上， 与 marker 的数量和尺寸无关（E 节）。

A起点不是 5.5–7.4

在算收益之前，先把基线钉对。

路线图首页那个大字框标的是 2026-08-21 口径。08-27 做了两次下调，那一页没跟着改： 先删掉 L·θ 这笔重复记账（p95 5.52 → 4.45），再把 p95 从"分位数各自 RSS" 换成实测的联合口径（× 0.85–0.895 → 3.78–3.98）。

读法 两次下调都不是精度改善——一次删掉重复的项，一次换掉一个被实测证明高估尾部的合成规则。 真实误差一分未变。但拿它当基线算收益时必须用新值，否则会把已经记过的账再赚一遍。

还有一个数没变：实测上界 A = 7.43 mm（逐相机弥散，p99 10.62，>20 mm 粗差 0.07%）。 它和 A′ 量的不是同一件事——A 问"换一台相机信，答案会变多少"， 系统性高估标签对单台相机的敏感度。所以下面这把尺子只画 A′，A 单独讨论。

「ArUco 有现成的自标定管线」这句话要打折 08-18 两份 rig layout 都报 success: false，重投影 RMSE ≈ 5.0 px， 拒掉 18–21% 的观测。生产夹爪 cube 那一版更甚：拒掉 2740/3400（80%）， 解出的角点刚性 RMS 逐 marker 是 38 / 61 / 84 / 139 / 343 mm （rig 是 0.75–1.5 mm，只有 17 号板 6.12 mm——那是一个真实的装配问题）。 一个 layout 根本量不出来的靶标，没有"现成的 BA"可以指望。
这些数不是什么 理想针孔、精确内参、无畸变、单相机、高斯模糊 2.5 LSB 噪声。 绝对毫米不是生产误差——生产还带着鱼眼标定误差、真实光照和真实运动。 同一批姿态上两行之间的比值才是结论，单独一行的绝对值不是。

F饼的三条裂缝

按会不会把收益吃光排序。

致命 · 会由正转负

FDM 是净亏，不是打折

build_hybrid_carrier_model 只吃 STEP，没有 --scale、也没有几何 BA。 现役 rig 恰恰相反——走 --cad-prior-mm 软先验 BA，打印误差会被吸收掉。 换过去等于主动放弃一个现有的补偿机制。SLA + 卡尺量 200 mm 基准（→250 ppm）是入场券，不是优化项。

中 · 吃掉相机行的收益

手部遮挡没建模

H2 那个"相机数 p50 6"只算了 carrier 挡自己（181 个 occluder 三角形）。 现役 cube 的 +Y 面几何上该看得见却只解出 25%，说明真实丢帧主因就是手。 相机行那 0.3 mm 的收益可能被它整个吃掉。

低 · 但会静默出错

anchor id 仍要手给

STEP 里没有记 marker id 的地方，三个 --anchor-id 只能写在命令行。 给错不报错，会解出一个看起来合理的错位姿。 （--pad-size-mm 62 给错反而是响的：默认 60 会找到 0 个 pad 并报错。）

G真正值钱的不在这张表上

A 口径把 marker→TCP 结构性移除了，所以它看不见 carrier 最大的那笔收益。

今天生产夹爪口径（B）给不出任何数，卡在两件事上。carrier 直接拆掉其中一件：

B 口径的第一个堵点 · carrier 拆掉它 cube 晃动是时变量，不进 RSS，它直接破坏刚体假设本身，而且本页所有既有检查对它免疫—— 多相机一致性看不见（晃动是共模量），重投影残差也看不见（单相机 cube pose 中位只用 1–2 个 marker，近乎退化）。 一体打印件 + 每视图 31 条棱，同时解决"会晃"和"看不见它晃"。

第二个堵点是 marker→TCP 常量（rotation_sigma_deg = 2.0° 是一个声明不是测量， 按现役杠杆臂折算即 9.1 mm），要靠 FR3 hand-eye 解决，跟换不换 rig 无关。

在 A 口径上抠 0.5–1 mm，远不如让 B 口径第一次有数。 B 才是真正会进训练集的那条路径。

H还剩哪一处判断

上一版这里写的是"该做但没做的那次仿真"。它做了，见 E 节；剩下的是这些。

D 表里原本 solver 和 timing 两行都是纯判断，合计占预估收益一半以上。 solver 已经换成比值（同口径 A/B，p90 0.50），timing 仍然一个直接证据都没有—— "大面高对比棱在运动模糊下退化慢于 6×6 模块解码"是个合理的机理，但本页没有任何数支持它， 而它独占 p95 方差的 20.2%。补法同样是那套 harness：给渲染加运动模糊，扫模糊长度。

已经补上的前置条件 现役 rig 的 marker_layout.json 本仓库里没有（生产 marker_layout_path 至今为空），已从 Thor 的 outputs/metrology/newrig_20260818/ 取回； harness 本身以 metrology.cli.compare_fiducial_targets 进了仓库，附 9 个单元测试。
仍然成立的前提 没有独立 GT，本页每个数字只能证伪不能验收。共模误差——全场尺度、world 系整体偏置、 多台相机共享的模型误差——对这里的所有数都不可见。换了 rig 也一样。 E 节那把尺子还额外受限于它自己的理想相机模型。
