FR3 训推 GUI 路线图

2026-11-10 · 目标：工程基础弱的学生只靠 GUI 按钮，就能完成「Thor 手持采集 → 导出 → 训练 → 右臂推理」，每一步都由系统把关，不靠自觉。

0 · 已完成（P0，未提交、未部署）

  • 导出：--target-world auto 现在一律保留录制时的相机世界系，不再随 world_graph 当天的状态切到 fr3_base。日志会逐臂列出能不能部署（Deployable on the right arm … / Not deployable on the left arm … until it is registered）。
  • 推理：必须指定 --arm，没有默认臂，原来写死的 192.168.1.208 已删掉。IP、夹爪 BOX（防止误驱动手持 BOX）、URDF 和 IK 目标点都从 fr3_arms.json 和这台臂的回放配置里取。新增 world_graph 对齐模式，相机世界数据集默认用它：启动时取「相机世界 → 该臂基座」的边并打印；边已退役或被守卫停用时拒绝启动。start_pose 只有显式指定才会用。用已退役的边换进基座的旧数据集会被拒绝。
  • 真机执行上锁：不带 --preview 的推理一律拒绝（[REFUSED]，退出码 2，在加载策略之前就检查）。维护者在场时，在推理机器上写 outputs/fr3_infer_real_unlock.json（字段 arm / by / reason / created_utc / expires_utc，最长 12 小时，只对写明的那台臂有效），用完删掉。outputs/ 不随部署同步，也不进 git。另外 --preview 下不再执行 robot_init_state 的移动（之前 preview 下也会动）。L3 做好后，由放行记录取代这个文件。
  • 用户指南 §8、§9 已按新约定改写。

1 · 剩下的缺口

环节现状对学生的后果
导出 → 训练视图GUI 的「训练视图」只认工作站 FR3 录制（gateway._training_view_command，--state-keys observation.state）。Thor 导出的 observation.state 是 BOX 传感器向量，手的位姿在 observation.ee_pose.<hand>.base。Thor 数据进不了训练，或者用错列训练却不报错。
训练只有 --prepare-only，训练要另外手动跑 fr3_train_il_policy.py。学生得自己拼命令、选 GPU、找 checkpoint。
推理入口只有命令行。run_pick_place_infer*.sh 写死了别人的路径、pika 夹爪和海康相机。没有安全的启动方式。
推理相机runtime 支持 gmsl2，但没有和录制器、预览共用 Argus 的调度（单 slot，Connect 前必须先停预览）。相机起不来，或者把录制会话挤掉。
放行没有离线 / 仿真 / 预览各级结果的记录，也没有门禁。可以跳过检查直接上真机。

2 · 分期

T1 · Thor 数据契约 + 训练视图（中）

  • 每台臂对应一只手：state = 该手 observation.ee_pose.<hand>.base（相机世界系，TCP = 球窝）+ 夹爪开度；action = 绝对位姿或按帧差分（沿用现有 action_mode）；图像 = 选定的固定相机。
  • 视图 meta 记录：手、世界 id、tcp link、标签链指纹。推理端校验与 --arm 和 IK 目标是否一致，不一致就拒绝。
  • GUI 在 Thor 导出旁加「建训练视图」，只列出能部署的臂。

T2 · GUI 训练任务（中）

  • 预设（ACT，步数、batch 按显存给档位），后台跑，日志和 loss 曲线在页面上看，checkpoint 自动登记。登记内容：来自哪个视图、哪个世界、哪套标签链。
  • 同一时刻只允许一个训练任务，不能和录制、推理抢 GPU 和相机。

T3 · 推理四级放行（大）

每一级的结果都和 (checkpoint, 臂, 注册边 id, 标签链) 绑在一起。前一级没通过，或者这四样里任何一样变了，下一级的按钮就是灰的。参数（臂、相机、夹爪、限幅）全部从注册表和已验证的配置里取，学生不能手填。

  1. L0离线开环：在留出的 episode 上跑策略，比较预测动作和标签（位置 / 姿态 / 夹爪误差的 p95），同时核对解码一致性（扩展 fr3_compare_infer_replay_decode）。
  2. L1MuJoCo：把 L0 的预测动作经注册边换到该臂基座，走现有 IK QC + MuJoCo 预演，检查可达性、关节限位和自碰撞。
  3. L2真机只看不动：--preview，接上真机和相机但不发动作。核对起始对齐统计、第一帧偏差、负载（fr3_arms.payload_check），以及日志里打印的边。
  4. L3真机限幅执行：复用回放页的「Move to start → Execute」两步确认，但起点按下面「起点怎么定」来选（回放页现有按钮走的是当前选中 episode 的第一帧，推理不能直接拿来用）。必须勾选「有人守急停」。单步限幅、限步数、限工作空间。

起点怎么定（L2 / L3 共用，不靠人判断）

world_graph 部署时，臂会去示教时手在房间里的实际位置，所以起点必须由系统给出，并由系统判断到没到位。

  • 不用平均起点。运行时现在算的是位置算术平均加四元数平均（estimate_dataset_start_pose_contract）。起点分成几簇时，平均值会落在簇之间，没有一条示教是从那里开始的；姿态分散时四元数平均也会偏。
  • 不按分布随机生成。位置和姿态各自抽样，可能凑出示教里没出现过的组合，也可能超出臂的可达范围。
  • 首次运行 / 排错：medoid 起点。取一条真实 episode 的起点，它到其他所有起点的距离之和最小（位置和姿态合成一个距离，按 1° 折算若干 mm）。这个起点一定在分布里、每次相同、好复现，还能直接用这条 episode 已经算好的 IK QC 关节解和 MuJoCo 预演来移过去。
  • 评估成功率：从留出的 episode 里抽 K 条，用它们的真实起点。每个起点都是人手到过、臂可达、过了 QC 的。抽中哪几条、每次结果如何，都和 checkpoint 一起登记。
  • 到位门槛。移完以后，自动比较实际位姿和目标起点：位置和姿态偏差都不能超过数据集起点自身的离散范围（取离 medoid 的 p95），另设绝对上限；夹爪开度也一起对齐（沿用 align_gripper_to_dataset_start）。不达标时「Execute」不可点。运行时已经会打印 nearest / median / p95 这几个起点偏差，把它变成门禁即可。
  • 场景复位。策略看的是图像，物体摆在哪里和臂的起点一样影响结果。GUI 并排显示被选中 episode 第一帧的相机画面，学生照着摆放物体。这一步只能人来做，但对照参考画面比凭感觉摆可控得多。

T4 · 文档与练习（小）

  • 指南 §8 按 T1–T3 重写。给一个「从采集到 L3」的标准练习任务，附通过标准（包括起点门槛和场景复位怎么做）。

3 · 需要你拍板

  1. 在哪里训练：Thor 本机（和采集抢 GPU、磁盘）、工作站，还是集群？这决定 T2 是本地任务还是远程提交。
  2. 策略输入哪几台相机：默认用标定状态 ok 的固定相机全部，还是挑 2–3 台？台数会影响 Thor 推理时的带宽和延迟。
  3. 右臂边的精度够不够：现在这条边典型约 3 mm、最大约 5 mm（软垫有竖直偏差）。用 world_graph 绝对部署时，这个误差会直接变成抓取点的偏差。要不要先换刚性球座重测，再开放 L3？
  4. 先做的顺序：建议 T1 → T3 的 L0/L2 → T2 → L1/L3。先能在离线和预览里看到问题，再开放真机执行。
