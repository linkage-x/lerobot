结论先行

  • 现在能回放的只有一只手。整条链（world → fr3_base 注册边、socket TCP、两步真机 replay、激光误差分析）只在 right cube → 一台 FR3（192.168.11.102）上跑通过。双臂相关的代码、标定、数据契约都还没开始，不是「差一点」。
  • 夹爪不在，正好做与夹爪无关的那一半。沿用主 roadmap 的判据：「夹爪明天回来，这项会不会白做？」不会白做的现在做：双手数据的 QC 与 benchmark 选集、按臂分开的 base 坐标系、双臂仿真与联合 retarget、双臂执行 runtime、第二台 FR3 上线、用激光测两台 base 之间的关系、FR3 本体执行误差（Phase 11）。会白做的等夹爪：socket 常量、左手 marker→TCP、夹爪回放、接触任务。
  • 无夹爪下测的执行误差不能直接搬到有夹爪的构型。负载和 TCP 力臂都变了。所以 FR3 本体计量要挂一块和夹爪等质量、等质心的配重；即便如此，结论也只标「配重构型」，夹爪回来后复测一次再定。
  • 10-23 第一批开工后，四个前提要改：
    1. 已有数据里没有双手。A1 在 Thor 上全部 37 个 v2/v3 session 里跑了一遍：左手 cube（marker 0–4）在任何相机、任何一帧都没被检测到（10-03 起每段 left sidecar 都是 0 帧解出）。唯一有左手的是 6 月的 dadada 两段 v1 数据，测量链不同，不能用。所以 A2 选集、B0 摆放、C3 retarget 都没有双手轨迹可用。A4（手持 cube 录无夹爪的双手轨迹）从「可选」变成前置。10-26：Q3 已答，手持 cube 也送修了，A4 要等 cube 回来。在那之前用 A5 的替代轨迹开发 C / D 线，但 A2 选集和 B0 摆放的最终结论仍要等 A4。
    2. C0 不拆数据集的坐标系。一个数据集只放在一个系里（仍是 fr3_base = right 的 base），两只手一起导出，T_LR 还是同一个文件里两列的乘积。左臂需要的 fr3_base → fr3_base_left 由回放时按本体描述（G1）在图上查，用到的边写进回放报告。export_v3 一行不改，旧导出天然逐字节不变。
    3. B3 只能到约 3 mm，不是 1 mm 级。G3 的合成实验显示：臂-臂同球和激光站位两种方法打平（共享工作区内 T_LR 的 p95 约 3.0 mm），瓶颈是每台 FR3 自身的运动学误差（FK 对激光 0.47 mm）。球位数量和 pivot 落座噪声影响都很小。经两条 world 边绕过去约 4.8 mm，所以 relative 模式仍然更好。要再往下，得做单臂运动学标定，多摆几个球没用。
    4. 闭环检查只能抓粗差。按现在 world 边的水平（留一 2.6 mm），闭环阈值约 15 mm，1% 误报下，10 mm 的错边只能抓到约 1/4。它能发现「base 被碰了」「错用了手眼边」这类错误，但证明不了一条边到毫米级。G2 原来写的退出条件「注入 5 mm 能抓到」在这个精度下做不到，已改。
  • 已定（10-23）：第二台 FR3 放在现有这台的左边（新的 = left，192.168.11.102 = right）；两台 base 重新定位后不再挪。人形是轮式的，可以移动，见 H 线。如果现有这台也要挪，它现役的球位边（ball_check_20261015T030840Z）随之作废，已导出到 fr3_base 的数据都要用新边重导（标签链防混用会拦住新旧混用）。

注册：单 FR3 → 双 FR3 → 人形

先更正一个前提：单 FR3 现役的注册边已经不是手眼标定了。10-09 的单 tag 手眼边（p0_two_marker_calibration.py，相机看臂上 tag-6）在 10-14 同球检验里差 10.7–13.3 mm（主要是约 10.7 mm 的竖直平移），单 tag 法两次重解之间自己就差约 4 mm。10-15 起生产用的是 5 球位刚体边（ball_check_20261015T030840Z，留一 rms 2.63 mm）。激光边（站位 × FK）受站位精度所限，只能证到 5–6 mm。

所有注册方法其实是同一件事

同一组物理点（或位姿）在两个坐标系里各量一次，拟合一个刚体变换。区别只在谁当公共观测物、误差经过哪些环节。

双 FR3：先管两臂之间，再管到 world

  • 不要两台各自做手眼。两条边各自带的相机侧误差（相机状态、cube 可见性、旋转 × 力臂）两边不相关，会直接叠进两手间距 T_LR；10-09 那条边单条就差 10 mm。
  • 拓扑：world ─ fr3_base_right ─ fr3_base_left，再加一条 world ─ fr3_base_left 构成闭环。
    • T_BL_BR（两臂之间）：首选臂-臂同球——两臂法兰装同款杯，绕桌上同一组 ≥ 4 个球位（含换高度、留一个点做留出）各做 pivot，球心分别落在两个 base 里，拟合刚体变换。备选是同一激光站位下两臂各做站位 × FK。两种方法独立，互为检验。
    • world → 一台 base：right 沿用球位刚体边；left 现在先上激光边，夹爪回来后用同球检验替换。
    • 闭环残差：inv(T_W_BL)·T_W_BR 和 T_BL_BR 的差，就是三条边误差的直接证据，不用另找 GT。
  • 球位要摆在两臂共享的工作区，并且要有高度差。T_BL_BR 的旋转误差 × 到工作区的距离会变成 T_LR 误差；10-14 只补到第 ④ 个换高度的球位，竖直方向才约束住。
  • 软件现状：world_transform 已经是在 world_graph 上做 BFS，多一个 base 节点不需要改结构；缺的是每条边的 σ、方法来源，以及「多条路径时做闭环检查，而不是取第一条」。

由此得出的设计原则（现在就该定）

  1. 标签留在相机 world，按本体导出时再转。不让 fr3_base 成为数据集里唯一的那份坐标。export_v3 --target-world 已经是这个思路，要推广到「按本体、按臂」。
  2. 相对量优先。T_LR、短时 RPE 这些不依赖根注册，换本体也成立；绝对量只在同一 world 且有注册边时使用。
  3. 本体描述抽象成一份文件（见 G1）：运动学树 + 命名 TCP + 根坐标系 + 每个根如何注册进 world（静态边 / session 边 / 逐帧跟踪）+ 碰撞模型 + 控制接口。双 FR3 是「两个固定根、外部边相连」，人形是「一个浮动根、内部链相连」，retarget / 仿真 / runtime / QC 都只读这份描述。

H 线 · 轮式人形（10-23 确认可移动；硬件到之前只做设计）

和双 FR3 相比，难点从「两台 base 之间」挪到了「底盘在 world 里在哪」：两手之间靠自身运动链，而底盘每停一次都要重新注册。建议先只做停靠操作（开到位、停稳、再操作），边走边操作放到后面。

口径红线

  • 两手不能各自做 first-frame 对齐。只允许一个共享 T_align，否则两手间距被悄悄改掉，T_LR 的指标就失去意义。
  • 配重构型的执行误差不等于有夹爪的执行误差。报告里写明构型；夹爪回来复测前不进 3 mm 预算。
  • 激光认证不了同步的双臂动态 T_LR（一次只锁一个靶）。能认证的是静态 T_BL_BR 和每只手各自的执行误差；动态 T_LR 只能用 FK 读回 + D2 的时钟对齐来估，标「估计」。
  • left 的任何绝对误差都带「标签链未验证」，直到 F4 完成。不要拿 left 的数去归因执行或注册。
  • absolute 回放必须有注册边连通，由 metadata 自动判定，不靠操作者记得；没有边只能做 relative。
  • retarget 不改原始 demo 标签。demo_raw / retarget_reference / executed 三套分开存，可执行性只作为 metadata。
  • 合成实验只认证方法和敏感度，不认证精度。用当前模型生成的数据评不出模型自身的错。
  • FK 不能自证。T_BL_BR、执行误差都要激光；FK vs FK 的一致只是内部一致性。
  • Connect / Execute 由操作者按，两臂都动时工作半径内不能有人。
