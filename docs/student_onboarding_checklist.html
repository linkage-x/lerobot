学生上手清单

2026-11-11 · 从拿到账号到第一个 PR 被审，大约半天。按顺序做，每一步做完再往下。规则以 AGENTS.md 为准，本页只讲怎么上手；后续计划见 docs/student_dev_workflow_roadmap.html。

0 · 先记住三件事

  1. 生产永远不碰。Thor 上 /home/nvidia/lerobot（端口 8765）是大家录数据用的。不往里部署，不改里面的文件，不重启它的网关，不传 --maintainer。你只用自己的沙箱。
  2. 机器人不由你（或你的 AI）启动。真机回放、pivot、负载辨识、move-to-start、双臂回零、真机推理：必须有人守急停，由维护者操作。不创建 outputs/fr3_infer_real_unlock.json。
  3. 门禁挡住你时，报告原因，不要"修"门禁。MuJoCo / IK QC、world graph 红条、cart check、label provenance、部署守卫、沙箱硬件守卫都一样。标定和 world 文件不经维护者不改。

1 · 维护者先开通（每位同学一次）

第一次给任何同学 write 之前（一次性）：GitHub 没有"只能写自己分支"的权限，write 能推所有没有保护的分支，还能在自己分支上改 workflow，读到仓库 secrets（仓库是公开的，Actions 日志也公开）。所以先：
  • main 和其他长期分支加保护（必须 PR、禁止 force push 和删除）；
  • 没在用的仓库 secret 删掉；CI 用的子模块 deploy key 移进只允许 box 使用的 environment，学生分支上的 workflow 读不到。

同学把 GitHub 用户名和 ssh 公钥（~/.ssh/id_ed25519.pub）发给维护者。维护者逐项开通：

  • 维护者linkage-x/lerobot 设为 write。read 只能从 fork 提 PR，而 fork 的 PR 在 CI 里拿不到子模块密钥，测试必挂、永远合不进去。
    gh api -X PUT repos/linkage-x/lerobot/collaborators/<login> -f permission=push
  • 维护者两个私有子模块 linkage-x/opencv_kalibr、linkage-x/box-sdk 至少 read，否则 git submodule update 失败。
  • 维护者公钥追加到 Thor nvidia@192.168.111.122:~/.ssh/authorized_keys，注释里写上名字，方便以后移除。
  • 维护者确认同学电脑在实验室网络里，能连到 Thor 的 22 端口和 8770–8799（沙箱网关端口）。
  • 维护者拉进开发群，告诉同学：找维护者走哪个渠道，生产多久发一次版。
现在大家共用 nvidia 账号：能 ssh 上 Thor 的人，技术上能覆盖生产，守卫只防误操作。独立账号和硬件隔离（路线图 P2-1 / P2-2）做完之前，只给小范围、当面讲过第 0 节的同学开通。

2 · 本地环境

需要：Linux 或 macOS，git，uv，Node.js 22（含 npm），以及你用的 AI 编码工具（Codex / Claude Code / Cursor…）。

  • GitHub 账号已配 ssh key：ssh -T git@github.com 显示你的用户名。
  • 克隆仓库，从 box 开自己的分支，拉子模块：
git clone git@github.com:linkage-x/lerobot.git
cd lerobot
git fetch origin
git switch -c <名字>/onboarding origin/box
git submodule update --init --recursive
  • Python 测试环境（与 CI 相同的依赖，够跑网关 / Thor / FR3 的测试；训练、推理另装）：
uv venv -p 3.12 .venv
uv pip install -p .venv/bin/python pytest pyyaml numpy scipy pyarrow av opencv-python-headless
PYTHONPATH=src .venv/bin/python -m pytest -q --noconftest tests/scripts/test_data_collection_gui_gateway.py

--noconftest：上游 LeRobot 的 conftest 会导入 torch，这些测试用不到。

  • 前端：
cd tools/data_collection_gui/frontend
npm ci
npx tsc --noEmit && npm test
cd -
  • 能登上 Thor：ssh nvidia@192.168.111.122 hostname。只用来部署沙箱，不在上面手工改东西。
  • 让你的 AI 工具在仓库根目录打开，并确认它读到了规则：问它"在沙箱里能不能调用真机回放？""能不能部署到生产？"，它应该引用 AGENTS.md 回答"不能"。答不上来就先让它读 AGENTS.md（Claude Code 通过 CLAUDE.md 自动加载，Codex 直接读 AGENTS.md）。

3 · 第一次进沙箱

沙箱名用自己的名字（小写字母开头，2–24 位小写字母、数字、-、_，如 zhangsan）。以后一直用这个名字，端口会固定下来。

bash run/deploy.sh thor --sandbox <名字>
  • 输出里有 gateway started (… port 87xx, sandbox <名字>)，然后本地前端启动在 http://localhost:5173/（被占用时 vite 换下一个端口，看输出）。第一次部署会从生产复制一份标定，要等一会儿。
  • 浏览器打开 GUI，顶部有黄条 沙箱 <名字> 和你的 commit。没有黄条就说明连的不是你的沙箱，立刻停下来问。
  • 复制一个小数据集进来（Thor 的磁盘也存着所有录制）：
bash run/sandbox.sh thor datasets              # 生产里可复制的数据集和大小，可加过滤词
bash run/sandbox.sh thor copy-dataset <名字> <数据集>
bash run/sandbox.sh thor status <名字>         # 端口、版本、数据集、占用空间
  • 在 GUI 里对这个数据集走一遍离线流程：轨迹生成 → IK QC → MuJoCo 预演 → 回放查看。卡住时看日志：bash run/sandbox.sh thor logs <名字>。
  • 亲眼确认硬件被拒：点一个需要相机 / BOX / 机械臂的按钮（如相机预览、BOX 连接），GUI 报错，内容是 sandbox '<名字>' does not touch hardware: …（HTTP 409）。这是预期行为，不要改它。
  • 本地前端用 Ctrl-C 关掉即可；沙箱网关在 Thor 上继续跑，不用时 bash run/sandbox.sh thor stop <名字>。

4 · 标准练习任务（走一遍完整的 PR 流程）

目的是熟悉流程，不是写功能。练习 PR 以草稿提交，维护者看过就关掉，不合并。

  1. 在 <名字>/onboarding 分支上，让 AI 帮你在 GUI 里做一个肉眼能看到的小改动：比如沙箱黄条（tools/data_collection_gui/frontend/src/App.tsx 里"沙箱"那一行）后面加上 · 练习。要求它只改这一处，不格式化别的代码。
  2. 本地跑 npx tsc --noEmit && npm test（在前端目录），通过后提交。commit message 写"为什么"，例如 chore(gui): onboarding exercise, mark my sandbox banner。
  3. 重新部署沙箱：bash run/deploy.sh thor --sandbox <名字>，在 GUI 里看到改动，黄条里的 commit 变成新的。
  4. 推分支、开草稿 PR，目标分支选 box： 
    git push -u origin <名字>/onboarding
gh pr create --draft --base box --title "练习：<名字> 上手" --body "上手练习，不合并"
  5. 等 CI 两项（Gateway / Thor / FR3 tests、GUI frontend）变绿。PR 页面会显示需要维护者审核：run/、tools/fr3/、world/标定、gateway.py 等路径归 CODEOWNERS，改到这些地方一定会落到维护者手里。
  6. 把下面三样发给维护者，维护者看过后关闭 PR：PR 链接；bash run/sandbox.sh thor status <名字> 的输出；MuJoCo 预演通过的截图。
做完这一节就算上手完成。之后的真实任务照同样的流程：git switch -c <名字>/<主题> origin/box → 本地测试 → 沙箱试跑 → PR 到 box → 维护者审核、合并、发版。一个 PR 只做一件事。

5 · 常见报错

现象原因怎么办
git submodule update 报 Repository not found没有子模块仓库的读权限找维护者开 opencv_kalibr / box-sdk 的 read（第 1 节）
git push 报 403主仓库只有 read找维护者改成 write；不要改成从 fork 提 PR（CI 会因子模块失败）
部署拒绝：树不干净 / 不在 origin/box你在部署生产（漏了 --sandbox）加上 --sandbox <名字>。不要提交、不要传 --maintainer 来"让它过"
沙箱名报错名字不合规或是保留名用小写的自己的名字
no free sandbox port in 8770-879930 个端口用完bash run/sandbox.sh thor list 看谁的沙箱不用了，在群里说；只删自己的
GUI 一直报莫名其妙的错 / 接口 404前端和网关版本不一致重新 deploy.sh thor --sandbox <名字>，让两边是同一个 commit；看 /api/snapshot 里的 deployment.release
某个按钮返回 409 does not touch hardware沙箱没有硬件，预期行为离线部分在沙箱做完，需要硬件的部分找维护者试
CI 里你没碰过的测试挂了可能是 box 本身或环境问题不要删测试、不要跳过，贴链接问维护者
复制数据集提示空间不足Thor 至少留 30 GB 给录制删掉自己不用的副本，挑小一点的数据集

6 · 日常习惯

  • 每次开新任务都从最新的 origin/box 开分支；长期分支定期 git rebase origin/box（只 rebase 自己的分支）。
  • 测试只跑你改到的文件对应的测试（AGENTS.md 第 5 节），lint 用 uvx ruff@0.14.1 check <文件>；不要整文件格式化。
  • mock 里的 pid 一定用真实整数，不要用裸 MagicMock：os.killpg(MagicMock()) 会变成 kill(-1)，整个桌面会被注销。
  • 沙箱里的数据集用完就删，长时间不用的沙箱 bash run/sandbox.sh thor remove <名字> --yes。
  • 拿不准是否安全时先问。问一句很便宜，机械臂走错一步、丢一个数据集都很贵。
