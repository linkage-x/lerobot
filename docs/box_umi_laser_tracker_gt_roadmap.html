结论先行

7 条
  • 仪器本身不是瓶颈。激光跟踪仪自身误差以本机证书为准，通常在几十微米量级。GT 链那 1 mm 会花在四处：SMR 球心 ↔ TCP、跟踪仪系 ↔ 相机 world 的注册、时间对齐、失锁。本页的工作量也集中在这四处。
  • 「原始数据只能在 Windows 拿」这个前提不成立，Trigger 口也不再是未知数。随机 SDK（v7.18.0.0）官方支持 Windows / Linux / Mac，README 给了 .deb 安装路径并注明 ARM 架构不依赖 Qt6 —— 拿到 Linux 包，logger 可以跑在 Ubuntu 工作站甚至 Thor 上，少一跳主机钟。但这条的权重取决于触发线：TTL 接得上时对齐走脉冲索引、全程不涉及主机钟，跑在哪台机器就只剩运维差别；接不上时主机钟才重新变成唯一手段。Trigger 口是 TTL 输入，Radian 上限 1000 Hz（相机 60 Hz 只占 6%），StartTTLMeasurement 每个脉冲回一条带控制器时间戳的点。对齐方式随之从「求 Δt」升级成脉冲索引对应。见 SDK 与随机资料。
  • 先拿与时间无关的静态数字。注册（T5）和静态精度图（E1）都只用静止位姿，不依赖时钟链。T0–T2 加 T4/T5 走完，就能给出「独立 GT benchmark」行的第一个数。时钟链同时并行打通。
  • 先 FR3 搭载，后手持。FR3 只当运动源、不读 FK：可控、可重复、没有人手挡光。手持受 SMR 接收角和遮挡限制，GT 覆盖率本身就是交付项。
  • STS 在库（序列号 6395，PRM 在档），姿态精度 ±0.010°。放在 259.5 mm 力臂上是 0.045 mm，对比现在那个从未实测的 2.0° 声明（9.1 mm）是 200 倍。代价有三条且都要单独处理：1.36 kg 挂在夹爪上（载荷变形，预算里还没有这一行）、装的位置不能挡住 cube、与 TTL 硬触发互斥。一次只锁一个靶这条不变：双手静态 TLR 可认证，同步双臂动态不覆盖。
  • 首个受检构型定为现有夹爪（cube 构型），它要一个专门的连接件，规格是「≥ 3 个非共线窝」不是「一个球座」。现有夹爪没有球接口（Hybrid Carrier 的球窝也配不上任何常见 SMR 口径，那条路顺延）；单光束跟踪仪一次只跟一颗球，一个窝只给一个点，姿态要靠 ≥ 3 个非共线窝组成工装位姿、再用 AX = XB 解。这条路直接打误差预算最大的那一行——旋转那 2° 声明在 259.5 mm 力臂上是 9.1 mm。STS 到位后这条路降为并行对照：STS 直接量姿态，不必等机加；但两条路各自的系统项不共享，同一场次两条都做、取差值，是这个数字最便宜的独立验证。见 T4 详述 与 首个受检构型。
  • 厂家的 SA / RMS 流程只作对照，不进 GT 链。它们的输出经过 best-fit；RMS 坐标系对齐「一般小于 2 mm」的门限，比整条 GT 链预算还宽一倍。

T3

时钟链

跟踪仪ThorA 路径已确认可行电气规格待核

给每个跟踪仪样本一个 Thor 时间，而且这个时间不能从相机标签反推出来。SDK 到手后这条路变了性质：TTL 模式下第 N 条回调就是第 N 个脉冲，所以目标从「把两个钟对齐到 0.7 ms」变成「证明脉冲一个没漏，并标定触发到测量的那一个常数延迟」。前者是统计估计，后者是计数与一次性标定——后者可靠得多。

  • T3a Trigger 台架：已知输入 / TTL / ≤ 1000 Hz / BNC 母头（背板照片可辨）；文档里查不到的是电平门限、边沿极性与最小脉宽、端接阻抗与是否隔离、触发→测量延迟——全部资料查遍都没有，只能问 API 或台架实测。用信号发生器扫电平与边沿，灌已知频率验证回调条数 == 脉冲数（漏脉冲判据），并专门跑过触发计数器回绕点（v7.18 刚修过「Trigger Counter 归零时丢数据」）。同时验证 TTL 与 1 kHz 实时流能否并开。
  • T3b 接 Thor PWM：从 pwmchip6 输出经缓冲隔离分一路到 Trigger 口（BNC 同轴），不能拖累现有 SG16A 触发。缓冲级按可切 3.3 V / 5 V 输出设计：Thor 是 3.3 V 逻辑，标准 TTL 门限（2.0 V）下够，5 V CMOS 门限（3.5 V）下不够，而规格未知。端接阻抗未知也在这里体现风险——若 Trigger 口是 50 Ω 端接，分路会拉低 SG16A 那一路的电平。接线后必须重跑相机硬同步验收（SOF spread）。
  • T3c 标定常量：触发延迟（示波器或同步闪光）；相机曝光窗相对 PWM 沿的位置，用 PWM 驱动 LED 扫延迟，独立于跟踪仪也独立于标签。录制器补记逐帧曝光时间：现为 Argus 自动曝光，元数据里没有曝光列。
  • T3d 交叉检验：time_offset.py 补 |v| 通道和子窗回归求 s（P1-采购行已点名的小缺口），只用来核对 A，或在 A 不可用时认证空间精度。
  • T3e 粗对齐：采集机 ↔ Thor 主机钟同步，只用于会话关联与下面的 T3f，同步状态写进 manifest。
  • T3f index 0 锚点（索引对齐唯一的整数歧义）：脉冲索引对应只给「跟踪仪第 N 条 ↔ 相机第 N 帧」，前提是两边从同一个脉冲开始数。PWM 是自由运行的，TTL 采集与相机录制不会同时起，所以必须先定 index 0。两种办法：① 会话开始时把 PWM 停一拍制造一个已知缺口，两边都看得见，是共同基准；② 用粗主机钟直接认——脉冲间隔 16.667 ms，只要主机钟对到 ±8 ms 以内就能唯一确定是哪一个脉冲，之后由索引接管精度。这是典型的粗捕获 + 精跟踪：主机钟的精度要求从 0.7 ms 放宽了一个数量级，NTP 随便满足，PTP 完全不必要。锚点判定结果与所用方法写进 manifest。
GATE首选按脉冲计数结案：一段 ≥ 10 min 的采集里，TTL 回调条数 == PWM 脉冲数 == 相机帧数，三者逐段可核；device_time 相邻差的直方图只有 16.667 ms 一个峰。加上触发延迟与「SOF → 曝光中点」偏置两个实测常数，时间行就只剩这两个常数的不确定度。计数对不上时才退回原判据：Δt 残差 ≤ 0.7 ms、钟速比 s ≤ 30 ppm。

T4 详述 · 受检构型怎么接 SMR

连接件是必做项

问题的实际形态不是「要不要做转接件」，而是「做几个窝、装在哪」。三条已核实的事实把它定死了。

  • 没有任何现成接口能直接接 SMR。Hybrid Carrier 的球窝是 R 12.68 mm 球面、配 25 mm 钢球（单边间隙 0.18 mm）；常见 SMR 口径 1.5″ 38.1 mm、7⁄8″ 22.2 mm、0.5″ 12.7 mm，没有一个是 25 mm。SMR 还带孔径与反射腔，不是完整球面，不能当座球压在球窝里受力。所以 连 carrier 也要转接件。本机实际有哪几颗 SMR、直径、类型、接收角、重量，T0 清点后才算数（「到手先核对」第 3 项）。
  • 现有夹爪连球窝都没有。cube 到 TCP 是 247 mm 的一条链，cube 的 CAD 不知道 TCP 在哪。现行生产常量 marker_to_tcp_calibration_20260825.json 靠 pivot 采集拿到：平移是实测（holdout 残差 p95 2.70 mm，σ = [1.20, 5.25, 1.83] mm），旋转是从上一版 bundle 继承的、没测过（σ 声明 2°，bundle 自己的 open_items 写着「两指夹爪绕接近轴 180° roll 的对称性未被证据排除」「拆装重复性未采」）。
  • 一个窝只给一个点。单光束跟踪仪一次只跟一颗 SMR，输出位置三自由度。要拿姿态，只能逐个静态测 ≥ 3 个非共线窝再做 Procrustes——说明书 §3.4 的 SMR1–3 × P1–P5 正是这个做法。而姿态恰恰是现有夹爪欠的那一项。

回答「首个受检构型选现有夹爪，是不是得专门设计夹爪-球连接件」：是，而且规格比一个球座高——要「≥ 3 个非共线窝的刚性工装」。好处是它顺带把 marker → TCP 的旋转第一次独立测出来：今天没有别的手段能做这件事（pivot 是定点约束，一个点永远定不了旋转，bundle 自己也这么写）。

  • 装法先定，它决定你认证的是哪个 TCP。螺在机体上的支架认证的是 CAD 本体 TCP；指间带硬限位的插件认证的是 TCP_closed（把夹爪机构间隙一并算进去）。两者不是同一个量，而这等于替主 roadmap Phase 0「开度是否改变 TCP」先做了一半决定——先定口径再开图。
  • 单窝有一个跟踪仪看不见的盲区。只有一个窝时，球心偏距 d 上的姿态误差 × d 完全不进残差：按现行 bundle 声明的 2°，d 只要 8.6 mm 就吃掉「SMR 球心 ↔ TCP」整行 0.30 mm。这是 ≥ 3 窝的第二个理由（第一个是它根本测不了旋转）。
  • 球心出处。窝的球心位置由定位面在 CAD 里构造出来，不是从相机数据拟合、也不是从打印皮肤量出来的。装配完用跟踪仪自测三窝间距对 CAD，这同时是一次装配自检和尺度检查。
  • 可重复拆装。两个定位销 + 螺钉；拆装重复性实测 ≥ 10 次取放并进预算——现有 bundle 缺的正是这一项。
  • 工艺：CNC 铝，不要 FDM。Hybrid Carrier 那次的致命项是收缩不是粗糙度，同样的坑不要再踩。磁吸窝买标准件（跟自制球窝不是一回事：磁吸窝是三点运动学定位，自制球面窝的间隙会变成姿态相关项，rig 那边已经吃过这个亏）。自制只做安装板。
  • 朝向与接收角。SMR 接收角有限（本机型号待 T0 核），三个窝的朝向要覆盖跟踪仪站位方向；手持时腕部一转窝就背对跟踪仪，所以 GT 覆盖率本身是 E3 的交付项。
  • 遮挡。窝板不能遮 cube 的 marker 面，也不能挡相机到工件的视线。先在 CAD 里用 carrier 那套 occluders 的算法跑一遍可见性，别等到现场发现检出率掉了。
  • 防脱与重量。说明书 §1.9 专门要求开测前确认磁吸底座粘牢，靶球摔落是设备损坏（还是共享设备）。手持动态下磁吸保持力要对抗加速度：做机械防脱（挡圈或系绳），重量待 T0 清点后核手持动力学。
  • 开口相关的 TCP。A 方案把开口钉死在 45 mm 就等于该轮不覆盖抓取；B 方案不受开口影响，但它测的是 marker → 窝，TCP 还要经 contact_tcp(g) 折一次。

预算冲突，先看清楚再开工。GT 链给「SMR 球心 ↔ TCP」这一行只有 0.30 mm p95；而夹持式 insert 的既有验收门限是 holdout p95 ≤ 1 mm（才够谈亚毫米）、≤ 3 mm（够 3 mm 预算），现行 pivot 实测 holdout 是 2.70 mm。差一个数量级。

同一个位置还有第三个数：pivot 工具把「球窝中心到 TCP_closed 的偏距」的不确定度默认取 --delta-sigma-mm 5.0，也就是现行常量里这一项声明的就是 5 mm。

含义：A 方案在测出自己的拆装重复性之前不进 GT 链；B 方案的 0.30 mm 要靠 CAD 构造 + 定位销 + 装配自检去挣。挣不到就把这一行换成实测值重配预算——别处没有余量可挪（合计 0.78 对 1.0 mm）。

GATE首个受检构型的连接件：三窝间距的跟踪仪实测 vs CAD 偏差 p95 ≤ 0.10 mm，拆装重复性 p95 ≤ 0.10 mm，两者写进 T6「SMR 球心 ↔ TCP」行。达不到就改结构，或降级为「只报 SMR 点误差，不报 TCP」并在结论里写明。

解算：AX = XB，A 侧用跟踪仪，不是 FK

主 roadmap P0-Now ⑫ 已经把「旋转怎么测」定案为 hand-eye，解算侧也已落地——metrology/hand_eye.py + metrology/cli/hand_eye_calibration.py（48 单测，GUI 标定中心有面板），而且它只吃「位姿对」，与夹爪几何无关。跟踪仪路线不改解算器，只换 A 侧的来源：

  • Aij = 跟踪仪测出的工装相对运动（3 个窝 → 一个 SE(3)），不是 FR3 FK。
  • Bij = 相机测出的 cube 相对运动，与原方案相同。

三个后果，每一个都消掉原方案的一个依赖：① 不依赖 FR3 的 FK，本页红线「FK 只当运动源、不当真值」自动满足；② 注册 TWG 在相对运动的两侧同时出现、精确抵消，所以这件事不必等 T5；③ 采集时是完整的生产构型——夹爪在位、可以手持，不必像 FR3 hand-eye 那样把夹爪卸下来装到法兰上（原方案的采集侧正因为要等新夹爪–rig 方案而顺延至今）。

平移由同一次解的平移方程 (RA − I)·tX = RX·tB − tA 一并给出，于是 pivot 那条链的 holdout 2.70 mm 和 --delta-sigma-mm 5.0 都绕开了，旋转与平移一次采集全出。

必须显式重算的一条旧结论。主 roadmap 否决过「多点 Procrustes 测旋转」：标度律 σθ ≈ σΔp / B，代入 0812 实测的球心分散度 σΔp = 1.40 mm，要 0.22° 需要窝间距 B ≈ 517 mm（乐观）～1.5 m（现实），夹在 45 mm 开口里做不到。

那次否决的是「球心由相机测」这个变量，不是 Procrustes 本身。换成跟踪仪测球心，同一条标度律等比缩放：σΔp 从 1.40 mm 降到 0.10 mm 量级（T6 仪器行 0.10 + 落座 0.05 的工程门限），B 需求同比例降到 ≈ 37 mm（乐观口径）～ ≈ 107 mm（现实口径）。做一个 150–200 mm 的三窝三角形就有 1.5–5 倍余量。

反过来写更好用：窝间距做到 150 mm 时，跟踪仪侧的球心分散度只要 ≤ 0.14 mm（现实口径）就够——这正是 T1 要实测的量，所以 T1 的结果直接裁决这条路成不成立，不必先加工再发现做不到。（0.10 mm 目前是工程门限、未测。）

窝板装哪里：BOX 本体基准面

  • URDF 里 joint_link_marker_cube 与 joint_lt_gripper_base 的 parent 都是 link_box——marker 挂在 BOX 本体上，不在夹爪上。所以窝板装 BOX 本体的精密基准面（夹爪原本就依赖的那个面）。
  • 不装 cube 上：会把 cube 自己的晃动与装配间隙一起带走，而那正是待检项之一。不装指间：那是 A 方案，夹持重复性进预算且不能做抓取。
  • 待测量因此是 Rbox,rig；TCP 那一段走 URDF 的 link_box → joint_lt_gripper_base → link_lt_gripper_tcp 固定链——与 FR3 hand-eye 路线残留的 CAD 输入（Tflange,box）同级，不更差。
  • 残留的机加输入因此退化成一块平板的平面度与孔位角，机加 ≤ 0.05°–0.1° 是常规水平；对比现值 2.0°，是 20 倍以上的改善。

采集协议与顺序

  • 先 left，再 right。left 有 pivot 实测平移可作对照——两条独立方法测同一个量，这是对 GT 链自身的一次校验；校验过了，再去测 right 那个真未知量才有底气。两侧同场做完、跟踪仪站位不动，顺带给 E4 的 TLR 一组静态数据，也才能取上面那个 6.15 mm 的差值。
  • 姿态：≥ 50 个静止位姿，≥ 2 根不平行的转轴（纯平移的姿态对贡献为零，这是 AX=XB 的可观测性条件），全程 cube 在多相机视野内，每姿态静置 ≥ 2 s。
  • 每个姿态逐个测 3 个窝（单光束一次只跟一颗）。窝序与姿态号写进 manifest；build_motions 里 |A| 与 |B| 的转角一致性检查是免费的错配探测器，必须开——两路数据配错是「拿到一个自信的错答案」最可能的方式，而它在残差里看不见。
  • 拆装重复性 N ≥ 5 次同场做（主 roadmap ③ 已写死为协议的一部分）：rotation_sigma_deg 取这 N 次的实测分散度，不取 hand-eye 自身的拟合残差——那又是模型自评。这一项两侧 cube 至今都是 0 次。
GATERbox,rig 有实测出处，bundle 的 rotation_source 改写为「跟踪仪 hand-eye 采集 + 数据 ID」，rotation_sigma_deg 由 N ≥ 5 次拆装分散度填入（目标 ≤ 0.2°，即力臂上 ≤ 1 mm；≤ 0.5° 为可接受下限）；right 的平移从「拷贝」变成实测；6.15 mm 矛盾有结论。

口径红线

评审时逐条过
  1. GT 链自身预算合格之前，不下「3 mm 已认证 / 未认证」的结论，只报「GT 链未合格」。
  2. 注册、钟速比 s 与 Δt、SMR 球心位置 c，都在独立于评测集的数据上拟合。评测轨迹上不做任何 best-fit。
  3. 注册只用 SE(3)，尺度不吸收；Sim(3) 尺度只作诊断输出。
  4. 运动互相关的 Δt 只能认证空间精度，时间戳结论必须来自独立时钟链。
  5. Windows 侧只落盘。SA / RMS 里做过 best-fit 或坐标变换的数据不进 GT 链，除非变换本身随数据导出。
  6. 跟踪仪数据与 episode 按 ID 配对并校验时间重叠，不按目录或顺序。
  7. 平滑前、平滑后都报；按速度档、可见相机数分层；每 episode 报 GT 覆盖帧比例。
  8. FR3 只当运动源或定位器，FK 不当真值。FR3 搭载的结论不外推到手持；带载构型写明。
  9. 跟踪仪挪动就是新站位，旧注册作废；每 session 首尾测固定窝网络。
  10. 厂家流程的门限（例如 RMS 对齐「小于 2 mm」）是另一台机器人的验收口径，不能搬来当本项目门限。
