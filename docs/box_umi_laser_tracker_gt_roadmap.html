  • 2026-09-22：目标收窄为「认证 TCP 位置 3 mm」，姿态不再是必测量。TCP 位置 = Ri·cTCP + ti，TCP 的姿态不进式子，所以 bundle 的旋转只通过 cTCP（3 个数）起作用——表外 ① 那 3.5–9.1 mm 在位置口径下只是 cTCP 的一个误差来源，可以不测旋转、直接在 TCP 处测。办法是跟踪仪 pivot（新增 E1p）：SMR 留在钢片上不动，TCP 卡进相机 pivot 标定用的同一个球窝里转，钢片球心落在以球窝中心为心的球面上，跟踪仪单独定出球窝中心，再用冻结站位与生产标签逐位姿相减。cTCP 原样代入、不拟合，所以常量误差与静态姿态相关误差都直接可见。顺带：left 的 pivot 平移第一次有独立核对、right 的拷贝平移（最坏 13 mm）直接实测、6.15 mm URDF 矛盾同场裁决。T4b 三窝 / STS 从 3 mm 位置路径上移出，只在要认证 TCP 姿态时再做。新增一个必须单独收紧的量：球窝中心 → TCP 的定义偏距 d——两边都加它、在比较里抵消，跟踪仪看不见；要 CAD / 卡尺量到约 0.3 mm，而生产 pivot 工具给它的默认 σ 是 5 mm。推导见 TCP 位置认证原理，待办见 下一步。
  • 2026-09-21：驻点集这条路走通了，而且比预想的便宜。首批 15 个位姿是垫着摆、手离开采的——不需要夹具，不需要 FR3，不需要 15 个支架；实测驻点 span 中位 0.067 mm，平均点自身不确定度 0.83 µm，点云直径 0.90 m、planarity 0.140 均过几何门槛。三个拦路的全是代码缺陷，而且都伪装成「你的数据不行」：一个锁竞争造成的握手死锁（滞后恒等于超时预算）、一个把「一段 episode」当成「一个 mount」的概念混淆（让 848 mm 的张开被判成 rotation diversity 不足）、一个找错落地路径的发现逻辑。均已修、均未部署。唯一要改的操作习惯是每段停到 3.5–4 s（一个驻点需要 2.6 s，这次中位只有 2.89 s，4/15 不够长）。现行驻点门槛比它实际守护的误差严约 50 倍：已定放宽到 span ≤ 0.30 / drift ≤ 0.15（12/15 通过，σ_mean 上限 2.45 µm = 预算的 0.25%），并把 σ_mean 写成产物里的具名项。旧门槛只剩 3 个位姿，三点必然共面、planarity 精确为 0，会给出一个描述门槛而非描述采集的几何拒绝。
  • 仪器本身不是瓶颈。激光跟踪仪自身误差以本机证书为准，通常在几十微米量级。GT 链那 1 mm 会花在四处：球心 c 的拟合、跟踪仪系 ↔ 相机 world 的注册、时间对齐、失锁，改版后再加两条机械项（钢片刚度、窝内微动）。本页的工作量也集中在这几处。注意这 1 mm 是「球心」的预算，不是 TCP 的——两者相差 rig → TCP 旋转那一项，见 T6。
  • 「原始数据只能在 Windows 拿」这个前提不成立，Trigger 口也不再是未知数。随机 SDK（v7.18.0.0）官方支持 Windows / Linux / Mac，README 给了 .deb 安装路径并注明 ARM 架构不依赖 Qt6 —— 拿到 Linux 包，logger 可以跑在 Ubuntu 工作站甚至 Thor 上，少一跳主机钟。但这条的权重取决于触发线：TTL 接得上时对齐走脉冲索引、全程不涉及主机钟，跑在哪台机器就只剩运维差别；接不上时主机钟才重新变成唯一手段。Trigger 口是 TTL 输入，Radian 上限 1000 Hz（相机 60 Hz 只占 6%），StartTTLMeasurement 每个脉冲回一条带控制器时间戳的点。对齐方式随之从「求 Δt」升级成脉冲索引对应。见 SDK 与随机资料。
  • 先拿与时间无关的静态数字。注册（T5）和静态精度图（E1）都只用静止位姿，不依赖时钟链。T0–T2 加 T4/T5 走完，就能给出「独立 GT benchmark」行的第一个数。时钟链同时并行打通。
  • 「先 FR3 搭载、后手持」这条排序的理由已经消失了。它原本成立是因为手持那一侧要另一个还没存在的夹具（等供应商）；改版后两者是同一块钢片，手持不再被 E2 卡住。FR3 仍然是更好的调试起点（可控、可重复、没有人手挡光），但它现在是可选项而不是前置条件。手持受 SMR 接收角与遮挡限制，GT 覆盖率本身就是交付项，而且要按「窝法线 ↔ 视线夹角」分层，否则接收角造成的选择偏差看不见。
  • STS 在库（序列号 6395，PRM 在档），姿态精度 ±0.010°。放在 259.5 mm 力臂上是 0.045 mm，对比现在那个从未实测的 2.0° 声明（9.1 mm）是 200 倍。代价有三条且都要单独处理：1.36 kg 挂在夹爪上（载荷变形，预算里还没有这一行）、装的位置不能挡住 cube、与 TTL 硬触发互斥。一次只锁一个靶这条不变：双手静态 TLR 可认证，同步双臂动态不覆盖。
  • 2026-09-17 改版：靶球从「逐个静止位姿测 3 个窝」改成「钢片 + 单窝，常驻机体、整段 episode 跟踪」。这不是同一个实验的省钱版，是换了一个实验。换来的是整条轨迹的 GT、速度相关项第一次可测、以及在真实采集构型下取数；失去的是 marker → TCP 常量——单窝时球心 c 只能由驻点集拟合，而拟合会把「机体系常量平移」与「机体系常量旋转」整个吸收掉，那两项合起来正是 marker → TCP。全场尺度、位姿相关项、速度相关项、相机集合台阶，一个都没丢。推导与逐项对照见 SMR 常驻本体。
  • ≥ 3 窝那条路没有被取消，只是被拆成了独立的一条线。误差预算里最大的单项仍然是 rig → TCP 旋转（2° 声明 × 259.5 mm 力臂 = 9.1 mm，至今零观测），而单光束跟踪仪一次只跟一颗球、一个窝只给一个点，姿态仍然只能靠 ≥ 3 个非共线窝 + AX = XB，或者靠 STS 直接量。本次改版唯一必须现在拍的机加决定，就是把这块钢片做成将来能再钻两个窝的样子：最大跨距 ≥ 120 mm（标度律给的 B ≈ 107 mm），留出两个窝位。加一块新板要重排机加并重做标定；在同一块板上加两个窝只是多钻两个孔。见 T4 详述 与 首个受检构型。
  • 厂家的 SA / RMS 流程只作对照，不进 GT 链。它们的输出经过 best-fit；RMS 坐标系对齐「一般小于 2 mm」的门限，比整条 GT 链预算还宽一倍。

四 · 操作口径（这次唯一要改的习惯）

  • 一段一个驻点姿态是对的，不是错的。段的边界天然就是驻点边界，比在一长段里切分更干净。代码原来的「一段 ≥ 3 驻点」是实现细节漏到了协议上，已按上面修正。
  • 每段停到 3.5–4 s 再保存。一个驻点需要 2×0.3（两端剪裁）+ 2.0（最短）= 2.6 s，这次中位段长只有 2.89 s，4/15 根本不够长。这是本次唯一必须改的操作。
  • 不需要夹具。垫书 / 泡沫 / 纸箱，手完全离开，实测 span 中位 0.067 mm 就够。夹爪重反而有利——自重就是稳定性。真要更方便，一个磁性表座万向杆或摄影球头即可，不需要 15 个支架。
  • SMR 接受锥本来就把姿态范围锁死了。绕光束轴的 roll 不受限（角锥棱镜绕自身光轴回射不变），偏离光束的 tilt 限 ±30°——这正好是两根不平行的轴。注意 roll 过头时重力会把 SMR 拽出磁窝。
  • 旋转多样性的门槛是 min_c_gain = 0.05，等效角约 2.9°，那是「能不能解」的地板而不是质量目标。σc ≈ σpose/(gainmin·√N)：增益是一次方，位姿数只在根号里，所以两根轴张开比多凑姿态值钱。
  • 姿态数跨 session 累加，旋转增益不累加（gain_min = max(per_session)）。所以两根轴必须在同一个 mount_id 内张开——合并之后。

几何：9 个未知量，和它们各自靠什么可观测

比较的两边根本不是同一个量：跟踪仪测一个点（球心，3 自由度，跟踪仪系 G），相机测一个完整位姿（6 自由度，相机 world 系 W）。把它们放进同一句话需要两样东西：

 p̂(t) = RW,rig(t) · c + tW,rig(t)      相机说球心在哪（c = 球心在 rig 系中的位置）
 p(t)  = RWG · pG(t) + tWG            跟踪仪说球心在哪（TWG = 注册）
 e(t)  = p̂(t) − p(t)

上表的四条「吸收」不是推测：metrology/tests/test_tracker_mount_fit.py 逐条注入单一偏差再拟合，断言残差为零、ĉ 按上式移动；尺度那一行断言残差不为零。任何一条翻转都说明某处报告在说它没资格说的话。

未知量是 TWG 六个加 c 三个，共 9 个。一个静止位姿给 3 个方程，所以计数上 3 个位姿就够；但可观测性要的是转轴。两个位姿相减消掉 tWG：

 (Ri − Rj) c = RWG(pi − pj) − (ti − tj)

纯平移的位姿对 Ri = Rj，左边恒为零，对 c 一个比特的信息都不给。这与 AX = XB 的可观测性条件同源，所以驻点集必须绕 ≥ 2 根不平行轴转——这条不是从旧方案抄过来的，是同一个数学重新推出来的。

反过来也要说清楚：老方案同样测不了新方案能测的东西。固定时差在残差里表现为 |v|·Δt，静止位姿上恒为零，所以「50 个驻点 × 3 窝」这个结构在原理上就看不见任何时间误差。两条路不是替代关系，是两个实验。

换来的四件事，每一件老方案都做不到

  • 整段轨迹的 GT，不是 50 个驻点。误差预算里「独立 GT benchmark」那一行要的本来就是轨迹口径，静态口径只是它的一个下界。
  • 速度相关项第一次可测。固定时差 = |v|·Δt：静止时不可见、随速度线性增长。这也是为什么按速度档分层是默认输出而不是可选项——一条轨迹里大部分帧接近静止，池化 RMS 恰好把这套装置要找的失效藏起来。
  • 在真实采集构型下取数。夹爪在位、人手在握、相机全开、正常动作，不是标定仪式。老方案要专门摆 50 个姿态、每姿态逐个测 3 个窝，采到的构型与生产构型不是一回事。
  • 驻点集从「50 姿态 × 3 窝 × 两只手」缩到「15–20 姿态 × 1 窝」，几分钟一次。于是它可以每场次重做，而不是标定一次用一个月——「拆装后是否复位」不再是一条需要单独证明的假设，而是每场次自带的量。

球装在夹爪侧，两个要求罕见地同向

这里有两个不同的力臂，很容易混成一个：

  • |c|（球心 ↔ rig/cube 系原点）决定灵敏度。姿态误差 dθ 把球心挪 |c|·dθ，所以 |c| 越大，相机估的旋转误差在残差里放大得越多。|c| = 0 时残差对旋转完全失明。
  • |c − cTCP|（球心 ↔ TCP）决定相关性。报告点是球心；球心不在 TCP 时，TCP 误差 = 球心误差 + 旋转 × 这段力臂，而新接法下第二项是未测量。所以这段越短，残差离真正关心的量越近。

cube 到 TCP 是 247 mm 的一条链，两端相距很远。把球装在靠近 TCP 的夹爪侧，同时得到大的 |c|（灵敏）和小的 |c − cTCP|（相关）——两个要求在这个几何下同向而不是互斥。截图里的装法（钢片在夹爪支架上、球靠近指根）在这两条上都是对的。反过来，装在 cube 那一侧会同时丢掉两样。

但固定点必须落在 TCP 那个刚体上，不能挂在 cube 侧。要验证的链条是「相机估 cube 位姿 → 常量 → TCP」，cube 与本体之间的装配间隙和晃动正是待检项之一。如果钢片经由 cube 或 cube 的附件固定，这段间隙在两边同时出现、精确抵消，于是看不见了——那等于把被测量从残差里减掉。需要现场核对：截图里的相机支架，在装配链上是挂在本体/夹爪侧，还是挂在 cube 侧。

新接法带来的六个新失效模式

  • 接收角把评测集选偏了。「适当保持夹爪姿态」这句操作要求，在数据上等于只有一部分姿态有 GT；而被排除的那些极端姿态，恰恰最可能是标签误差最大的。这是选择偏差，不是覆盖率不足。对策两条：逐 episode 报 coverage；并按「SMR 窝法线 ↔ 跟踪仪视线夹角」分层报残差，让「接近接收角边界时误差是否变大」成为可回答的问题。结论里必须写明它只适用于测到的那段姿态范围。
  • 磁吸保持力要对抗动态载荷。百克量级的球在 30 m/s² 下是 4–6 N。1.5″ 磁窝本来就是为这颗球设计的（轴向吸力 20–50 N），但剪切与剥离方向弱一个量级，余量只有一到三倍，不是二十倍。机械防脱（挡圈或系绳）是必做项：说明书 §1.9 要求开测前确认磁吸底座粘牢；靶球摔落是设备损坏，而且是共享设备。一根绳把「摔球 = 毁掉共享仪器」变成「球晃一下、本场作废」。分配值 0.15 mm。
  • 球在窝里的微动会伪装成相机误差。球若在高加速度下相对窝滑动几十微米再弹回，它进的是残差，长得像标签抖动。判据便宜：同一段动作快慢各一遍，看残差随加速度（而不是随速度）的变化——速度相关指向时钟，加速度相关指向机械。老的 T1「落座重复性取放 20 次」是静态口径，不覆盖它。分配值 0.10 mm。
  • 钢片是悬臂，SMR 在它末端。板的挠度直接进残差。钢比铝好，但决定刚度的是厚度与跨距而不是材料。静载检查当场就能做：板上装好 SMR，用弹簧秤加已知侧向力，跟踪仪读位移，直接得到 mm/N。
  • 激光现在打在机体上，紧挨着相机。老方案球在独立工装上；新方案光束终点就在相机支架上。钢片的镜面反射会让自动曝光跳变、marker 检出率掉。钢片做哑黑（发黑或哑光漆），不要抛光。T1 里「对相机的干扰」那一项因此从「顺带测一下」升级为上线前必过的门：跟踪开 / 关各录一段，比 marker 检出率与角点残差。
  • 加了质量就改了被测系统 —— 但这条比它听起来轻，原因在报告口径而不在机械。1.5″ 球 + 加厚的板约 300–350 g，挂在 1.5 kg 量级的手持 BOX 上是约 20% 的质量增加与重心偏移，操作者的动作分布会变。但本页报的不是一个池化数字，而是 error(速度, 姿态, 相机数) 的分层曲线，而输入分布偏移不会让一个在该分布上测出来的函数失效——只要生产工况落在测过的范围内。于是真正剩下的风险只有「范围覆盖」：如果多出来的质量让操作者再也上不到生产速度，快档就没测过。对策已经在设计里——E3a 是主动跑速度档，不是靠自然动作碰运气。
    想让它彻底消失还有个便宜办法：板与窝常驻，球不常驻，生产采集时在窝里坐一颗等重的哑光钢球，验证时换成 SMR。钢球几乎不要钱，SMR 不必跟着上生产线冒险，两种场次的动力学完全一致。
    在做这件事之前，结论里固定写一句「本结论取自带 SMR 工装的构型」。

一次验证场次的顺序

  1. 热机 90 min（T0 定案）→ 前后视检查（每场次一次）→ 固定窝网络首测（判断站位是否被碰）。
  2. 驻点集 A：≥ 15 个静止位姿，绕 ≥ 2 根不平行轴，每姿态静置 ≥ 2 s；全程 cube 在多相机视野内且 SMR 在接收角内。留出 ≥ 5 个位姿不参与拟合，用来出留出残差。
  3. 评测 episode：正常采集，跟踪仪全程锁定，1 kHz 流不停。这里不做任何拟合。
  4. 驻点集 B：收尾再采一组。A 与 B 解出的 (TWG, c) 之差，就是本场次的漂移 / 碰撞检查——免费，且必须做。差值超限时这一场的评测数据作废，而不是「用平均值继续」。
  5. 固定窝网络尾测 → 落盘、封存、scp 回传。

注意第 2 步与第 3 步的先后不重要，重要的是它们是两批数据。驻点集与评测集混采、或者用评测轨迹自己拟合 c，都会把待测的误差吸收进注册——这就是 SpatialRegistration.shape_only() 那条路永远返回 certifies_space = False 的原因。

GATE驻点集的可观测性先判后出数：转轴近平行时拒绝出数（沿用 hand_eye.py 的约定）；(TWG, c) 给 bootstrap σ；留出位姿的复核残差与拟合残差同量级。场内 A/B 两次拟合的 Δc 与 ΔTWG 写进 manifest，超限即作废本场评测数据。每 episode 报 coverage 与「窝法线 ↔ 视线夹角」分层残差。本场次的任何结论都不得涉及 marker → TCP。

T2a 先定一件事：logger 跑在哪台机器

  • SDK 官方支持 Linux 与 ARM（SDK 节），所以有三档：① 跑在 Thor——采集机与相机同机；② 跑在 Ubuntu 工作站——少一跳；③ 跑在 Windows 工控机——现状。
  • 但这个选择的权重取决于 T3b 那根触发线接不接得上，不能反过来。接得上：对齐走脉冲索引，全程不涉及主机钟，主机钟只用来定 index 0（要求从 0.7 ms 放宽到 ±8 ms，见 T3f），跑在哪台机器就只剩运维差别——少一次 rsync、少一台机器、起停可与录制原子化（孤儿 episode 目录错位那类配对风险由构造消除）。接不上：主机钟重新变成唯一手段，① 的价值才真正凸显。所以优先级是先要 Trigger 电气规格，再要 Linux 包。
  • ① 有一条容易被低估的代价：它扰动被测系统本身。Thor 正满载跑 7 台相机 + 录制，再塞一个 1 kHz 回调线程加落盘，可能动到我们正要认证的那条流水线——那就成了「认证一个被自己改过的系统」。② 工作站是更稳的默认选择，尤其在触发线接得上的情况下。
  • ①/② 还要确认：跟踪仪专网怎么接到目标机；宁可走工作站中转，也不要给 Thor 加网段 profile（单网口多 profile 已经造成过重启后网络飘忽）。

T2b 取数路径：逐条满足才能作为 GT 原始数据

  • 动态场次走 TTL：StartTTLMeasurement，每个相机 PWM 脉冲一条 {timestamp, x, y, z}。第 N 条即第 N 个脉冲，与相机第 N 帧索引对应。时间戳用来查漏脉冲（相邻应差 16.667 ms），不用来做对齐。
  • 并行开 1 kHz 实时流：SetRealTimeCallbackFunction 落 is_measurement_valid/is_tracking/operation_mode（失锁段的唯一可信来源）、level_x/level_y（站位监控）、body_temperature 与激光/ADM 强度（漂移监控）。先在台架上确认 TTL 与实时流能否同时开——不能的话，失锁判定要退回 TTL 的 error_code。
  • 静态 6D 场次走 STS：Start6DDynamicMeasurement 或 Get6DSinglePointMeasurement。这类场次没有可信时间戳，也开不了 TTL（配件互斥），所以只能用于静止位姿。
  • 坐标必须是跟踪仪原生系，没做过 best-fit 或变换；能脚本启停并写入会话 ID。
  • 兜底：Linux 包没到手时用 OT Bridge（UDP 2000，JSON）从 Ubuntu 直接取流，它每帧同时给主机 epoch 与控制器时间戳。降级用 SA 导出，在 SA 里做过的变换或拟合必须随数据一起导出，否则不进 GT 链。RMS 只出 E5 的 ISO 9283 对照报告，不当原始数据源。
  • 并发限制：同一时刻只能有一个客户端占用跟踪仪，SA 与自写 logger 不能并行，场次要排开。

跟踪仪ThorA 路径已确认可行电气规格待核

给每个跟踪仪样本一个 Thor 时间，而且这个时间不能从相机标签反推出来。SDK 到手后这条路变了性质：TTL 模式下第 N 条回调就是第 N 个脉冲，所以目标从「把两个钟对齐到 0.7 ms」变成「证明脉冲一个没漏，并标定触发到测量的那一个常数延迟」。前者是统计估计，后者是计数与一次性标定——后者可靠得多。

硬触发买到的是可分离性，不是精度。软同步下要估时间偏置只有两条路——运动互相关，或残差对速度的斜率（decompose_residual_by_speed）。两条估出来的都是同一个东西：所有随 |v| 线性增长的项之和。而相机自己就有随速度增长的误差：滚动快门的行相关偏斜、模糊下检测阈值的不对称、曝光期内的加速度二阶项。它们与时钟偏置具有完全相同的特征，拆不开——这正是红线那句「运动互相关的 Δt 只能认证空间精度」的由来。硬触发把时钟那一项从这个和里拿掉，剩下的斜率就纯粹是相机自己的运动相关误差，而那恰恰是要测的东西之一。

所以交付物会变窄而不是失效：结论从「标签误差 X mm，其中时钟贡献 a、运动模糊贡献 b」退化成「标签误差 X mm，其中速度相关的那部分无法归因」。判决 3 mm 没有代价（用户关心总误差不关心归因）；改进流水线代价很大（不知道该修时钟还是修曝光）；重调平滑器 σ 居中。

2026-09-18 落地时挖出来的两件事 都比曝光那一项更靠前

① 标签用的根本不是 SOF，是 N/fps 名义栅格。thor_lerobot_v3 里写得很明白：timestamp_s = frame_origin_s + local_frame / fps，注释是「parquet timestamp 列保持 N/fps（loader 合同）」。硬件 SOF（camera_frame_times_rel）只拿去做 BOX 最近邻查找的目标，没有进 parquet。而 GT 链读的是 v2 sidecar 的 timestamp_s ← parquet timestamp，所以跟踪仪比对用的是名义栅格。ts_sync.md §5.4 实测 N/fps 与硬件 SOF 之间有 逐 episode 变的 10–55 ms 固定 skew；在 680 mm/s 下 45 ms 就是 30 mm。这一项比曝光那 2.7 mm 大一个数量级，而且它不是猜的，是已经量过的。曝光中点修正必须搭一个不违反 loader 合同的载体才能到达 GT 标签——现在这一版只到了 BOX 对齐那条路。

② validate_against_tracker 把 episode 本地秒当成了 Thor 绝对秒。_read_sidecar 读出的 cam_t 是 episode 本地时间（从 ~0 开始），直接当 camera_thor_s 传进 pair_on_camera_times，命令行上没有任何 t0 锚点参数。好消息是它会响亮地失败而不是悄悄给个错数——两段时间根本不重叠，覆盖率直接 0、走「cannot run」分支。之前跑通的那次是 fixture 自己造的 sync.csv，时间对得上，把这个缺口盖住了。上真机前必须把 meta.json 的 t0_mono_s 接进来，这也正好是 ① 的那个载体。

曝光中点的符号：不问供应商，用两档曝光自己读出来

帧时间线是 触发 → 积分 → 读出（§3.1 的 slave mode 约束 exposure_us + readout_time < PWM 周期 就是这个顺序的证据），所以若 getSensorTimestamp 给的是积分起点，采样时刻 = SOF + Texp/2。但 Tegra VI 到底锁存哪条边，是驱动细节不是数据手册条目。实验判据：同一段运动录两档锁定曝光（如 2 ms 与 12 ms），各自用 --exposure-fraction 0.0（即不做修正）估相机↔IMU 偏置，两个偏置之差必须正好是 (e长 − e短)/2 = 5 ms：差值的符号直接读出锁存的是哪条边，差值的大小顺带检验「中点模型」本身成立与否。两个问题都不欠供应商。代码里它是 EXPOSURE_CENTER_FRACTION = 0.5，一个具名常量而不是字面量，就是为了这个实验有地方落结论；符号搞反的代价是一整个 Texp，不是 Texp/2。

GATE首选按脉冲计数结案：一段 ≥ 10 min 的采集里，TTL 回调条数 == PWM 脉冲数 == 相机帧数，三者逐段可核；device_time 相邻差的直方图只有 16.667 ms 一个峰。加上触发延迟与「SOF → 曝光中点」偏置两个实测常数，时间行就只剩这两个常数的不确定度。计数对不上时才退回原判据：Δt 残差 ≤ 0.7 ms、钟速比 s ≤ 30 ppm。

  • 站位固定（2026-09-17 已定）带来一个结构性简化，而且代价差距是量化过的：TWG 在 world_frame_id × tracker_station_id 不变期间是常量，可以跨场次累积拟合；每场次只需重拟合 c（3 个未知量，线性、每个位姿都贡献，不需要任何转角）。实测：同样的位姿与噪声，冻结站位后 σc 比联合解小 4.4 倍，而且这个比值与噪声大小无关。要靠加位姿弥补 4.4 倍需要 19 倍的位姿数，所以这不是方便，是这条路能不能达到 T6 那 0.20 mm 的分水岭。于是「必须绕 ≥ 2 根不平行轴」只对第一次建立 TWG 是硬条件，之后降为一致性检查——这对 ±30° 接收角下转不动大角度的现实是实质性缓解。
  • 而且它白送两个诊断：① 跨场次的 ΔTWG 同时监视跟踪仪站位和相机外参有没有漂——主 roadmap P2 想要的 global-drift watchdog，不用另做。② TWG 固定后，把逐位姿单独解出的 c 对姿态作图：任何系统性变化就是姿态相关的 rig 位姿误差，被直接画出来而不是混在残差里。这两件事老方案都做不了。
  • 只用 SE(3)：尺度不吸收，另报 Sim(3) 拟合出的尺度（ppm）作诊断。全场尺度正是要暴露的共模误差。
  • 先判可观测性再出数、没有 σ 不算测量：沿用 hand_eye.py 的约定，转轴近平行时拒绝出数，bootstrap 给 σ。
  • 版本化：注册写成 world graph 的一条边，带 world_frame_id、tracker_station_id、mount_id、标定 hash、日期、残差。跟踪仪挪动就是新站位，钢片拆装一次就是新 mount，两者都让旧的 (TWG, c) 作废。
  • 驻点集与评测集分开采，位姿不同，最好时段也不同。评测轨迹上不再做任何 best-fit——c 现在也在这句话的管辖范围里，这正是 SpatialRegistration.shape_only() 永远返回 certifies_space = False 的原因。
GATE注册 σ（bootstrap）进链预算「注册行」。留出静态位姿上的复核残差应与注册残差同量级；明显更大说明相机 world 有空间畸变，那本身就是 E1 的结论。

T4 详述 · 受检构型怎么接 SMR

2026-09-17 起：本节属于 T4b（顺延）

本节整节仍然成立，但它回答的已经不是主路线的问题了。轨迹验证走 T4a 钢片 + 单窝；本节的 ≥ 3 窝方案降为 T4b，只在要 marker → TCP（误差预算里 9.1 mm 零观测的那一行）时才做。下面三条事实、标度律、以及「一个窝只给一个点」的推理一个字都没变——变的是它们现在服务于一个被推后的目标。读的时候把「必做项」理解成「要那个数字时的必做项」。

问题的实际形态不是「要不要做转接件」，而是「做几个窝、装在哪」。三条已核实的事实把它定死了。

  • 没有任何现成接口能直接接 SMR。Hybrid Carrier 的球窝是 R 12.68 mm 球面、配 25 mm 钢球（单边间隙 0.18 mm）；常见 SMR 口径 1.5″ 38.1 mm、7⁄8″ 22.2 mm、0.5″ 12.7 mm，没有一个是 25 mm。SMR 还带孔径与反射腔，不是完整球面，不能当座球压在球窝里受力。所以 连 carrier 也要转接件。本机实际有哪几颗 SMR、直径、类型、接收角、重量，T0 清点后才算数（「到手先核对」第 3 项）。
  • 现有夹爪连球窝都没有。cube 到 TCP 是 247 mm 的一条链，cube 的 CAD 不知道 TCP 在哪。现行生产常量 marker_to_tcp_calibration_20260825.json 靠 pivot 采集拿到：平移是实测（holdout 残差 p95 2.70 mm，σ = [1.20, 5.25, 1.83] mm），旋转是从上一版 bundle 继承的、没测过（σ 声明 2°，bundle 自己的 open_items 写着「两指夹爪绕接近轴 180° roll 的对称性未被证据排除」「拆装重复性未采」）。
  • 一个窝只给一个点。单光束跟踪仪一次只跟一颗 SMR，输出位置三自由度。要拿姿态，只能逐个静态测 ≥ 3 个非共线窝再做 Procrustes——说明书 §3.4 的 SMR1–3 × P1–P5 正是这个做法。而姿态恰恰是现有夹爪欠的那一项。

回答「首个受检构型选现有夹爪，是不是得专门设计夹爪-球连接件」：是，而且规格比一个球座高——要「≥ 3 个非共线窝的刚性工装」。好处是它顺带把 marker → TCP 的旋转第一次独立测出来：今天没有别的手段能做这件事（pivot 是定点约束，一个点永远定不了旋转，bundle 自己也这么写）。

开图前钉死的八条

  • 装法先定，它决定你认证的是哪个 TCP。螺在机体上的支架认证的是 CAD 本体 TCP；指间带硬限位的插件认证的是 TCP_closed（把夹爪机构间隙一并算进去）。两者不是同一个量，而这等于替主 roadmap Phase 0「开度是否改变 TCP」先做了一半决定——先定口径再开图。
  • 单窝有一个跟踪仪看不见的盲区。只有一个窝时，球心偏距 d 上的姿态误差 × d 完全不进残差：按现行 bundle 声明的 2°，d 只要 8.6 mm 就吃掉「SMR 球心 ↔ TCP」整行 0.30 mm。这是 ≥ 3 窝的第二个理由（第一个是它根本测不了旋转）。
  • 球心出处。窝的球心位置由定位面在 CAD 里构造出来，不是从相机数据拟合、也不是从打印皮肤量出来的。装配完用跟踪仪自测三窝间距对 CAD，这同时是一次装配自检和尺度检查。
  • 可重复拆装。两个定位销 + 螺钉；拆装重复性实测 ≥ 10 次取放并进预算——现有 bundle 缺的正是这一项。
  • 工艺：CNC 铝，不要 FDM。Hybrid Carrier 那次的致命项是收缩不是粗糙度，同样的坑不要再踩。磁吸窝买标准件（跟自制球窝不是一回事：磁吸窝是三点运动学定位，自制球面窝的间隙会变成姿态相关项，rig 那边已经吃过这个亏）。自制只做安装板。
  • 朝向与接收角。SMR 接收角有限（本机型号待 T0 核），三个窝的朝向要覆盖跟踪仪站位方向；手持时腕部一转窝就背对跟踪仪，所以 GT 覆盖率本身是 E3 的交付项。
  • 遮挡。窝板不能遮 cube 的 marker 面，也不能挡相机到工件的视线。先在 CAD 里用 carrier 那套 occluders 的算法跑一遍可见性，别等到现场发现检出率掉了。
  • 防脱与重量。说明书 §1.9 专门要求开测前确认磁吸底座粘牢，靶球摔落是设备损坏（还是共享设备）。手持动态下磁吸保持力要对抗加速度：做机械防脱（挡圈或系绳），重量待 T0 清点后核手持动力学。
  • 开口相关的 TCP。A 方案把开口钉死在 45 mm 就等于该轮不覆盖抓取；B 方案不受开口影响，但它测的是 marker → 窝，TCP 还要经 contact_tcp(g) 折一次。
  • 不迁移。新夹爪上的窝位置已在供应商需求 V2 的 T3 提出；现有夹爪这套工装明确只为拿 A′ 基线，不迁到新夹爪。

预算冲突，先看清楚再开工。GT 链给「SMR 球心 ↔ TCP」这一行只有 0.30 mm p95；而夹持式 insert 的既有验收门限是 holdout p95 ≤ 1 mm（才够谈亚毫米）、≤ 3 mm（够 3 mm 预算），现行 pivot 实测 holdout 是 2.70 mm。差一个数量级。

解算：AX = XB，A 侧用跟踪仪，不是 FK

主 roadmap P0-Now ⑫ 已经把「旋转怎么测」定案为 hand-eye，解算侧也已落地——metrology/hand_eye.py + metrology/cli/hand_eye_calibration.py（48 单测，GUI 标定中心有面板），而且它只吃「位姿对」，与夹爪几何无关。跟踪仪路线不改解算器，只换 A 侧的来源：

  • Aij = 跟踪仪测出的工装相对运动（3 个窝 → 一个 SE(3)），不是 FR3 FK。
  • Bij = 相机测出的 cube 相对运动，与原方案相同。

三个后果，每一个都消掉原方案的一个依赖：① 不依赖 FR3 的 FK，本页红线「FK 只当运动源、不当真值」自动满足；② 注册 TWG 在相对运动的两侧同时出现、精确抵消，所以这件事不必等 T5；③ 采集时是完整的生产构型——夹爪在位、可以手持，不必像 FR3 hand-eye 那样把夹爪卸下来装到法兰上（原方案的采集侧正因为要等新夹爪–rig 方案而顺延至今）。

平移由同一次解的平移方程 (RA − I)·tX = RX·tB − tA 一并给出，于是 pivot 那条链的 holdout 2.70 mm 和 --delta-sigma-mm 5.0 都绕开了，旋转与平移一次采集全出。

必须显式重算的一条旧结论。主 roadmap 否决过「多点 Procrustes 测旋转」：标度律 σθ ≈ σΔp / B，代入 0812 实测的球心分散度 σΔp = 1.40 mm，要 0.22° 需要窝间距 B ≈ 517 mm（乐观）～1.5 m（现实），夹在 45 mm 开口里做不到。

那次否决的是「球心由相机测」这个变量，不是 Procrustes 本身。换成跟踪仪测球心，同一条标度律等比缩放：σΔp 从 1.40 mm 降到 0.10 mm 量级（T6 仪器行 0.10 + 落座 0.05 的工程门限），B 需求同比例降到 ≈ 37 mm（乐观口径）～ ≈ 107 mm（现实口径）。做一个 150–200 mm 的三窝三角形就有 1.5–5 倍余量。

反过来写更好用：窝间距做到 150 mm 时，跟踪仪侧的球心分散度只要 ≤ 0.14 mm（现实口径）就够——这正是 T1 要实测的量，所以 T1 的结果直接裁决这条路成不成立，不必先加工再发现做不到。（0.10 mm 目前是工程门限、未测。）

窝板装哪里：BOX 本体基准面

  • URDF 里 joint_link_marker_cube 与 joint_lt_gripper_base 的 parent 都是 link_box——marker 挂在 BOX 本体上，不在夹爪上。所以窝板装 BOX 本体的精密基准面（夹爪原本就依赖的那个面）。
  • 不装 cube 上：会把 cube 自己的晃动与装配间隙一起带走，而那正是待检项之一。不装指间：那是 A 方案，夹持重复性进预算且不能做抓取。
  • 待测量因此是 Rbox,rig；TCP 那一段走 URDF 的 link_box → joint_lt_gripper_base → link_lt_gripper_tcp 固定链——与 FR3 hand-eye 路线残留的 CAD 输入（Tflange,box）同级，不更差。
  • 残留的机加输入因此退化成一块平板的平面度与孔位角，机加 ≤ 0.05°–0.1° 是常规水平；对比现值 2.0°，是 20 倍以上的改善。

采集协议与顺序

  • 先 left，再 right。left 有 pivot 实测平移可作对照——两条独立方法测同一个量，这是对 GT 链自身的一次校验；校验过了，再去测 right 那个真未知量才有底气。两侧同场做完、跟踪仪站位不动，顺带给 E4 的 TLR 一组静态数据，也才能取上面那个 6.15 mm 的差值。

口径红线

评审时逐条过
  1. GT 链自身预算合格之前，不下「3 mm 已认证 / 未认证」的结论，只报「GT 链未合格」。
  2. 注册、钟速比 s 与 Δt、SMR 球心位置 c，都在独立于评测集的数据上拟合。评测轨迹上不做任何 best-fit。
  3. c 由驻点集拟合时（2026-09-17 改版的现行口径），「机体系常量平移」与「机体系常量旋转」已被拟合吸收，该场次的残差不能用来认证 marker → TCP，也不能称为「TCP 误差」。报告点是 SMR 球心，措辞固定为「模去常量 rig 系偏置与旋转」。要 marker → TCP 只有两条路：T4b 的 ≥ 3 窝 AX = XB，或 STS。
  4. 钢片一次拆装就是一个新 mount，旧 c 作废，与「跟踪仪一挪就是新站位」同级。每场次驻点集采两组（评测前后各一组），两组的 Δc / ΔTWG 超限即作废本场评测数据，不取平均。
  5. 注册只用 SE(3)，尺度不吸收；Sim(3) 尺度只作诊断输出。
  6. 运动互相关的 Δt 只能认证空间精度，时间戳结论必须来自独立时钟链。
  7. Windows 侧只落盘。SA / RMS 里做过 best-fit 或坐标变换的数据不进 GT 链，除非变换本身随数据导出。
  8. 跟踪仪数据与 episode 按 ID 配对并校验时间重叠，不按目录或顺序。
  9. 平滑前、平滑后都报；按速度档、可见相机数分层；每 episode 报 GT 覆盖帧比例。另按「SMR 窝法线 ↔ 跟踪仪视线夹角」分层：接收角决定了哪些姿态有 GT，不分层就看不见这个选择偏差，而它恰好偏向排除误差最大的那些帧。没测到的姿态段不外推。
  10. FR3 只当运动源或定位器，FK 不当真值。FR3 搭载的结论不外推到手持；带载构型写明。
  11. 跟踪仪挪动就是新站位，旧注册作废；每 session 首尾测固定窝网络。
  12. 厂家流程的门限（例如 RMS 对齐「小于 2 mm」）是另一台机器人的验收口径，不能搬来当本项目门限。

±30° 接收角下，横向 0.5 m 的动作在 0.8 m 处就单独吃光整个锥，一度姿态摆动都不剩。所以真正要问的不是「站位多远」，而是「验证轨迹允许在多大的横向范围里跑」。反过来算：留 10° 给姿态保持误差，α = ±30° 时允许的横向半径是 0.8 m 处 0.29 m、1.5 m 处 0.55 m、2.2 m 处 0.80 m。

「能否固定夹爪角度运动、只验空间位置？」——可以，而且数学上完全自洽，应该作为第一场来做。姿态钉死意味着所有姿态误差都退化成常量，而常量机体系旋转正好被 c 吸收，于是残差就是纯粹的位置误差，没有任何混入——这不是近似，是上面那张吸收表的直接推论。RWG 仍然可观测，靠的是平移方向的多样性（轨迹要非共线、最好非共面），尺度也照样可测。

要留意一处退化：姿态固定时 c 与 tWG 完全混淆，只有二者的组合可观测。这对残差毫无影响（残差对怎么拆分不敏感），但意味着这一场报不出 |c| 和旋转灵敏度，而且驻点集仍然必须带转角——或者用固定站位累积下来的 TWG，那时逐位姿直接解 c，转角就只是一致性检查。

代价是三条，都要写进结论：① 姿态误差完全不可观测，不只是常量部分；② 这是在最容易的工况下验证——真实操作腕部摆动很大，而相机位姿误差通常恰恰是姿态相关的；③ 相机集合切换的台阶不会出现，因为看得见 cube 的那组相机基本不变。所以它不能替代真实操作那一场。

但它换来的东西很实在：时间链、注册、插值、速度相关项，全都不需要姿态变化就能验完——而速度相关项（|v|·Δt）正是老静态方案在原理上永远拿不到的那一项。而且它在 1.5 m 站位下 coverage 会很高，等于把站位问题一起绕开了。更值钱的是：先做它，真实操作那一场的残差减去它，差值就是姿态相关误差——一个干净的分解，只有按这个顺序做才拿得到。
