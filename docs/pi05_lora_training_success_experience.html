pi0.5 + LoRA 训练成功经验

范围：结合 FR3 抓取 Baseline Roadmap、实验档案和当前 repo，只总结截至 2026-08-31 已有较确定收益的经验。

这不是“成功率已经解决”的复盘。当前只是流程跑通，训练、推理、真机 rollout 和评分链路都有了闭环；模型具备基础成功能力，但固定协议 20 轮为 0 成功，合计 2 / 29 ≈ 7%。因此这里保留的是能稳定改善可训练性、可诊断性和可回退性的经验，不把尚未验证的 crop、yaw 分相位加权、DAgger 写成成功经验。

二、当前结果该怎么读

确定成立：030000 不是随机输出。它在留出集上三个平移维全线上涨，真机上也表现出“会找本次物体”的能力，失败从“没有条件化”换成了“最后几毫米与插入精度不足”。
不能外推：2/29 的真机结果只能证明有基础成功能力，不能证明成功率可用。20 轮固定协议全失败，而且失败断在不同阶段，二元 success/failure 已经不够。

三、明确不要写成经验的东西

  • 不要说“继续调大 rank 一定有效”。历史上 rank 的含义被 alpha/r 反向稀释过。
  • 不要说“增加推理采样 / inference steps / EMA 会解决 B/C 档”。当前证据指向均值精度，不是单纯采样散布。
  • 不要说“只看 lift 或 held steps 就能判成功”。夹爪闭合并抬起时，手里也可能是空的。
  • 不要把 crop、分相位 yaw 权重、DAgger 当作已验证收益。它们是下一步候选，不是本轮成功经验。

四、确定有收益的经验

1. 先修动作/观测契约

经验：训练前先确认标签不是观测的平凡复制，动作定义也不能和部署时的动作定义漂移。否则 loss 会下降，但学到的是一条不可部署的捷径。

本轮证据：首帧可作弊度从 0.68 降到 0.18；夹爪 copy 通路 R² 从 0.9999 降到 0.31。这不直接提升抓取成功率，但让后续 L0-L4 的结论可读。

repo 形态：fr3_delta_action_transform.py 明确把 delta 定义为 dataset frame 间差分，absolute action 仍是源数据；部署侧再把 delta 还原为绝对 EE 命令。

2. 离线生成 delta action

经验：FR3 采集路径保留 absolute EE，训练 view 再离线派生 delta。不要在 recorder 的控制循环里存 delta。

确定收益：控制循环约 200 Hz，而训练 view 是 30 Hz；在控制 tick 上生成 delta 会把一帧动作缩小到约 1/6.7，策略上线后会明显变慢。离线按 dataset frame 差分后，这个尺度错误被消掉，且以后可以不重录硬件数据就重建 view。

recording: absolute EE action 是源数据 training view: consecutive dataset frames -> delta action runtime: delta action -> absolute EE command
3. LoRA alpha 必须和 rank 一起钉住

经验：LoRA 的有效缩放是 alpha / r。只调 rank 不设 alpha，会把“加容量”变成“降更新强度”。

本轮证据：历史配置里 r=32 但 alpha 落到默认 8，实际缩放只有 0.25。L2b 只把 alpha 从 8 抬到 32，目标模块和参数量不变，dx 单次抽样 R² 从 0.106 到 0.479，买下 L2 约一半改进，且零新增参数。

repo 形态：--lora-alpha 默认取 rank；测试固定了生成的 peft block 和 alpha/r == 1.0。

4. 容量加在 action expert，不先动 VLM

经验：先证明视觉信息有没有穿过冻结 VLM，再决定 LoRA 加在哪。信息已经抵达 expert 时，优先扩 action expert 和投影头，而不是给 LM / vision tower 加 adapter。

本轮证据：KV cache 留一岭回归可读出 peg 位置，LOO R² 为 x=0.485、y=0.201，相对 embed_image 基线保留 114.6% / 109.6%。瓶颈在下游读出，不在冻结 VLM。

L2 收益：目标模块从默认 q/v + 投影头扩到 action expert 全 linear，并用 r=64/alpha=64，可训练参数从 2.57M 到 27.86M。ep4 上 dx 单次抽样 R² 0.106 -> 0.893，dy 0.106 -> 0.797，dz -0.196 -> 0.799，夹爪 0.659 -> 0.976。

5. 归一化和梯度预算分开处理

经验：MEAN_STD 解决动作维度尺度问题，但它会让每个维度默认拿同等 loss 预算；pi0.5 这种 flow matching 训练还需要单独的逐维权重。

本轮证据：drz 拿了 32.0% 的未加权 loss 预算，但逐步上限只有 0.151，约 84.9% 方差不可约。把权重设为 [1,1,1,0.2,2] 后，第 4 层 H22/H40 三个平移维全部上涨，夹爪仍保持约 0.96。

repo 形态：PI05Config.action_loss_weights 已落地；apply_action_loss_weights 会把权重重归一化到均值 1，只重分配梯度，不暗改总学习率。

6. 先跑便宜探针，再跑 8 小时训练

经验：不要直接用全量训练验证假设。先用单条 episode、8 条 episode、逐维 loss、KV cache 这类便宜探针，把“管线坏 / 容量不够 / 泛化不足 / 预算分配错”分开。

本轮证据：L0 判断动作目标是否可预测；L1 把缺口拆成采样散布和条件均值；L2 证明是可训练预算；L3 证明角度内插 holdout 不只是背题；L4 用实测 loss 份额确定 drz 降权。几次探针成本加起来低于一次全量训练，却直接改变了最终配方。

7. 留出集必须和训练侧对照一起读

经验：holdout 低不一定说明泛化差，也可能是这个 checkpoint 本来就差，或该 episode 的目标维度信号量小。holdout 要和训练侧 episode 同时评，且要看被考察维度的行程分位。

本轮证据：L3 中未训练 H22/H40 的表现可超过训练过的 T2；dx 数字与 episode 自身 x 行程强相关，这个模式在 L3 和第 4 层重复出现。第 4 层里 H22/H40 的 chunk 累计平移指标为 dx +0.840/+0.863、dy +0.868/+0.862、dz +0.930/+0.903。

边界：这个 holdout 是角度内插，只证明环带内泛化；半径 <56 mm、>170 mm 和 79° 缺口仍是 OOD。

8. 真机 rollout 先建测量链

经验：训练一旦有基础成功能力，下一步不是继续堆参数，而是把真机失败变成可机读数据。否则 0/20 只能说明失败，不能说明该改抓取、插入、视野还是数据覆盖。

本轮证据：S0/S0.1 已把逐步轨迹、事件约化、结果入库、落点图、会话内归位打通；后端 116 项、前端 133 项通过，真机双轮闭环验收通过。但 08-31 固定协议 20 轮全失败后，二元评分已经不够，必须进入阶段评分。

repo 形态：tools/fr3/task_ladders/insert_peg.yaml 定义阶段链，rollout_log.jsonl 记录操作者评分；轨迹事件读夹爪指令而不是观测宽度，因为观测夹爪有大量掉 0。

五、推荐以后直接沿用的检查清单

阶段检查通过后才做什么
建 view 前 确认 action 不可由首帧 state 平凡复制；delta 在 dataset frame 离线派生；drop 的维度从 action names、stats、runtime 解码一起消失。 开始 pi0.5/LoRA 训练。
训练前 打印并保存 peft block：r、alpha、target_modules、可训练参数数；确认 alpha/r=1。 相信“加容量”的实验语义。
小实验 先用单条 episode 和 8 条 episode 探针验证容量、散布、holdout，不用真机。 启动全量长训练。
全量训练 固定 holdout 与 train 对照，报告单次抽样和条件均值；drz 不再用近零分母 R² 下结论。 决定是否进入真机 rollout。
真机前 跑相机外参门；归档 checkpoint、train config、inference config、评测脚本和 prompt。 开始固定协议 rollout。
真机后 每轮都必须评分；用阶段漏斗报告，而不是只报 success/failure；轨迹文件按会话归档。 决定后续是 crop、yaw、补数据还是接管采集。

六、最终结论

pi0.5 + LoRA 这次最确定的成功，不是把 FR3 peg insertion 直接训到可用成功率，而是把系统从“不可诊断的失败”推进到“有可复用配方、有非零真机成功、有可回退 checkpoint、有分阶段测量链”。

真正值得复用的收益来自三类事：第一，把数据和动作契约修到可读；第二，把 LoRA 更新强度、模块覆盖、归一化和逐维预算钉成可解释的训练配方；第三，把 rollout 的失败记录成能驱动下一次决策的阶段数据。当前成功率还低，所以所有后续提升都应该以 030000 为锚点，一次只动一个变量。
