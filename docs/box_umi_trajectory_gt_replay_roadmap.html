3 mm 轨迹精度误差预算

Phase 3 驱动

目标口径：TCP 平移误差按 p95 ≤ 3 mm 管理。各项按近似独立的 RMS 预算合成；最终仍必须由 Phase 7 独立 GT benchmark 验收。

e_total ≈ sqrt(e_camera² + e_marker_geometry² + e_marker_tcp² + (L·θ)² + e_solver² + e_timing² + e_smoothing²)
L 是 marker rig 到 TCP 的杠杆臂，当前约 241 mm；θ 用 rad。0.5° 在当前杠杆臂下已贡献约 2.1 mm。
先读口径：为什么本页同时存在 0.2 mm 和 2 mm 两组数，以及该用哪一组。 这不是矛盾，是两类不同的量。所有亚毫米数字都产自单次标定内部——用同一套外参既做拟合又做检验， 误差在两边同时出现并抵消，因此看不见「外参本身就是错的」。自洽性检查只能给误差的下限。 本页已经因为这个口径错过两次（先是把「同一份检测重跑 BA 的 0.06 mm」当成重标复现性， 2026-08-19 又把「同一次采集 held-out 的 0.244 mm」当成端到端精度），所以把谱系钉在这里。
数字它实际测的是什么检查里允许了多少「独立性」
0.06 mm同一份检测数据重跑 BA连检测都不重做
0.244 mm0804 §6.2「独立 3D 一致性」：BA 未用过的 427 帧，但取自同一次采集、用同一套外参三角化只换帧

每放开一级独立性，数字涨一个量级：0.06 → 0.244 → 2.2。 0804 报告自己已经写了这条警告——「§6.2 的 3D 一致性衡量的是『相机之间对棋盘角点是否自洽』， 它对标定质量敏感，但对下游 marker 模型的错误完全免疫」。
为什么信 2 mm 而不是反过来：2.22 mm 那组有已知的悲观来源（两次解算里有一次是补拍前覆盖不足的版本）， 但 2.10 mm 完全不涉及那次解算（对着现行生产标定测的），从像素残差折算的 1.7–1.9 mm 又是第三条独立路径—— 三条落在同一量级，其中两条不共享任何薄弱环节。反过来要信 0.2 mm，就得解释为什么 BA 在真实视频上的重投影残差是 2.2 px 而不是 0.2 px；目前没有这个解释。
0.244 mm 并未作废，只是回答的问题更窄：「给定这一套外参，相机之间对棋盘角点自洽到 0.24 mm」—— 这说明相机布局与几何有能力做到亚毫米，Level 1「不要加相机」的结论依然成立。 0.244 → 2.1 的差额只有两个去处，且可分开：换一次标定实现（pairwise 单这一项就量到 ~2 mm）与换目标 （ChArUco 亚像素棋盘交点 → 手持 rig 上的 AprilTag marker 角点）；既然第一项已能解释大部分，第二项不需要背太多。
实务口径：写进 sidecar 的 σ、任何以 σ 为门限的下游判据、以及对 3 mm TCP 预算的核账，一律用 2 mm 量级； 论证「相机布局/几何是否够用」时才用 0.244 / 0.26 mm。 不要再用任何单次标定内部的自洽数字去论证端到端精度。

2.1 理论误差预算与可达精度判断

用于判断当前 8-camera rig 是否具备毫米级测量能力，并定位真正的精度瓶颈。

误差模型
核心判断：若工作距离约 0.7–1.2 m、有效 baseline 约 0.4–0.8 m、角点定位误差约 0.1–0.3 px，纯随机三角测量误差理论上可落在亚毫米量级。最终 2–3 mm TCP 精度更可能受外参、标定板尺度/平整度、机械漂移与 marker→TCP 等系统误差限制。
现场实测（outputs/calibration/thor_gmsl2_extrinisics_robot_base_0720，7 相机联合解）： per-camera sample residual translation mean 2.3 – 7.7 mm（最差 cam_07，max 53 mm）、rotation mean 0.34° – 1.27°（max 6.97°）； pair residual translation mean 5.4 – 21.9 mm。较早的 Hikon 8 相机报告同量级（sample 4.33 mm / pair 11.9 mm，辅助 marker spread mean 4.9 mm、max 50.7 mm）。

对照上表：0.5°–1.3° 的外参旋转误差在 1 m 处就是 9–22 mm 等效位置误差，比 3 mm 指标高一个数量级。现阶段瓶颈明确在 rig 外参，不在角点噪声，也不在相机数量。 一个直接原因是标定目标：当前 stage-3 用的是 single_tag36h11_id6_160mm——单个 160 mm AprilTag，四个角点、共面、深度与倾角方向天然弱约束。
Level 1 实测（2026-08-04，outputs/metrology/level1_0720，7 相机，σpixel=0.2 px 假设）： 上面那句「瓶颈在外参」不再是推断，已量化证实。全工作区 worst-axis σ 为 p50 0.14 mm / p95 0.26 mm / max 0.34 mm；亚毫米区（σmax<1 mm）在 z≈0 处达 7.0 m²，含一个 2.24 m 的完整内接方形（中心 x≈0.30, y≈−0.05），高度上从 z≈−0.4 覆盖到 +0.8。

2.2 Workspace Uncertainty Map：σx / σy / σz

回答“桌面哪里测得准、哪里测不准，以及当前 8-camera layout 是否天然支持 ≤3 mm”。

建议展开
它算的不是实际 GT 误差，而是几何可观测性： 在已知相机内外参和假定 pixel/corner noise（例如 0.2 px）时，预测工作空间中某个 3D 点或刚体 pose 的理论协方差。
核心含义与计算

对空间点 P=[x,y,z]ᵀ，每台相机给出投影 u_i = π_i(P)。线性化后：

δu ≈ J · δP

若像素观测协方差为 Σ_u，则三维点协方差近似：

Σ_P ≈ (Jᵀ Σ_u⁻¹ J)⁻¹

最终读取：

σx = √Σ_P(0,0), σy = √Σ_P(1,1), σz = √Σ_P(2,2)

对 UMI 更推荐进一步对 marker 刚体的 6DoF pose 求 Jacobian，得到：

σx, σy, σz, σroll, σpitch, σyaw

为什么它能直接指导相机布局
  • 如果 8 台相机几乎都从上往下看，通常 XY 很强，但 Z 与部分旋转方向可能偏弱。
  • 真正重要的是不同 azimuth / elevation 的交叉视角与有效 baseline，而不是“相机数量多”本身。
  • 如果右后角 σz = 5 mm，而中心 σz = 0.6 mm，优先调整能改善右后角交叉角度的一两台相机。
  • 可在虚拟相机布局上先重算 uncertainty map，再决定是否实际挪相机。
建议输出的 4 类可视化
  • σx map：水平 X 测量精度。
  • σy map：水平 Y 测量精度。
  • σz map：深度方向精度，桌面上方相机系统通常最值得关注。
  • worst-axis map：σmax = √λmax(Σ)，直接显示最差方向的不确定度。

进阶版可画 3D uncertainty ellipsoid，直观看出“哪个方向被约束得最差”。

从 point map 升级到 UMI pose map
  • 单点 map 只反映位置几何，不反映 marker cube 尺寸和朝向。
  • 实际 UMI 应把所有可见 marker corners 对刚体 SE(3) pose 的 Jacobian 联合起来。
  • 完整版应依赖 (x,y,z,R)：同一位置下 marker 转 90° 后，可见面和姿态可观测性会改变。
  • 第一版可以固定几个代表性姿态；第二版再加入 FoV、tag incidence angle、marker 可见面等 visibility model。
建议验收：先看理论 map 是否在主要操作区满足 σmax < 1 mm 左右；若理论上已经是 4–6 mm，则应先改相机几何。若理论上 <1 mm、实测却 3–5 mm，则优先排查 calibration bias、marker geometry、机械漂移等系统误差。

Level 1：Point Geometry Map 怎么算
  1. 将 workspace 离散成 3D grid，例如每 20 mm 一个采样点。
  2. 对每个点判断哪些 camera 可见：在相机前方、投影落入图像 FoV。
  3. 对每个可见 camera 求投影 Jacobian J_i = ∂(u,v)/∂(x,y,z)。
  4. 将所有 camera Jacobian 堆叠成 J。
  5. 根据像素噪声权重 W 计算信息矩阵：

H = Jᵀ W J

三维位置协方差：

Σ_P ≈ H⁻¹

读取：

σx = √Σ(0,0), σy = √Σ(1,1), σz = √Σ(2,2)

worst-axis：

σmax = √λmax(Σ_P)

正式版本：建议用 OpenCV projectPoints() + 数值差分求 Jacobian，从而自然包含真实 distortion model，而不是只用理想 pinhole 解析式。

Level 2：升级到 Marker 6DoF Pose Map

最终 tracking 的不是一个孤立点，而是刚性 marker cube。对 marker pose 的局部扰动：

ξ = [δx, δy, δz, δθx, δθy, δθz]ᵀ

把每个 camera、每个可见 marker corner 的 reprojection Jacobian：

J_ij = ∂u_ij / ∂ξ

全部堆起来：

Σ_pose ≈ (Jᵀ W J)⁻¹

因此可以同时得到：

σx, σy, σz, σroll, σpitch, σyaw

完整版应依赖 (x,y,z,R)，因为同一位置下 marker 转 90° 后，可见 marker 面和姿态可观测性会改变。

Level 3：传播到 TCP，而不是停留在 Marker

最终训练需要的是 TCP trajectory，因此 Marker covariance 还要通过 T_marker→TCP 传播。

关键原因是 lever arm：marker orientation uncertainty 会转化成 TCP position uncertainty。

例如 marker→TCP 距离约 120 mm，orientation uncertainty 0.5° 时，仅 lever-arm 项就约产生 1 mm 位置误差量级。

最终得到：

Σ_TCP = J_M→TCP · Σ_marker · J_M→TCPᵀ

2.4 Canonical World Persistence：由稳定相机共识维持唯一世界系

世界系不再绑定 robot base，也不要求桌面锚板作为主基准；正常 session 用未移动相机子集把当前 rig 注册回同一个 canonical world。若全部相机都移动，则显式产生新的 world island，而不是让历史轨迹失效或静默改写旧 world。

P0 数据完整性 · P1 Replay 基础
当前场景足以采用 stable-camera consensus：8 台相机中大多数情况下至少有 4 台保持物理不动。数学上 1 台已足以定义一个 6DoF frame；≥4 台的价值在于冗余、故障诊断和对“哪台相机动了”的 robust consensus。因此桌面锚板不再是唯一世界系的主机制。
系统级原则：Trajectory Validity 与 World Continuity 必须解耦。如果 8 台相机全部移动，旧 session 的 T_W_TCP(t)、RPE、T_LR、contact-local trajectory 仍然有效；丢失的只是旧 world 与新 world 之间的绝对 6DoF 关系 T_Wnew←Wold。此时必须新建 world_frame_id，将新旧数据视为两个 coordinate islands。只有跨 session absolute replay / object-world alignment 需要恢复这条变换；不得因为 continuity break 删除、重标或静默重解释历史数据。
理论依据：gauge、canonical frame 与 stable-camera consensus

1）BA gauge 与长期 world frame 是两件不同的事。 BA 为消除 SE(3)+scale 的 gauge freedom，可以临时固定一台相机/一帧 board；这只是优化内部约束。对外落盘的 W 应是一个冻结的 canonical frame，并由历史高质量标定保存 T_WC_i^ref。它可以取桌面友好的方向，也可以沿用现有 world，只要定义冻结且可版本化。

2）“至少 4 台不动”不是唯一性的数学要求，而是可靠性的工程要求。 若某台相机确定没动，它单独就可把新 session 注册回旧 W；但单相机没有自证能力。对候选稳定集合 S，可比较历史与当前 pairwise 外参：

ΔT_ij = inv(T_CiCj^ref) · T_CiCj^cur

若多对相机同时满足 translation / rotation threshold，它们形成稳定 cluster。4 台相机提供 6 个 pairwise constraints，可用 robust voting / maximum-consensus / clique 的方式识别“未移动子集”，并排除被碰动的 camera。

3）新 session 的临时 rig frame 不应成为新 world。 假设当前重标得到临时 gauge S，对稳定相机集合求一个共享刚体对齐：

T_WS* = argmin_T Σ_{i∈S} ρ( || Log( inv(T_WC_i^ref) · T · T_SC_i^cur ) ||²_{Σ_i^-1} )

然后所有当前相机统一写成 T_WC_j^cur = T_WS* · T_SC_j^cur。被移动的相机只更新自己的 T_WC_j；只要稳定 cluster 存在，canonical W 本身不跳。

4）stable-camera consensus 有一个不可观测模式：所有“稳定相机”共同做相同刚体运动。 若它们装在同一个框架且框架整体移动，所有 pairwise T_CiCj 都不变，内部 consensus 无法发现。这不妨碍定义唯一 camera-rig world，但会破坏它相对桌面/地面的绝对稳定性。若这种 common-mode motion 有现实可能，可保留一个与相机架机械独立的固定 ArUco / datum / laser-tracker reference 作为低频 global-drift watchdog，不再承担主标定。

5）移动平台 marker 与 world anchor 的角色必须分开。 左右 FR3 平台上的 ArUco marker 随机器人一起移动，因此它们用于估计 T_WP_L/R，不能反过来定义 W。这使系统形成清晰的三层关系：canonical camera world → mobile platform → FR3 base。

6）全相机移动时不是“旧数据失效”，而是 world graph 断边。 对旧轨迹做任意共同左乘 X∈SE(3)，episode 内 relative motion 与双手相对位姿不变：inv(XT(0))·XT(t)=inv(T(0))·T(t)，且 inv(XT_L)·XT_R=inv(T_L)·T_R。因此 delta/RPE/bimanual/contact-local 等 training-facing 信息不依赖跨 session absolute world continuity。真正不可观的是 T_Wnew←Wold；没有跨移动仍固定的 reference 时，任何算法都不能凭 camera graph 自己恢复它。

7）World 应被建模成可版本化的 pose graph，而不是一个永远只有一个名字的全局变量。 每个 canonical world node 有唯一 world_frame_id；若 continuity 可由 stable-camera consensus 保持，则继续同一 ID；若全部相机移动且无外部 anchor，则创建新 ID。以后若通过固定环境 marker / laser tracker / 其他跨 session datum 恢复 T_Wnew←Wold，只需给两个 world node 增加一条带 covariance 的 registration edge，历史 trajectory 本身无需重建。

8）因此“唯一世界系”与“永不漂移的物理绝对系”不是同一要求。 日常 session 需要的是 canonical world 的连续性；全相机移动时允许 continuity 显式断开。固定 environmental anchor 的职责只是避免/修复这类断边，不能成为历史数据可用性的前置条件。

Phase 5 — Trajectory-level Offline Optimization

离线候选，需 contact A/B

用整段 SE(3) 优化替代因果 EMA，压低 frame-to-frame jitter 和 relative-action error；当前仅作为离线 A/B 候选，必须先证明不会抹平真实 contact motion，再允许接入生产标签路径。

原理与当前实现

逐帧 corner BA 给出的是观测 T_obs,i 及其局部可信度；Phase 5 不再把 XYZ 和 quaternion 分开滤，而是在 SE(3) 上直接解整段轨迹：

min{T_i} Σ_i || Log(T_obs,i-1 T_i) ||²Σ_i-1 + Σ_i || Log(T_i-1T_{i+1}) / Δt_i - Log(T_{i-1}-1T_i) / Δt_{i-1} ||²Q-1
  • 第一项是 measurement factor：让优化结果不要离开 visual BA 观测；后续直接用 Phase 3 的 FIM / covariance 给每帧加权，当前 V1 也支持固定 sigma。
  • 第二项是 constant-velocity prior：惩罚相邻 SE(3) 速度突变，等价于弱 acceleration prior；它只压 jitter，不强迫轨迹变成直线。
  • 整段 batch 求解是零相位口径：第 i 帧同时看过去和未来，不像因果 EMA 只看历史，因此不会产生固定 group delay。
  • 优化变量使用左乘小扰动 T_i = Exp(δ_i) T_obs,i，初值为 δ_i=0；残差使用鲁棒 loss，episode / 大时间间隔处分段，避免跨 episode 或丢帧窗口互相拉扯。

Phase 9 — 双 FR3 Base Registration、Replay Frame 与初始状态

新增主线

两台 FR3 的 base 可以移动，但每次移动后都必须重新建立同一个 metric world 下的几何关系；同时把 first-frame alignment 从“临时技巧”冻结成有语义的 replay protocol。

理论依据：刚体注册、共享 SE(3) 对齐与初始条件

1）Base registration 本质是刚体坐标系注册。 两台 FR3 的运动学都只在各自 base frame 中有意义；要比较双手、做 inter-arm collision 或 absolute replay，必须先把它们放到 Phase 2.4 维护的同一个 canonical metric world：

T_W_TCP,L = T_WB_L · T_B_L_TCP,L，T_W_TCP,R = T_WB_R · T_B_R_TCP,R。

当前硬件上，T_WB 最自然地拆成 T_WP · T_PB：8-camera 测可移动平台的 ArUco rig 得到 T_WP，平台到 FR3 base 的刚体外参 T_PB 预先标定。因此只要平台被移动，旧的 T_WP / T_WB 就不再成立；这不是“软件参数漂了”，而是物理坐标系本身发生了变化。机械定位销只用于减小变化，session registration 负责重新测量剩余偏差。

2）双手不能各自做独立 first-frame alignment。 若左、右分别乘不同的 A_L、A_R，则：

T'_LR = inv(A_L·T_L) · (A_R·T_R)

一般不再等于原始 T_LR = inv(T_L)·T_R，会把双手间距和相对姿态人为改掉。对双手 demo，应求一个共享 T_align ∈ SE(3)，或做带左右 residual 权重的 constrained SE(3) alignment，使公共刚体变换只改变整段动作在世界中的落点，不改变双手内部几何关系。

3）Relative replay 与 absolute replay 测的是不同东西。 shared first-frame alignment 会主动消掉一个常量 world-frame 偏置，因此更适合检验 trajectory shape / short-horizon motion；absolute replay 则固定 T_WB，用于检验真实桌面、物体与 TCP 的空间一致性。两者不能用同一个数字替代。

4）Replay 是动力系统问题，初始条件不只是一帧 pose。 同一 reference trajectory 在不同 q(0), dq(0), gripper(0), object/contact state(0) 下可能产生不同控制瞬态甚至不同接触结果。正式 replay 前的 minimum-jerk / quintic approach，本质上是在连续地把系统送入指定初始状态，并令起始速度/加速度接近可控范围，避免把初始化瞬态误算成轨迹 fidelity。

5）Absolute replay 必须消费 world continuity，而 relative replay 不需要。 若 demo 与当前 FR3 session 属于不同 world_frame_id 且两者之间没有显式 registration edge，则 absolute replay 必须拒绝或降级；但 shared first-frame relative replay 仍可进行，因为它只依赖 episode 内/双手内部几何。这个判据必须由 metadata 自动决定，不能靠操作者记忆。

机械建议：不要求把两台 FR3 永久固定在地面；更符合当前场景的是平台内刚性固定 + 平台移动后可靠锁止 + session registration。平台 ArUco rig 与 FR3 base 必须共刚体；只要平台被移动，旧的 T_WB_L、T_WB_R、inter-arm collision scene 与 absolute replay transform 就全部失效。
9.1 Session-level Dual-base Registration：移动平台 ArUco rig

首选链路：左右 FR3 所在移动平台各自定义刚性 platform frame P_L / P_R，平台上布置多个已标定 ArUco marker；8-camera 在 canonical world W 下直接估计平台 pose：

T_WB_L = T_WP_L · T_P_LB_L，T_WB_R = T_WP_R · T_P_RB_R

  • T_WP_L/R：每次平台移动后由 8-camera 重测；T_PB：FR3 相对平台的固定安装外参，只有机器人从平台拆装/安装结构变化时才重标。
  • 平台 marker 应视为一个分布式刚体 layout：保存 platform_marker_layout.json，所有可见 marker corners 联合求一个 platform pose；避免“每个 tag 独立 PnP 后再平均 pose”。较大的 marker baseline 还能显著加强 base orientation 约束。
  • marker 必须贴/装在与 FR3 base 共刚体的承力结构上，避免薄钣金、塑料罩或可变形盖板；否则测到的是 panel motion，不是 base motion。
  • 每 session 求 T_WB_L、T_WB_R 与 T_BL_BR = inv(T_WB_L)·T_WB_R；移动任何一台平台后 registration 自动失效并重算 collision scene。
  • replay 前后可持续观测 T_WP(t)，把平台滑动/被碰撞作为 base-motion fault；输出 pose covariance / repeatability，并传播进 inter-arm collision safety margin 与 absolute replay error budget。
  • FR3 FK 可用于求/检查 T_PB，但不能单独认证 absolute base pose；平台 ArUco 的作用是“把可移动机器人注册进 world”，不是定义 world 本身。
9.2 两种 Replay Mode

Relative / trajectory-fidelity mode：允许 first-frame alignment，但双手不能各自独立吸收一个 SE(3)。应求一个左右手共享的 T_align（或带小 residual 的 bimanual constrained alignment），共同作用到左右 demo，从而尽量保持 T_LR。

T_cmd,L/R(t) = T_align · T_demo,L/R(t)

Absolute / task-fidelity mode：只使用 session 标定的 world↔base 关系；禁止 per-episode 自由平移/旋转把 world registration error 吃掉。

9.3 Initial State 不只是 EE first pose
  • 初始状态至少记录：左右 TCP pose、q / dq、gripper opening、object pose、contact state；对于已夹持物体的 demo，只对 EE first frame 对齐是不够的。
  • 正式轨迹前增加 smooth approach（minimum-jerk / quintic），到 replay start pose 后速度接近 0，再开始计入 benchmark，避免启动瞬态污染 p95/RPE。
  • 记录 initial_alignment_residual，不要用 alignment 把异常静默吃掉。
Gate：session registration 通过；左右共享的 alignment / absolute frame contract 可复现；初始 pose、gripper、object/contact state 满足任务要求后，才允许进入 retarget。

Phase 10 — Bimanual Collision-aware Retarget & Executability

新增主线

不再做“左轨迹单独 IK + 右轨迹单独 IK”，而是寻找一条同时保持任务语义、双手关系、关节连续性与安全间距的联合双臂轨迹。

理论依据：7DoF 冗余、双臂约束优化与碰撞安全裕量

1）TCP trajectory 并不唯一决定 FR3 的 joint trajectory。 FR3 是 7DoF，而一般末端位姿任务只有 6DoF，因此存在至少 1 维局部冗余。速度层可写成：

q̇ = J⁺ ẋ + (I − J⁺J) z

第一项完成 TCP 运动，第二项位于 Jacobian null-space，可用于远离 joint limit、奇异位形和另一只机械臂。若逐帧独立 IK，只约束 T_TCP(t) 而不约束 null-space 连续性，就可能出现 elbow branch 跳变，因此必须把整段轨迹作为连续优化问题处理。

2）双臂 retarget 是一个带任务层级的约束优化。 两只手分别误差很小并不保证双手协作正确；真正的协同变量是：

T_LR(t) = inv(T_L(t)) · T_R(t)。

对于夹持、拉伸、装配等任务，T_LR 与 contact geometry 往往比单手 world-space pose 更接近任务不变量。因此优化器应允许利用 joint/null-space 先避碰，必要时才小幅修改 TCP，并对 T_LR / contact residual 施加更高权重。

3）“无碰撞”不是足够条件。 几何模型中的 signed distance 只代表名义模型。真实系统还有 base registration、TCP calibration、link geometry、controller tracking 等不确定度，因此应要求：

d_min > d_safe，其中 d_safe 应至少覆盖两臂相对位置不确定度与动态 tracking tail。

更保守地，可把左右末端/连杆不确定度近似传播到相对距离方向；只有当 nominal clearance 明显大于该方向的高分位 uncertainty 时，simulation collision-free 才能转化成真机安全置信度。

4）Geometry path 与 timing 要解耦。 一条路径可写成 T(s)，执行速度由 s(t) 决定。同一几何路径在不同 timing 下会产生完全不同的 q̇/q̈/jerk、控制误差与碰撞制动裕量。因此 retime 不是“改了动作形状”，但会改变动作动力学；必须把 original / retimed / executed timing 分开保存。

5）Retarget 后直接改 UMI action label 会产生监督偏差。 UMI 图像记录的是原始手真实位于 T_demo 时的视觉状态；若只把 action 改成明显不同的 T_retarget，输入 observation 与监督 action 不再来自同一个物理状态分布。小改动可作为可行性近似，但大改动更适合作为 reject/metadata，或通过 FR3 真机 replay 重新采 embodiment-native observation-action pair。

min E = E_L + E_R + λ_LR E(T_LR) + λ_smooth E_smooth + λ_margin E_margin + λ_collision E_collision
对于双手接触任务，推荐优先级：contact geometry > bimanual relative pose T_LR > single-hand absolute pose > joint posture。
联合约束
  • 连续 IK / trajectory optimization：避免 7DoF 每帧独立 IK 的 elbow / null-space branch 跳变。
  • joint position / velocity / acceleration / jerk limit，manipulability / singularity margin。
  • left/right self-collision、inter-arm link-link、gripper-gripper、arm-opposite-gripper、table/environment collision。
  • collision-free 不够：要求 d_min(t) > d_safe；d_safe 由左右 tracking uncertainty、base-registration uncertainty、动态误差与模型 margin 倒推，而不是随手设一个常数。
  • 把原始 timing 拆成 geometry path T(s) 与 time parameterization s(t)；必要时 retime，但必须保存 original / retimed / executed timestamp。
Retarget 允许改多少、训练标签怎么处理
  • 永远保存三套轨迹：demo_raw、retarget_reference、后续 executed_robot；禁止覆盖原 demo。
  • 输出 retarget_translation/rotation_p50,p95,max、bimanual_relative_retarget、contact-window residual、min_interarm_clearance、joint-limit/singularity margin。
  • free-space 可以允许更大的微调；contact window 必须更严格。具体阈值由 Phase 12 physical replay / task success 反推，不先拍脑袋冻结“1 mm / 5 mm”。
  • UMI observation + UMI action 的 BC/VLA：默认仍用 demo_raw 作为 supervision，retarget 主要作为 feasibility / quality metadata。若大幅 retarget 后直接替换 action label，会制造 observation-action mismatch。
  • FR3-native policy：更优路径是 retarget → 双 FR3 真机 replay → 重新采 FR3 observation + actual action，形成 embodiment-native 数据，而不是把 UMI 图像硬配 retarget label。
Gate：连续可执行、无碰撞、clearance 高于不确定度驱动的 safety margin；retarget distortion 与 T_LR distortion 均在任务允许范围内。只通过 IK 但需要大幅改轨迹的 episode 不应默认为 training-valid。

Phase 11 — FR3 Intrinsic Physical Replay Metrology

先测机器人本身

在掺入 UMI、retarget 和复杂 contact 之前，先量清楚 FR3 本身对已知 Cartesian reference 的真实物理 tracking 能力，得到 replay error budget 中的 robot/controller 项。

理论依据：Repeatability ≠ Absolute Accuracy，为什么必须独立测 FR3 Physical Motion

1）机器人“重复到同一点”与“到达真实空间中的正确点”是两个指标。 repeatability 衡量多次执行同一命令后的离散程度；absolute accuracy / displacement accuracy 还受到 link 参数、joint zero、base frame、tool/TCP、载荷变形和控制误差影响。因此即使 FR3 内部 FK 每次都几乎相同，也不能据此推出真实 TCP 的 30 mm 位移误差同样很小。

2）内部闭环误差和外部物理误差要分账。

e_internal = T_cmd⁻¹ · T_FK 主要反映 controller + robot model 的内部一致性；

e_physical = T_cmd⁻¹ · T_GT 则把真实机械结构、tool/TCP、base、负载/柔顺性等都包含进来。若两者明显不同，差值本身就是 robot-model / mechanical / registration 系统误差的证据。

3）为什么先做简单基准再做 UMI replay。 End-to-end replay 中同时混有 recording、registration、retarget、collision avoidance、controller 与 contact。先用已知的 10/30/50/100 mm、旋转和几何轨迹激励 FR3，相当于系统辨识里的“隔离变量”：先测出 robot/controller 自身的 bias、repeatability、速度依赖和 workspace dependence，后续 UMI replay 才能做误差归因。

4）动态误差通常依赖速度/加速度，而不是一个固定常数。 可把真实 tracking 误差粗略理解为：

e_robot = e_static(q, payload) + e_dynamic(q, q̇, q̈, controller) + e_timing。

因此 benchmark 必须覆盖典型 workspace、姿态与 demo speed 分布；只做低速静态 30 mm 平移不能代表真实 manipulation replay。

5）独立 GT 的意义是打破共同模型误差。 FR3 FK 与 controller 都依赖同一机器人模型，二者互相比可能共同“相信”同一个错误。外部 6DoF laser / optical tracker 使用不同测量原理，可作为更独立的 physical reference；若只有单点 XYZ，则只能认证位置，不能完整认证 orientation。

最小 Benchmark Matrix
  • 平移：X/Y/Z 的 ±10 / ±30 / ±50 / ±100 mm；重复 30–50 次，先低速静态，再扫 demo typical / p95 speed。
  • 旋转：roll/pitch/yaw 代表性小角度；再做 line / circle / figure-8 / coupled SE(3)。
  • 先单臂分别测，再双臂同时运动；双臂时额外看 controller interaction、最小 clearance 与 T_LR。
  • 每次同时记录 T_cmd、FR3 T_FK、independent T_physical_GT。
必须分开两个误差：
e_internal = error(T_cmd, T_FK)：控制器/模型内部一致性；
e_physical = error(T_cmd, T_physical_GT)：真实 TCP 是否走到命令位置。
只有后者能回答“命令左移 30 mm，实际物理 TCP 到底走了多少”。
Gate：建立 position/orientation × speed × workspace 的 p50/p95 map，并给出 FR3 physical tracking 的预算；若基础 30 mm relative move 已明显超过 1–2 mm 级，应先解决 TCP、tool calibration、base registration 或 controller，而不是继续归因于 UMI GT。

Phase 12 — UMI → Dual-FR3 Physical Replay Benchmark

最终闭环

最终比较的是 UMI 实际录到的双手 TCP 与双 FR3 实际执行出来的双手 TCP，而不是 demo vs command、也不是 command vs FK。

理论依据：End-to-End Replay Fidelity 为什么必须分层评价

1）最终 replay 误差是串联系统误差，不等于某一阶段的 3 mm。 概念上：

demo physical motion → recording GT → frame registration → retarget/retime → robot command → physical execution → replay GT

每一段都可能引入 bias、随机误差或时延。因此“录制 GT p95 ≤3 mm”只能认证 recording subsystem，不能推出真实 FR3 replay 也 ≤3 mm。最终必须直接比较 T_demo 与独立测得的 T_actual。

2）Absolute error 与 relative error 对系统误差的敏感性不同。 常量 world/base 偏置会显著影响 global APE，但在 first-frame-aligned relative motion 中大部分被消除；相反，trajectory deformation、控制 lag、局部速度误差会保留在 RPE 中。因此两者组合才能区分“整段放错位置”和“动作本身执行变形”。

3）双手任务需要显式看 differential / relative error。 若左右同时产生同方向 common-mode 2 mm 偏差，单臂 APE 都不好看，但 T_LR 可能几乎正确；若左右分别向相反方向偏 2 mm，则双手间距可错 4 mm。对协同 manipulation，后者通常更危险，所以必须单列 bimanual fidelity。

4）Contact-local metric 的权重高于自由空间全局平均。 Manipulation 的任务约束在接触附近急剧增强：抓取边缘、插入、双手夹持等对毫米级几何更敏感。长时间自由空间运动会稀释少量但关键的 contact error，因此 benchmark 应按 contact window 单独统计，而不是只报全 episode mean/p95。

5）Timing error 可转化为空间等效误差。 若 reference 与 GT 有时间偏差 Δt，在局部速度 v, ω 下会产生约 v|Δt| 与 ω|Δt| 的假空间误差。双臂 T_LR 对左右不同步尤其敏感，所以 independent replay GT 必须同步或严格时间对齐。

6）Training-valid 与 replay-certified 分级是可扩展性要求。 真机 replay 是昂贵测量，不能现实地覆盖每条大规模数据。因此 training-valid 负责判断“数据质量足够且双 FR3 模型上可执行”，replay-certified 负责用抽样/任务族 benchmark 认证“该数据分布在真实机器人上也能保持 fidelity”。两者必须分开命名，避免把抽样认证错误外推到整个数据集。

UMI physical motion ↓ 8-camera GT T_demo,L(t), T_demo,R(t) ↓ shared alignment / absolute registration ↓ bimanual retarget + collision constraints T_ref,L(t), T_ref,R(t) ↓ dual-FR3 control FR3 physical motion ↓ independent 6DoF replay GT T_actual,L(t), T_actual,R(t) ↓ relative / absolute / bimanual / contact replay metrics
必须报告的 6 组指标
  1. Initial alignment residual：正式 replay 开始前左右位置 / 姿态 / gripper / object-state 偏差。
  2. Relative trajectory fidelity：shared first-frame alignment 后的 shape error + 40/100/400 ms/1 s RPE。
  3. Absolute world-space replay error：固定 session registration，不允许 episode alignment 吃掉误差。
  4. Bimanual fidelity：T_LR^demo vs T_LR^actual，尤其双手夹持 / 协同接触窗口。
  5. Contact-local error：contact 前 / 当下 / 后窗口的位置、姿态、切向位移；优先级高于全程自由空间平均误差。
  6. Timing / retime fidelity：original timing、retimed reference、executed timing 与 motion-equivalent error。
Dataset 进入训练的两级口径

Training-valid：tracking ∧ qc ∧ bimanual ∧ dual_fr3_executable。这是可规模化的数据准入，不要求每条都真机 replay。

Replay-certified：在上述基础上，额外通过独立 physical replay benchmark。可按 episode、任务族或分层抽样做认证，不能把少量 benchmark 的 pass 静默扩展成“全数据都已物理认证”。

FR3-native 数据：如果真机 replay 时同步重新采 FR3 相机 / proprioception / gripper / force/tactile，则保存 executed_robot 作为新的 robot-native demonstration；这与“修改 UMI 原始 action label”是两类数据。

Gate：分别冻结 recording_accuracy、relative_replay、absolute_replay、bimanual_replay 与 contact_replay；只有独立 physical GT 支持时才宣称“FR3 replay 达到 3 mm-class”。
