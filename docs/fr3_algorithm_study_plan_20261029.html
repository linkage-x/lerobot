通用背景（每次先贴给 ChatGPT）

背景：我在一台 Franka FR3 机械臂上做抓取任务：夹起桌上的一根 peg，再插进孔里。孔和 peg 之间的间隙只有约 2.5 mm，没有倒角。
策略模型是 LeRobot 里的 pi0.5：PaliGemma（SigLIP 视觉塔 + Gemma 2B）编码图像、文本和状态，作为前缀；一个 Gemma 300M 的 action expert 用 flow matching 生成 50 步的动作块，推理时去噪 10 步。
训练方式：只在 action expert 上训 LoRA（r=64，alpha=64），SigLIP 和 PaliGemma 都冻结。
动作和观测：
- 动作是世界坐标系下、相对上一条命令的末端位移（delta_ee_from_prev_cmd），加上夹爪，频率 30 Hz。
- 状态和动作都用分位数归一化。状态被离散成 256 档，写进文本提示。
- 有两个相机：腕部（ee）相机和侧面相机。
训练数据有三类：
- 人用 SpaceMouse 示教；
- 策略自己跑的轨迹；
- 一个脚本专家（grasp funnel，状态机：搜索→对准→下降→合爪）的纠正。
策略自己走过的步骤，用这个专家程序离线重标，相当于离线 DAgger。
实机推理在一台 5090 上跑，机器人侧在另一台装实时内核的 NUC 上，块与块之间用 Real-Time Chunking 衔接。
我会 Python 和 PyTorch 基础，想补算法细节。请用中文回答：先讲直觉，再给公式，最后给一个能在 CPU 上跑的小例子。不确定的地方请直说。

M1 · 模仿学习的分布偏移与 DAgger

P1

为什么跟你有关：

  • 10-22 发现，corrective-153 视图里 43% 的训练帧是旧策略自己没纠正过的步骤。模型因此学会了“直接往下走”：它看得到 peg 的方向，但只横移约 1 mm，而标签要求横移约 13 mm。
  • funnel_relabel 就是针对这个问题的离线 DAgger。
  • R6 的教训是另一面：标签规则本身（偏离超过约 8 mm 先抬起），也会被模型忠实地学走。

必会概念

  • 行为克隆就是监督学习，但测试分布由模型自己决定。只要错了一步，模型就会走到训练里没见过的状态，误差会累积。经典结论：误差上界从 O(Tε) 恶化到 O(T²ε)。
  • DAgger：状态取自学习者实际走到的地方，标签由专家给出。成立的前提是：在学习者走到的每个状态上，专家都能给出正确动作。
  • 为什么能离线重标：funnel 是“状态 + peg 位置”的程序，所以可以对录下的任意一帧，模拟出“专家此刻会怎么做”。人类专家做不到这一点。
  • HG-DAgger / 人类接管：没被人控制的维度不能当专家标签。比如接管时夹爪保持策略最后一次的输出，这个维度上记录的仍是学习者自己的动作，所以要用 intervention_unsupervised_action_dims 把它从损失里去掉。
  • 多模态动作：同一个状态下有好几种合理动作时，MSE 回归会把它们平均成一个“中间值”。这是选用生成式动作头的原因，见 M4。

对应代码

  • tools/fr3/funnel_relabel.py：开头的 docstring 写清了重标的全部理由，是最好的教材。
  • tools/fr3/grasp_funnel.py：专家状态机。
  • src/lerobot/policies/pi05/configuration_pi05.py：intervention_unsupervised_action_dims 的注释。
  • tools/fr3/dagger_takeover.py：人类接管的实现。

自测题

重标时，为什么用“funnel 从这一帧模拟出的动作块”，而不是录下来的未来动作？

录下来的未来是策略自己走的，本来就没有纠正。另一种做法是每一步都标成“朝 peg 移动”，但动作块仍取自录下的未来，那么同一个动作块里每一步都朝同一个 peg 修正，修正量会被重复叠加。所以要用专家从这一帧的命令出发、按运动学模拟出完整的动作块。

R6 补了一批“低位、偏心”的数据，为什么反而在实机上更爱抬起、反复重试、最后超时？

funnel 的规则是：偏离超过约 8 mm 就先抬起，再对准。新增的低位帧里，抬起标签在成功的录制中约占 67%，在没合手的录制中约占 77%，偏离超过 10 mm 的帧 100% 是抬起。模型忠实地学会了这个规则。数据越多，这个行为越强。这就是“标签规则的问题”，而不是“数据太少”。

什么样的专家无法做离线 DAgger？

两类：一是专家的决策依赖录制时拿不到的信息（例如人眼看到、但没被记录的东西）；二是专家本身不是状态的确定函数（例如人类示教）。这两种情况只能在线采集：让人在机器人上实时接管。

M2 · 动作与观测的表示

P1

为什么跟你有关：

  • 录制时如果按 200 Hz 控制节拍取增量，会让策略慢 6.7 倍。
  • 合爪时，实测位姿相对命令有一个固定偏移，约 (+3.8, −1.8, −3.2) mm。所有 gain 都要以它为中心计算。
  • R6c 必须沿用 R4 的 stats.json。
  • 拷贝视图后，裁剪源尺寸在 NUC 上被解析错过，导致试验出错。

这些都属于“表示”的问题。

必会概念

  • 三种动作表示：绝对位姿、相对当前实测位姿的增量、相对上一条命令的增量（本仓库用最后一种）。它们在积分漂移、跟踪误差和延迟下的表现各不相同。
  • 增量的时间尺度必须等于策略查询的间隔，也就是一个数据帧（30 Hz）。所以增量在离线处理时由相邻帧做差得到。
  • 动作块（chunk）：50 步 × 1/30 s ≈ 1.67 s。模型一次输出整块，执行时只用一部分，见 M6。
  • 分位数归一化：把 q01–q99 映射到 [−1, 1]。和 mean/std 相比，它不受少数大动作的影响。代价是超出范围的值会被压缩，各维度在损失里的权重也随之改变（见 configuration_pi05.py 的注释）。
  • 状态怎么进入 pi0.5：先归一化到 [−1, 1]，再离散成 256 档，写进文本提示 State: …。由此可以推出状态的有效分辨率。
  • action_loss_weights：本仓库用的是 [1, 1, 1, 0.2, 2]，意思是按维度给 flow matching 的损失加权。

自测题

finetune 时，如果用新数据重新算了 stats.json，会出什么问题？

同一个物理动作（比如向 +x 移动 1 mm）会对应另一个归一化数值。从旧 LoRA 继承下来的“特征 → 归一化动作”映射整体错位，开头几千步都在纠正这个错位，而不是在学新数据。所以 R6c 复制了 R4 的视图，沿用 R4 的 stats。

为什么 gain 要用 cx = ox + 3.8、cy = oy − 1.8，而不是直接用 ox、oy？

合爪时，手臂会稳定在离命令一个固定偏移的位置。“正好对准 peg”对应的实测偏移不是 0，而是约 (−3.8, +1.8) mm。不先减掉这个偏移，就会把一个系统性常量当成模型的误差。

状态离散成 256 档，对“读位置”意味着什么？

如果某个轴的 q01–q99 范围是 R mm，那么每档约为 2R/256 mm 以上，因为 [−1, 1] 被分成了 256 份。这个精度足以粗定位，但无法分辨毫米级的对准，所以毫米级信息只能来自图像。这和 10-29 交换探针的结论一致：模型读的是腕部图像，没有走“位置捷径”。

M3 · pi0.5 的模型结构

P1

为什么跟你有关：你冻结了 SigLIP 和 PaliGemma，只训 action expert，所以训练只能改变“冻结特征 → 动作”的映射。10-29 的分诊就是按这个结构来分的，先后回答了两个问题：

  • 冻结的特征里有没有 x 信息？有，线性读出误差约 1.8 mm。
  • 映射能不能泛化到新场景？这才是缺口所在。

必会概念

  • 前缀：每个相机的图像经 SigLIP 变成 16×16 = 256 个 patch token，再经 multi_modal_projector 投影到 Gemma 的宽度。之后接上文本和离散状态 token。前缀内部是双向注意力。
  • 后缀：action expert 处理 50 个带噪声的动作 token。它可以看前缀，前缀看不到它（块状因果 / prefix-LM 掩码）。两个 Transformer 逐层共享注意力，但权重彼此独立。
  • 时间步注入：pi0.5 用 adaRMSNorm，把 flow 的时间 t 作为条件，调制 action expert 每一层的归一化。pi0 的做法不同：把 t 拼进动作 token。
  • KV cache：前缀只计算一次，10 步去噪都只跑 action expert，所以推理很便宜。
  • pi0 与 pi0.5 的差别：状态的表示方式（连续 token 还是离散文本）、时间步的注入方式，以及训练配方（知识隔离 / 离散动作的联合训练）。

对应代码

  • src/lerobot/policies/pi05/modeling_pi05.py：embed_prefix、embed_suffix（约第 684 行，其中有 adaRMS 的条件）、forward、sample_actions。
  • src/lerobot/policies/pi_gemma.py：双 Transformer 共享注意力的实现。
  • tools/fr3/fr3_train_il_policy.py：--lora 的 target-modules 正则决定了哪些层可训练。

自测题

在“冻结视觉、只训 action expert 的 LoRA”的设定下，哪类错误是加再多数据也修不好的？

M4 · Flow matching：动作是怎么“生成”出来的

P1

为什么跟你有关：训练 loss（比如 R6c 第 50 步的 0.055）看起来“很小”，但它几乎不能用来比较策略的好坏。离线探针每帧要采样两次再取平均，也是因为模型的输出本来就带随机性。这两点都来自 flow matching 本身。

必会概念（本仓库的约定：t = 1 是纯噪声，t = 0 是动作）

训练:  ε ~ N(0, I),  t ~ 0.999·Beta(1.5, 1) + 0.001
       x_t = t·ε + (1 − t)·a              # 噪声和真实动作块的线性插值
       u   = ε − a                        # 目标速度（沿直线从 a 指向 ε）
       loss = ‖v_θ(x_t, t, obs) − u‖²     # 按维度乘 action_loss_weights
推理:  x_1 = ε;  dt = −0.1
       重复 10 次: x ← x + dt · v_θ(x, t, obs)   # Euler 积分到 t = 0
  • 和扩散模型（DDPM）的关系：两者是同一族方法。flow matching 的路径是直线，目标更简单，需要的步数更少。
  • Beta(1.5, 1) 的用意：密度朝 t → 1 增大，也就是把训练重点放在高噪声端。在高噪声时，动作主要由观测决定，这一段最难学。
  • 能表示多模态：不同的噪声样本会走到不同的“模式”，而不是被平均到中间。
  • loss 有不可约部分：u 里含有随机的 ε，所以就算模型完美，loss 也不会是 0。比较两个模型时，要看下游指标。

对应代码

  • modeling_pi05.py：sample_beta（约第 101 行）、sample_time、forward（约第 739–784 行：x_t、u_t、MSE）、sample_actions（约第 828–860 行：Euler 循环和 RTC 钩子）、apply_action_loss_weights。

自测题

如果把推理步数从 10 改成 1，会发生什么？

一步 Euler 相当于直接用 x_1 − v 估计动作，结果会接近条件均值，多模态被抹平。轨迹会更“平均”，在需要二选一时（比如从左边还是右边绕）就容易出问题。路径越直，单步的误差越小。这正是 rectified flow 和一致性模型改进的方向。

为什么离线探针每帧要用不同的随机种子采样两次再取平均？

输出依赖初始噪声 ε。单次采样里，噪声带来的方差会混进 gain 估计。取平均能降低方差，两次之间的差异还可以顺带估计这部分噪声有多大。

M5 · LoRA 与微调策略

P2

为什么跟你有关：这几轮里有两种做法：

  • 从基础模型重训：R4、R6。
  • 从 R4 用小学习率继续微调：R7b、R6c。

R6c 想检验的问题是：微调能不能在学到新数据的同时，保住 R4 合手的行为。理解遗忘和可塑性的权衡，才能读懂结果。

必会概念

  • LoRA：W' = W + (α/r)·B·A。B 初始化为 0，所以训练开始时模型和原模型完全一致。r = α = 64，缩放系数为 1。
  • 可训练参数：27.9M，只占全模型的约 1%。容量够不够，看的是数据覆盖，而不是参数量。
  • --init-adapter 微调：
    • 使用新的优化器，Adam 的一阶、二阶矩都清零；
    • 学习率 1e-5，warmup 100 步；
    • 余弦衰减到 1e-6，共 15k 步。
    学习率小、步数少会遗忘得少，但新数据也可能学不进去。
  • 数据比例：R6c 有 556 条 episode，其中新数据 49 条。均匀采样时，新数据只占约 9% 的梯度。上采样（重复或加权）是一个独立的旋钮。
  • epoch 估算：步数 × batch size ÷ 训练帧数。数值远大于 1 时，要警惕记住具体位置（seed 0 的 4/10 就是这个原因）。
  • 选 checkpoint：每 2.5k 步存一次。用离线指标挑，不用 loss。train_gate.py 会在训练过程中自动探测每个 checkpoint。

对应代码

  • tools/fr3/fr3_train_il_policy.py：--lora*、--init-adapter、view_training_episodes。

M6 · 推理与执行时序：动作块与 RTC

P2

为什么跟你有关：离线探针用的是 inference_delay=0，也不带上一个动作块。实机上则有网络和推理延迟，还有 RTC 引导。两者测到的不是同一个东西。理解这层差别，才知道离线结果在实机上该打几折。

必会概念

  • 动作块（ACT 的思路）：一次预测 H 步，执行其中一部分再重新规划。重新规划的次数少了，复合误差也就少了。代价是块内开环，对新出现的偏差反应慢。
  • 块与块的衔接：推理要花 d 步时间。这期间机器人还在执行旧块，新块的前 d 步早已“过时”，直接拼接会产生跳变。
  • Real-Time Chunking（Black 等，2025）：把上一块中已经承诺执行的那部分当作 inpainting 约束，在每一步去噪时引导新块和它一致。
    • 引导权重随 t 变化，并被 max_guidance_weight 截断；
    • 前缀权重按调度（LINEAR）逐步衰减；
    • execution_horizon 决定每块执行多少步再重新规划。
  • AMP：训练和推理的精度（bf16）要一致。use_amp 不一致曾让 NUC 握手失败。

对应代码

  • src/lerobot/policies/rtc/README.md、modeling_rtc.py（denoise_step，大约在第 116–230 行）、configuration_rtc.py。
  • tools/fr3/fr3_policy_server.py：搜索 rtc_* 参数和 warm forward。
  • tools/fr3/policy_remote.py：NUC 侧的客户端。

自测题

离线 gain 是 0.67，实机上对偏移的修正可能更大还是更小？

多半更小，至少会更慢。实机的新块前缀被上一块约束住了（上一块还没开始修正），再加上推理延迟，修正会晚几步才生效。离线探针测的是“不受约束的整块”，相当于上限。

execution_horizon 调大或调小，各有什么代价？

调大：重新规划次数少，动作平滑，但对新偏差反应慢。调小：反应快，但推理负载高，衔接次数多，抖动风险更大。

M7 · 专家、标签与数据配方

P1

为什么跟你有关：这个项目每一次真正的进展，都来自数据或标签：

  • R4 靠重标，把合爪时的 dx 从 −8.5 mm 拉到了 +1.3 mm；
  • R6 新增的数据把离线 x gain 提高了一倍，但实机变差了；
  • “要不要多录”这类决策，答案也全在这里。

必会概念

  • 专家的设计就是策略的上限，也是策略的“性格”。标签是程序生成的，所以规则可以改，改完可以重标，不需要重新录制。但规则改动会影响所有用它重标的数据，需要你亲自批准。
  • 覆盖比数量重要：训练里低位帧占 26%，大多已经对准（p90 1.9 mm）；实机 rollout 里 57% 的帧落在窗口外。这是状态分布不匹配。
  • “该多录还是该改标签”的判据：
    • 模型已经接近标签（gain 约为标签的 0.85），但实机行为不好 → 问题在标签。
    • 模型在训练集上贴合，在新场景上差 → 问题在覆盖或泛化。
  • 坏标签：peg 倒下（113 次里有 5 次），funnel 照样会给出“正确”动作，但物理上是错的。这类数据需要过滤。
  • 保留集要按 episode 或按场景划分：同一条 episode 内的帧高度相关，按帧随机划分会泄漏。用 gui_annotations.json 里的 includeInTraining: false 来标记。
  • arm A 与 arm B：A 是策略自己完整地跑一次，保留失败的那些，失败的部分再重标；B 是策略接近之后，由 funnel 接管。两者覆盖的状态分布不同。

M8 · 离线诊断工具箱

P1

为什么跟你有关：机器人时间是最贵的资源。R4 到 R6c 的每一个决定，都是先离线验证再上实机。掌握这套方法，你就能自己判断一个 checkpoint 值不值得上机器人。

必会概念

  • gain（增益）：gain = −Σ(c·m) / Σc²，是过原点的最小二乘，意思是“每毫米偏移，模型修正多少毫米”。1 表示全部修正，0 表示完全不理会。
    • 只取 |c| 在 3–10 mm 的帧：太小的偏移会被噪声淹没，太大的偏移会触发“先抬起”的规则。
    • 对标签本身也算一遍 gain 作为参照，看的是“模型 / 标签”的比值。
  • 线性探针：在冻结特征上做岭回归，读出偏移量，回答“信息在不在”。
    • 必须按 episode 分组做交叉验证，否则同一条 episode 的相邻帧会泄漏。
    • alpha 用内层交叉验证来选。
  • 反事实交换探针：只换腕部图像、只换侧面图像、或只换状态，看动作的变化应归因到哪个输入。10-29 的结论：只有腕部图像在起作用，没有走位置捷径。
  • 按 episode 的 bootstrap：以 episode 为单位重采样，得到置信区间。比较两个模型时，在同一批帧上做配对差值的 bootstrap，比两个独立的置信区间灵敏得多。
  • 分组：训练集、保留集和新场景要分开报告。“训练集好、新场景差”就是泛化缺口。

对应代码与数据

  • tools/fr3/holdout_probe.py、tools/fr3/close_probe.py、tools/fr3/train_gate.py

M9 · 实机实验设计与小样本统计

P2

为什么跟你有关：你经历过的几种情况，都需要这部分知识来判断：

  • R5 的 9/10 对 5/10 并不显著（p = 0.14），但机制指标显著（p = 0.03）；
  • R6 的 A/B 在第 16 次就停了，靠的是配对 6:0 的不一致对；
  • seed 0 的 4/10 其实是记住了位置。

要分清哪些结论可信、下一次要跑多少次，就要懂小样本统计。

必会概念

  • 二项比例的置信区间：用 Wilson 或 Clopper-Pearson。10 次试验的区间非常宽（9/10 的 Wilson 95% 区间约为 0.60–0.98）。
  • 配对设计：同一个 peg 位置，两个 checkpoint 各跑一次。用 McNemar 精确检验，只看不一致的那几对。6:0 时 p = 2 × 0.5⁶ ≈ 0.031。
  • 机制指标往往比成功率灵敏：比如合爪时的 |dx|，用 Wilcoxon 符号秩检验。前提是这个机制确实决定了成功与否。
  • 功效分析：想检测从 50% 到 70% 的提升，需要的试验次数远多于 30 次。要在开跑之前就算好。
  • 一次只变一个量，否则结果无法归因。
  • 偏差来源：
    • 看到数据再决定什么时候停（可选停止）；
    • 挑 seed；
    • 自动判定不等于真值（R3 里自动判为插入的 24 次中，有 6 次其实没插进）；
    • 孔位会缓慢漂移。
