为什么信 2 mm 而不是反过来：【2026-08-24 第三条腿已换成干净的那一条。】此前这里用的是 2.22 mm，并自认「有已知的悲观来源」；实测拆开后它确实不可用，但原因不是覆盖不足，而是那两次解算换掉了解算脚本本身（内参只占 0.69 mm）。换成同解算器下的两轮独立挥板 2.54 mm后论证反而更强：2.10 mm 完全不涉及那次解算（对着现行生产标定测的），从像素残差折算的 1.7–1.9 mm 又是第三条独立路径——三条落在同一量级，其中两条不共享任何薄弱环节。反过来要信 0.2 mm，就得解释为什么 BA 在真实视频上的重投影残差是 2.2 px 而不是 0.2 px；目前没有这个解释。
0.244 mm 并未作废，只是回答的问题更窄：「给定这一套外参，相机之间对棋盘角点自洽到 0.24 mm」—— 这说明相机布局与几何有能力做到亚毫米，Level 1「不要加相机」的结论依然成立。 0.244 → 2.1 的差额只有两个去处，且可分开：换一整轮标定采集（2026-08-24 实测：两轮独立挥板 pairwise p50 3.16 mm、标签 2.54 mm）与换目标 （ChArUco 亚像素棋盘交点 → 手持 rig 上的 AprilTag marker 角点）；既然第一项已能解释大部分，第二项不需要背太多。

两条可复用的判据（本页因为它们纠正过三次结论）：
① 内参 vs 外参：内参外推误差必然随像半径增长、且随可见 marker 数收敛。cam_09 两条都不满足（离轴 11°→41° 上 29.8/30.1/33.8/36.5 mm 基本平；1/2/3/≥4 个 marker 上 34.7/30.8/33.7/30.3 mm 完全不收敛），同批数据里 cam_07 随 marker 数为 9.2/3.6/2.6/2.4 mm、cam_06 为 8.6/5.6/5.7/5.1 mm，收敛得干干净净。所以 cam_09 是外参错，重标它的内参不会改善。
② 测外参错误要把 rig 位姿钉死在其余相机的共识上。cam_09 自己 PnP 的 RMSE 一直是 0.76 px（那是让 rig 位姿自由拟合自己的角点），钉死后同一台是 36.57 px。「自己拟合自己」的残差对外参错误完全免疫。必须做对照（每台都解一遍），否则分不清在测误差还是在吸收误差。

2026-08-24 内参这个自由度已定量：不是拟合噪声，是「哪一轮挥板」。方法：外参角点检测、解算器、gauge、选帧策略全部钉死，唯一变量是内参用哪些挥板帧重拟；基线先复现无误（RMSE 0.2437 px，与磁盘上的 calib_final/extrinsics_fisheye 的 T_ref_cam 逐位一致，pairwise 差 0.000 mm）。结果按「独立性放开的程度」排成一条阶梯，读数是工作区标签位移 p50（400 个点取自 0817 那条 rig 轨迹，每点 7 台可见）：
· 对照·只换外参帧（内参固定，858 帧切两半）→ 0.05 mm（pairwise 0.10 mm）。BA 对自己的帧抽样几乎免疫，所以下面每一格都可以干净地归给内参。
· 只换内参帧（同两轮数据重采样，10 组互不相交的半分裂，两边都是 200 帧）→ 0.61 mm（0.12–1.21；pairwise p50 中位 1.47 mm）。单次拟合 σ ≈ 0.43 mm。
· 帧数从 200 减到 120 → 0.12 mm。「多采几帧」不是杠杆。
· 换一整轮独立挥板（r1 只用 1503 那轮 / r2 只用 1600 那轮，各 200 帧）→ 2.54 mm，pairwise p50 3.16 mm、rig 尺度差 −796 ppm。
· 对照量级：换相机模型（fisheye→rational）1.43 mm；换成厂商内参 4.09 mm。
结论一：内参没被排除，但被重新定位了。拟合噪声（0.61）解释不了 2 mm，跨轮次差（2.54）可以，而且它在整个工作区上几乎是常量（p50 2.54 / p95 2.76 / max 2.79）——是系统项，不会靠多采帧或多台相机平均掉。
结论二：现行生产内参被覆盖较差的那一轮主导。r1 的画幅半径覆盖只有 0.48–0.70，r2 是 0.64–0.94；但合并后按帧数均匀选 200 帧，其中约 56% 落在 r1，所以 full 贴着 r1（标签差 0.47 mm）而与 r2 差 2.41 mm。「合并后覆盖 0.95」这个统计是并集，不代表拟合被边缘帧支配。
结论三（口径更正）：文档此前引用的 2.22 mm 不是内参敏感度。把它拆开：同一解算器下只换内参是 0.69 mm，而用同一套内参重解、只把旧的 ad-hoc 脚本换成现行 CLI 就差 1.70 mm；外参帧抽样的对照只值 0.10 mm，所以那 1.70 mm 归给旧脚本一份没有归档的解算配置。这正是把解算搬进 CLI 的理由。

Δt 的硬指标由速度定：p95 680 mm/s 下 1 ms = 0.68 mm，要让 GT 侧 timing 贡献 ≤0.5 mm，Δt 残差须 ≤0.7 ms。两支的 timing 难度因此完全不同：
· SMR（1000 Hz + 有时间戳）：即使最近邻查表，间隔/√12 = 0.29 ms → 0.20 mm，timing 基本免费。
· STS（100 Hz + 无时间戳）：最近邻查表 10/√12 = 2.89 ms → 1.96 mm，直接不可用，必须插值（10 ms 窗内按 a≈5 m/s² 估二阶项 a·T²/8 ≈ 0.06 mm，可忽略）。这与本页 v16.3 的结论同构：瓶颈是查表方式，不是时钟。更麻烦的是「无时间戳」意味着只有 host 到达时间，其抖动不是仿射的，t_laser = t_viz·s + Δt 这个模型对它并不直接成立。可行做法是按固定 100 Hz 重建时间网格（与本项目给 EE pose 用的 PWM 相机网格同一手法：相位由到达时间定、网格给时刻），并且到达时间只用来做丢帧检测——丢帧不检出会让均匀网格静默错位。因此选型时要问的第一个问题是「STS 有没有带设备时间戳的低层接口」，这比 100 Hz 本身更要紧。
一条口径红线（本页已经踩过两次）：registration 与 s, Δt 必须在独立于评测集的数据上拟合。在同一段轨迹上既拟合又检验，误差会被吸进拟合参数里，量出来的是下限而不是误差——正是误差预算表前那张口径谱系表说的事。		预算 / 型号 / 租或买 / A 还是 B。决策点已经从「买什么」变成「要不要为姿态单独付 STS 的代价」：分支 A 能认证 3 mm 位置（已含 L·θ），分支 B 多买到的是姿态归因 + 姿态交付，代价是 1400 g（只能上 FR3 侧）与无时间戳带来的 timing 工程量。
必须先向厂家确认的规格，按重要性排序：
① STS 是否有带设备时间戳的接口（哪怕低层/raw）——没有就只能靠 100 Hz 网格重建时间轴；
② STS 的姿态不确定度（6DoF 靶标的角度精度与 SMR 的位置精度不是一个量级）——按 L=102.3 mm 折算，0.5° = 0.89 mm、0.2° = 0.36 mm；待测量本身 p95 是 1.83°，≤0.2° 才有约 9× 余量；
③ SMR 那个「系统运行时间」戳的分辨率、是否单调，以及它标的是测量时刻还是回传时刻；
④ 失锁 / 断光后的重捕行为——手持演示时人体会频繁挡光，GT 会被打成碎片；必须按 episode 报「GT 覆盖帧比例」。这是 A/B 都躲不掉的采集风险，也是录制侧 GT 比 replay 侧 GT 难得多的主因；
⑤ 双臂：是否有可同时跟踪两靶的型号或双站方案、代价多少，再决定是否接受「分次测 + 只认证静态 TLR」。
另需准备：SMR 窝 / STS 安装面要进夹爪与 FR3 法兰的机械设计——这一项与供应商夹爪阻塞耦合，安装面应一并提给供应商；以及一段专用标定运动（充分旋转激励，用于解 c 与 registration，且不得与评测集共用）。		能在同一 metric world 下输出单末端、可对齐到视觉时间轴的 independent reference（A：3DoF 位置 @1000 Hz；B：6DoF @100 Hz），并交付：
