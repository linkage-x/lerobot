FR3 Workstation 数据采集 / QC / 训练 / 推理闭环 Roadmap

目标：把工作站这条 FR3 + Pika + RealSense 链路收敛成可重复执行的闭环：采集、QC、Training View、ACT 训练、离线验证、真机 preview、真机 bounded rollout。

本文按当前代码现状写，不把另一台 DAS / Hikrobot rig 的经验参数迁移到这台机器上。

robot_ip: 192.168.1.206 target frame: pika_task_tcp start pose: fr3_pika_gripper.xml home keyframe record cameras: ee / side @ 60 Hz Training View gated by QC no DAS start

仍未闭环的硬约束

P0
  1. 起始位姿不能使用 DAS start。闭环应以 src/lerobot/robots/franka_research3/assets/franka_fr3/fr3_pika_gripper.xml 的 home keyframe 为唯一初始 pose 合同。
  2. IK 工具坐标系必须从几何合同推出。训练动作代表手指工作点，不是 gripper mount，因此 IK 目标应是 pika_task_tcp，并且 URDF、MJCF、record config、rollout args 必须同名同位姿。
  3. gripper 单位已经从数值猜测前移到 feature name。gripper.pos 按 normalized 处理，*.width_mm/*.distance_m 按显式单位处理；只有缺名字的旧 checkpoint 继续走 legacy heuristic。

第一性原理结论：policy 的动作目标必须对应数据集里被记录和被重建的物理点。抓取任务中这个点应是手指工作点 / task TCP；如果 IK 用的是 gripper mount 或另一个固定 frame，系统不会报错，只会把整条轨迹平移到错误工作空间。

闭环路线

执行顺序
Phase 0
同步与环境基线
  • 把本地改动通过正常 deploy 同步到工作站，不依赖手工 scp 的单个 yaml。
  • 在工作站确认 .venv-fr3、RealSense 权限、Pika 串口、FR3 FCI 网络。
  • 运行 bash tools/fr3/run_pick_place_infer_workstation.sh env，保存输出作为本轮 rollout 配置快照。
Gate
env 输出的 robot IP、camera config、URDF、target frame、gripper threshold 全部匹配工作站合同。
Phase 1
Frame / start pose 代码闭合
  • 硬件 start pose 已切到 XML home keyframe；继续禁止把 SDK move_to_start() 当工作站合同。
  • 跑 URDF/MJCF frame 一致性测试，修复 pika_task_tcp 的任何模型差异。
  • 在 rollout runtime 的 preflight 里把 T_B_Ws 起点对齐统计、target frame、dataset root 写入日志。
Gate
home 后 q 误差达标；frame test 通过；preview 首帧对齐误差在 20 mm / 8 deg 安全阈值内。
Phase 2
数据集 QC 与 Training View
  • 在 Dataset Processing 页对已有工作站 datasets 全量 rerun QC，尤其确认 timestamp_sync verdict。
  • 只从 qc_pass 或确认后的 qc_warn 构建 Training View；pose_ready 但 QC 未跑过的 dataset 不准进入训练。
  • 默认训练合同使用 delta_ee_from_prev_cmd；保留 absolute_ee 作为诊断基线。
Gate
meta/il_view_manifest.json 有 action contract、自检结果、excluded episodes、source episode map。
Phase 3
ACT 训练与离线验证
  • 用 Training View 训练 ACT，不在 GUI 内做跨 session 合并；跨 session 合并只走 CLI，并人工保证每个源 session 已过 QC。
  • 训练后检查 checkpoint 的 train_config.json 能反查 dataset root、camera keys 和 action names。
  • 离线跑 action reconstruction self-check / MuJoCo replay gate，先看 policy 输出能否重建成合理绝对 EE 流。
Gate
checkpoint 能加载；相机 keys 为 ee/side；delta 重建无 reference 缺失；离线轨迹无异常 step。
Phase 4
真机 smoke 到 bounded rollout
  • smoke：不 homing、不运动，只验证 checkpoint、camera、一次 forward、action decode。
  • preview：先移动到 XML keyframe start，20 step，无真实 rollout，打开相机窗口核对实时图像。
  • real_debug：交互式 rollout，打开 MuJoCo target viewer；终端按 s/x/q 控制。
  • real_once：单次 bounded rollout，作为第一次闭环验收模式。
Gate
首帧安全阈值、每步安全阈值、gripper 归一化、相机 freshness 均在日志中可追溯。
Phase 5
调参只在本 rig 上发生
  • n_action_steps、ACT temporal ensemble、command EMA、controller gains 继续默认留空，直到这台机器有可复现实测。
  • 只基于失败类型调参：视觉滞后、首帧对齐、IK 不可达、gripper 时序、policy 抖动分别看不同日志。
  • 每次修改生成一份 rollout config snapshot，避免把调参写成隐式 shell 历史。
Gate
同一 checkpoint 在相同 dataset start pose 下，bounded rollout 可重复，失败能归因到单一模块。

Gripper 单位后续修复

完成

normalize_dataset_gripper() 已先按 dataset feature name 判定单位：gripper.pos 在 Pika workstation 上保持 normalized，*.width_mm 转毫米，*.distance_m 转米；只有没有 unit-bearing 名字的旧 checkpoint 继续使用数值 heuristic。

--gripper-close-below 不再作为默认单位绕行启用。它保留为部署侧可选 guard，用于任务明确需要“低于某个开度直接闭合”的情况。

当前部署路径已经不再依赖 0.1125 这个阈值规避单位歧义；后续仍可把单位/range 写入 training view 或 checkpoint metadata 做进一步显式化。
