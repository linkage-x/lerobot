2.1 理论误差预算与可达精度判断

用于判断当前 8-camera rig 是否具备毫米级测量能力，并定位真正的精度瓶颈。

误差模型
核心判断：若工作距离约 0.7–1.2 m、有效 baseline 约 0.4–0.8 m、角点定位误差约 0.1–0.3 px，纯随机三角测量误差理论上可落在亚毫米量级。最终 2–3 mm TCP 精度更可能受外参、标定板尺度/平整度、机械漂移与 marker→TCP 等系统误差限制。
现场实测（outputs/calibration/thor_gmsl2_extrinisics_robot_base_0720，7 相机联合解）： per-camera sample residual translation mean 2.3 – 7.7 mm（最差 cam_07，max 53 mm）、rotation mean 0.34° – 1.27°（max 6.97°）； pair residual translation mean 5.4 – 21.9 mm。较早的 Hikon 8 相机报告同量级（sample 4.33 mm / pair 11.9 mm，辅助 marker spread mean 4.9 mm、max 50.7 mm）。

对照上表：0.5°–1.3° 的外参旋转误差在 1 m 处就是 9–22 mm 等效位置误差，比 3 mm 指标高一个数量级。现阶段瓶颈明确在 rig 外参，不在角点噪声，也不在相机数量。 一个直接原因是标定目标：当前 stage-3 用的是 single_tag36h11_id6_160mm——单个 160 mm AprilTag，四个角点、共面、深度与倾角方向天然弱约束。
Level 1 实测（2026-08-04，outputs/metrology/level1_0720，7 相机，σpixel=0.2 px 假设）： 上面那句「瓶颈在外参」不再是推断，已量化证实。全工作区 worst-axis σ 为 p50 0.14 mm / p95 0.26 mm / max 0.34 mm；亚毫米区（σmax<1 mm）在 z≈0 处达 7.0 m²，含一个 2.24 m 的完整内接方形（中心 x≈0.30, y≈−0.05），高度上从 z≈−0.4 覆盖到 +0.8。

敏感性检验都推不翻结论：角点噪声放大到 0.5 px（区间上限的 1.7 倍）→ max 0.86 mm；裁掉图像边缘 150 px（回避未验证的厂商边缘畸变）→ max 0.56 mm；只保留 3 路相机（模拟重度遮挡）→ max 0.46 mm。

因此 Phase 2.2 的分支判据已经落地在「另一侧」：理论 <1 mm 而实测 3–5 mm ⇒ 优先排查 calibration bias、marker geometry、机械漂移，而不是改相机几何。 不要挪相机 任何放得进房间的桌子都完整落在亚毫米区内，增加相机数量同样不会改善——余量已经在两个数量级上。
0804 重标结果（calib_20260804_150355）：瓶颈已被移除。换 ChArUco + 脱离机器人后， 独立 3D 一致性（BA 未用过的 608 帧，三角化 vs 已知板几何刚体拟合）：p50 0.078 mm / p95 0.254 mm； 重建尺度偏差 +0.008%（1 m 处 0.08 mm，说明板标签的 30 mm 是准的）。 对照 0720 的 per-camera sample 平移残差 2.3–7.7 mm，好一个多数量级。 补覆盖并改用 fisheye 内参后进一步降到 p50 0.077 / p95 0.244 mm，BA 重投影 0.2437 px，cam_07 的残差从 0.85 px 降到 ≤0.265 px。

交叉验证：Level 1 理论预测 σmax p95 = 0.26 mm，此处实测 3D 一致性 p95 = 0.254 mm。 两条完全独立的路径给出同一数量级——Level 1 的模型可信，且「几何不是瓶颈」的结论得到实测确认。
口径修正：本页下方「关键公式与数量级推导」的算例（Z=1 m, f=1000 px, B=0.5 m, σ_d=0.2 px → σ_Z≈0.4 mm）把 0.2 px 直接当成了视差噪声。 σpixel 是每角点测量噪声，而视差是两次独立角点测量之差，故 σ_d = √2·σpixel，同条件下的正确值是 ≈0.57 mm。不影响任何结论，但两个数都已在 metrology/tests/test_uncertainty.py 里钉死，避免再次混用。

2.2 Workspace Uncertainty Map：σx / σy / σz

回答“桌面哪里测得准、哪里测不准，以及当前 8-camera layout 是否天然支持 ≤3 mm”。

建议展开
它算的不是实际 GT 误差，而是几何可观测性： 在已知相机内外参和假定 pixel/corner noise（例如 0.2 px）时，预测工作空间中某个 3D 点或刚体 pose 的理论协方差。
核心含义与计算

对空间点 P=[x,y,z]ᵀ，每台相机给出投影 u_i = π_i(P)。线性化后：

δu ≈ J · δP

若像素观测协方差为 Σ_u，则三维点协方差近似：

Σ_P ≈ (Jᵀ Σ_u⁻¹ J)⁻¹

最终读取：

σx = √Σ_P(0,0), σy = √Σ_P(1,1), σz = √Σ_P(2,2)

对 UMI 更推荐进一步对 marker 刚体的 6DoF pose 求 Jacobian，得到：

σx, σy, σz, σroll, σpitch, σyaw

为什么它能直接指导相机布局
  • 如果 8 台相机几乎都从上往下看，通常 XY 很强，但 Z 与部分旋转方向可能偏弱。
  • 真正重要的是不同 azimuth / elevation 的交叉视角与有效 baseline，而不是“相机数量多”本身。
  • 如果右后角 σz = 5 mm，而中心 σz = 0.6 mm，优先调整能改善右后角交叉角度的一两台相机。
  • 可在虚拟相机布局上先重算 uncertainty map，再决定是否实际挪相机。
建议输出的 4 类可视化
  • σx map：水平 X 测量精度。
  • σy map：水平 Y 测量精度。
  • σz map：深度方向精度，桌面上方相机系统通常最值得关注。
  • worst-axis map：σmax = √λmax(Σ)，直接显示最差方向的不确定度。

进阶版可画 3D uncertainty ellipsoid，直观看出“哪个方向被约束得最差”。

从 point map 升级到 UMI pose map
  • 单点 map 只反映位置几何，不反映 marker cube 尺寸和朝向。
  • 实际 UMI 应把所有可见 marker corners 对刚体 SE(3) pose 的 Jacobian 联合起来。
  • 完整版应依赖 (x,y,z,R)：同一位置下 marker 转 90° 后，可见面和姿态可观测性会改变。
  • 第一版可以固定几个代表性姿态；第二版再加入 FoV、tag incidence angle、marker 可见面等 visibility model。
建议验收：先看理论 map 是否在主要操作区满足 σmax < 1 mm 左右；若理论上已经是 4–6 mm，则应先改相机几何。若理论上 <1 mm、实测却 3–5 mm，则优先排查 calibration bias、marker geometry、机械漂移等系统误差。

2.3 Uncertainty Map 实现路线

从“相机布局几何”逐步升级到“真实 UMI TCP 可达精度预测”。

建议实现
推荐不要一步到位：先做最简单的 3D point geometry map 验证相机布局，再升级到 marker 6DoF pose covariance，最后把 marker→TCP lever arm 传播进去得到真正与训练标签相关的 TCP uncertainty map。
代码现状：Level 1 已完成（2026-08-04）。位于 metrology/uncertainty.py + metrology/cli/level1_uncertainty_map.py。 如预判，cv2.projectPoints() 返回的 jacobian 只对 rvec/tvec/内参，不对 3D 点，因此走中心差分——这样真实的 rational 畸变模型也留在导数里，而不是退化成理想 pinhole。

验证做了两层：解析协方差对拍闭式双目公式 σ_Z = Z²/(fB)·σ_d（精确相等）；再在真实 rig 上对拍蒙特卡洛三角化——近场 3 点吻合 1–5%，远场（距相机 2.6–2.8 m、仅 4 路可见）吻合 2%。后者是端到端的，T_base_cam 方向反了或 Jacobian 退化成 pinhole 都会被它抓住。

两个实现要点值得记下：①可见性判据必须除了「投影落在图像矩形内」之外再加视线方向约束——rational 畸变模型会把远离光轴的点折回传感器，只判矩形会把不可见点误判为可见。②地图的定义域由相机覆盖自动导出（coverage_extent()：扫出 ≥2 路可见的体积），不依赖机器人也不依赖桌面尺寸——世界系若绑机器人，机器人一挪结论就得重算。

Level 1：Point Geometry Map 怎么算
  1. 将 workspace 离散成 3D grid，例如每 20 mm 一个采样点。
  2. 对每个点判断哪些 camera 可见：在相机前方、投影落入图像 FoV。
  3. 对每个可见 camera 求投影 Jacobian J_i = ∂(u,v)/∂(x,y,z)。
  4. 将所有 camera Jacobian 堆叠成 J。
  5. 根据像素噪声权重 W 计算信息矩阵：

H = Jᵀ W J

三维位置协方差：

Σ_P ≈ H⁻¹

读取：

σx = √Σ(0,0), σy = √Σ(1,1), σz = √Σ(2,2)

worst-axis：

σmax = √λmax(Σ_P)

正式版本：建议用 OpenCV projectPoints() + 数值差分求 Jacobian，从而自然包含真实 distortion model，而不是只用理想 pinhole 解析式。

σ_pixel 不要长期写死为 0.2 px Level 1 唯一未验证输入
现状：Level 1 的全部结论都建立在「每角点定位噪声 = 0.2 px」这一假设上。已做的敏感性检验表明结论在 0.5 px 处仍成立（max 0.86 mm）， 但 0.5 px 本身也是拍的——必须实测一次，才能把 Level 1 从「假设下的结论」升级为「已验证的结论」。

采集协议（必须做对，否则测的是别的东西）：

  • 目标刚性固定在工作区内，用生产曝光/增益/帧率、生产照明，连续采 300–1000 帧。相机先热机 ≥15 min。
  • 关键：静止目标不等于静止。楼板振动、空调风、有人走动都会让整块板一起动，直接算 corner 方差会把这部分算成探测器噪声。 正确做法是先对每帧拟合该 tag 的刚体位姿/单应，再统计去掉刚体运动之后的重投影残差——那才是探测器噪声。两者之差本身就是有用信息（机械稳定性）。
  • 测生产路径实际用的角点：pupil_apriltags + refine_edges=1，且当前没有 cornerSubPix。测 refine 之后的版本没有意义，因为 solver 吃不到。
  • 按 image radius / marker 投影尺寸 / 入射角分桶，并逐相机给值（--sigma-pixel-camera cam_07=0.35），而不是全 rig 一个数。
  • 静止测得的是下界。生产中 cube 在动，运动模糊会抬高角点噪声；需另行按「曝光时间 × 运动速度」估模糊惩罚，或直接在典型运动速度下复测。

产出：把实测值回填进 Level 1 重跑；若与 0.2 px 差异在 2 倍以内，本页所有结论不变（σ 与 σpixel 严格线性，已在测试中钉死）。

Level 2：升级到 Marker 6DoF Pose Map

最终 tracking 的不是一个孤立点，而是刚性 marker cube。对 marker pose 的局部扰动：

ξ = [δx, δy, δz, δθx, δθy, δθz]ᵀ

把每个 camera、每个可见 marker corner 的 reprojection Jacobian：

J_ij = ∂u_ij / ∂ξ

全部堆起来：

Σ_pose ≈ (Jᵀ W J)⁻¹

因此可以同时得到：

σx, σy, σz, σroll, σpitch, σyaw

完整版应依赖 (x,y,z,R)，因为同一位置下 marker 转 90° 后，可见 marker 面和姿态可观测性会改变。

Level 3：传播到 TCP，而不是停留在 Marker

最终训练需要的是 TCP trajectory，因此 Marker covariance 还要通过 T_marker→TCP 传播。

关键原因是 lever arm：marker orientation uncertainty 会转化成 TCP position uncertainty。

例如 marker→TCP 距离约 120 mm，orientation uncertainty 0.5° 时，仅 lever-arm 项就约产生 1 mm 位置误差量级。

最终得到：

Σ_TCP = J_M→TCP · Σ_marker · J_M→TCPᵀ

建议最终 QC 直接使用：

σ_TCP,x / σ_TCP,y / σ_TCP,z / σ_TCP,max

推荐画哪些图
  • σx heatmap：World X 方向理论精度。
  • σy heatmap：World Y 方向理论精度。
  • σz heatmap：深度方向理论精度，通常最重要。
  • σmax heatmap：协方差最大特征值对应的最差方向。
  • 3D uncertainty ellipsoid：对代表性位置画协方差椭球，直接看最弱约束方向。
  • 多高度切片：例如 z=0.15 / 0.30 / 0.45 / 0.60 m，避免只看单一桌面高度。
实现顺序： 先完成 Level 1，并用它决定是否需要调整 camera placement 已完成，结论=不需要调整； rig 冻结后做 Level 2； marker→TCP 标定完成后做 Level 3。 最终真正与 UMI GT 质量对应的是 Level 3，而不是 Level 1。 Level 1 的 σ 已经小到可以忽略，意味着 Level 2/3 的数值将几乎完全由 marker 几何与 marker→TCP lever arm 决定——这两项的标定质量就是最终 GT 质量。

2.4 世界坐标系：脱离机器人，锚定桌面

当前世界系 = robot base，机器人一移动整套外参即作废。

决策
问题：世界系绑在 robot base 上有三重耦合——机器人挪动则外参全部失效；外参靠 FR3 举着板标出，继承 FK 误差；机器人够不到的桌面区域根本标不了。双手 UMI 是手持场景，机器人本不该出现在测量链路里。
建议方案与理由

先把两件常被混为一谈的事拆开：

  • BA 的 gauge（为使优化良置而固定的 7 个自由度）——纯内部、任意。固定某一台相机为单位阵，尺度由标定板实测尺寸给定，机器人完全不参与。
  • 落盘/上报的坐标系——必须物理可解释、可复现、长期稳定。

建议：世界系 = 桌面锚定基准板。

  • 原点：刚性多 tag 板（ChArUco / AprilGrid），螺接在桌面一角、操作区之外，尽量多相机可见。
  • 姿态：Z = 桌面法向，X = 桌面长边。workspace 范围直接就是 x ∈ [0, 桌长]，不需要再解释「0.45 是什么意思」。
  • rig 存成 T_world_cam_i，一次冻结长期不动；机器人降级为被定位对象，T_world_base 需要对 FK 时单独测一次，机器人挪了只重测这一个变换，不是重标定。

关键设计点：用 ≥2 块锚板，不是 1 块。板与板之间的相对变换是不变量，每次开工重测即可区分故障类型：板间距离都稳定但相机位姿变了 ⇒ 某台相机动了；某块板相对其它板变了 ⇒ 那块板或桌子动了。这一条同时把 Phase 2 验收要求的「跨天 repeatability」「静态 target 长时漂移」和 Phase 8 的漂移监控一起解决。

实操细节：

  • 相机是装在独立支架上（非与桌面刚性相连）时，锚板方案更该选——它让 rig↔桌面漂移变成可观测量，而不是悄悄污染数据。
  • 锚板别纯平放。相机高度分三档（cam_06/08 z≈0.38、cam_12 0.55、cam_07/09 0.78、cam_13/14 0.92–0.99），平板对低位相机是掠射角、位姿可观测性差。做成 L 形两面或整体倾斜 20–30° 明显更稳。
  • 板必须是刚性基材（铝板 / dibond），并用卡尺实测印刷方格尺寸再填配置——尺度误差等比例进位置，0.35% 就是 1 m 上 3.5 mm。同批 cube 已有 5.6 / 5.8 两个 marker_size_cm 的前车之鉴。

  • 生产配置更保守：pose_estimation_mode: best_rmse_single_marker —— 每个相机只保留重投影 RMSE 最小的那一个 marker，其余观测直接丢弃。roadmap 要求的是所有可见 corner 一起进 loss，方向正好相反。
  • min_cameras_per_fusion_frame: 1 且 fallback_all_when_too_few_inliers: true：单相机帧也会产出「融合」位姿并写进训练标签，且不带降级标记。
  • 无 subpixel refinement（全仓库无 cornerSubPix），只依赖 AprilTag detector 的 refine_edges。
  • 无 covariance 输出。per-frame 诊断只有 num_camera_samples / num_inliers / cube_num_markers / RMSE，且只落在 analysis CSV，不进 sidecar。
  • 建议路径：先保留现有 detection 与相机管理（多进程、mkv 读取、标定加载都已稳定），只把 fuse_frame_samples() 换成一个「所有相机所有可见 corner → 单刚体 T_world_marker(t) 的鲁棒重投影最小二乘」，用 per-camera PnP 结果做初值。这样改动面可控，且能立刻和现有 pose 平均做 A/B。
Gate：如果 visual-only 已达到 static <1 mm、dynamic ≈2–3 mm，则核心路线成立；否则优先排查标定、布局、corner 精度和 marker/TCP，而不是先上 4DGS。
