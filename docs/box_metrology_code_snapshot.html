结论（2026-08-21 重写：缺口已从“离线模块未进生产”变成“生产已换血，剩下的是标定与认证”）。 0805 的判断仍有效：外参已经接近亚像素 BA 级，端到端没有因此改善；真正没有被多相机平均掉的是 marker/rig 几何与 marker→TCP 这类所有相机共享的系统项。 本节此前的结论行（v13.8）整体过期了：marker_rig_ba、TCP covariance 和 SE(3) smoother 已于 2026-08-19（abacec0）进入生产，sidecar v2 也已带齐 σ / BA success / 相机数 / 残差 / 真实 timestamp。 当前主阻塞分成三层：第一，Phase 3 的实物几何、marker→TCP 与拆装/重夹 repeatability 仍需冻结（被供应商阻塞）；第二，尺子本身还有一台已知错到 2° 的相机（cam_09，已从数据解出修正但未进生产），且外参的重采复现性至今没有第二个独立样本；第三，原来的“FR3 IK/replay gate”只证明可达，尚缺双 base registration、联合 collision-aware retarget 与 independent physical replay metrology。 因此后半段不再用一个 replay_pass 混掉不同含义，而拆成 dual_fr3_executable 与 physical_replay_certified 两级。
方法论教训：不要用「误差预算里最大的那一项」代替「实测最大的那一项」。 外参 9–22 mm 是算出来的上界，marker 尺寸错误没有出现在任何误差预算里——因为没人怀疑过一个写在配置里的常数。 实测能发现它，是因为用了无参考判据（相机间一致性）：它对「所有相机共有的系统偏移」敏感，而对 FK 误差、marker→TCP 常量免疫。 对 FK 的绝对误差在 marker=5.4 时反而更小（10.7 mm vs 5.6 的 14.3 mm），只看它会选错值。
新增工程约定：新代码放进 third_party/opencv_kalibr/metrology/——一个真正可导入的 package（带 pyproject.toml），而不是新开 submodule，也不再往 scripts/ 堆脚本。 理由：opencv_kalibr 的 remote 是自家 linkage-x/opencv_kalibr（非上游 fork，不存在「改不动」），新 submodule 只会产生第三份标定加载与 cube 几何定义，加剧已有的配置分裂； 但该仓库无 packaging、靠 sys.path.insert，且 scripts/ 与 hikon_cube_tracking_offline/ 下的 cube_tracking.py / hikon_cube_tracking_in_robot_base.py 已 md5 分叉——这正是「新代码必须有工程形态」的直接证据。
